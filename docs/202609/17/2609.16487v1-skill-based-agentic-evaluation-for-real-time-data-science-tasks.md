## 摘要
我们提出一个框架，用于在实时、持续更新的数据上评估数据科学智能体，该框架使用可执行真值和格式无关的事实型评分。考虑以下示例查询：“上周的受众规模是多少”——参考会随着底层数据变化而变化，因此静态参考会过时，标准的 LLM 作为评判者（LLM-as-a-judge）流程无法根据固定真值验证回答。我们的核心贡献——真值即代码（ground-truth-as-code）——将每个期望答案编码为一个可执行参考函数，该函数在评估时直接从实时数据重新计算答案，从而确保参考与其所描述的系统保持一致。我们将此与一个事实型级别、格式无关的评判器结合，该评判器将智能体的回答和计算得到的真值都分解为原子断言，并对其计算精确率、召回率和准确率，而不论回答格式如何（散文、列表、表格、HTML 等）。该方法适用于其预期输出可表示为可执行数据计算的智能体。我们通过一项人类与 LLM 一致性研究来验证该框架，研究对象是一个内部开发并已部署到生产环境的机器学习技能，并使用为复现生产模式（schemas）和实体关系而构建的合成数据库。相对于自然语言真值基线，我们的方法在马修斯相关系数（MCC）上取得了 29% 的提升——MCC 是一种类别平衡的度量，用于衡量专家标注者与 LLM 作为评判者预测之间的一致性——并且每个测试用例的 token 消耗降低了 16%，而缺乏显式真值的自导向基线则与人类判断呈负相关。在工业界，执行多源数据集成并对非平稳数据进行计算的智能体已被常规部署；我们提出真值即代码作为其评估的一种实用方法。

## Abstract
We present a framework for evaluating data-science agents on live, continuously updated data using executable ground truth and format-agnostic factoid scoring. Consider this example query: "what were last week's audience sizes"---the reference answer changes as the underlying data changes, so static references become outdated and standard LLM-as-a-judge pipelines cannot verify responses against a fixed ground truth. Our central contribution, ground-truth-as-code, encodes each expected answer as an executable reference function that recomputes the answer directly from live data at evaluation time, ensuring the reference remains consistent with the system it describes. We combine this with a factoid-level, format-agnostic judge that decomposes both the agent's response and the computed ground truth into atomic claims and scores precision, recall, and accuracy over them, irrespective of the response format (prose, list, table, HTML, etc.). The approach is applicable to agents whose expected outputs can be expressed as executable data computations. We validate the framework through a human--LLM agreement study on an internally developed machine learning skill deployed in production, using a synthetic database constructed to reproduce production schemas and entity relationships. Relative to a natural-language ground-truth baseline, our method achieves a 29% improvement in the Matthews Correlation Coefficient (MCC)---a class-balanced measure of agreement between expert annotators and LLM-as-a-judge predictions---and a 16% reduction in token consumption per test case, while a self-directed baseline lacking explicit ground truth is anti-correlated with human judgment. Agents that perform multi-source data integration and computation over non-stationary data are routinely deployed in industry; we propose ground-truth-as-code as a practical methodology for their evaluation.

- **第二个痛点**：智能体可用散文、列表、表格、HTML 等多种格式表达同一组事实，单一的整体式 LLM 评判分数会把**表述质量**与**数据正确性**混为一谈。
- **整体含义/定位**：论文提出一套可落地的评估方法论（而非新模型），把"执行准确率"（execution accuracy）范式从 text-to-SQL 扩展到开放式的数据科学智能体回答，适用于"期望输出可表示为可执行数据计算"的智能体。

## 2. 方法论

### 2.1 核心思想
- **真值即代码（Ground-Truth-as-Code）**：期望答案不是静态字符串，而是一个**可执行的参考函数**，在评估时从实时数据重新计算。
- **事实级、格式无关评判（Factoid-level, format-agnostic judging）**：将智能体回答与真值都分解为原子断言（factoid），在断言层面计算精确率、召回率、准确率。

### 2.2 关键技术细节

**（1）测试台构建**
- 给定被测技能 `S` 与智能体 harness `H`，构建测试台 `T = {τᵢ}`，每个测试用例为四元组 `τᵢ = (Uᵢ, Gᵢ, E, C)`：
  - `Uᵢ`：用户查询；
  - `Gᵢ`：真值即代码函数；
  - `E`：环境变量（业务上下文、共驻技能）；
  - `C`：计算变量（凭证、超时、API 端点）。
- **真值从不预计算或存储**：评测时 harness 并行运行技能 `S` 得到回答 `rᵢ`，同时执行 `Gᵢ` 得到实时真值 `gᵢ`，二者面对**同一时刻的同一数据状态**。

**（2）真值即代码的形式化**
- `Gᵢ : E → D`，`D` 将 factoid 键映射到期望值；
- 在 `C` 指定的计算环境中执行，拉取云端实时数据产生 `gᵢ = Gᵢ(E)`；
- 因为是普通代码，`Gᵢ` 可与测试台一起纳入源码版本控制，具备与生产代码同等的**逐次变更可审计性**；函数签名充当 **schema 契约**，上游 API 变更时会显式失败。

**（3）事实分解（Factoid Decomposition）**
- factoid = 可独立判定真伪的最小信息单元；
- 设 `Φ(·)` 为字符串到原子断言集合的映射，**非对称地**应用于回答与真值：
  - `Fᵣ = Φ(rᵢ)`（无条件下——agent 若输出无关事实，本身即扣分信号）
  - `F_g = Φ(gᵢ | Uᵢ)`（以用户查询为条件，只保留与查询相关的 factoid）
- 提取过程**与格式无关**：无论 `rᵢ` 表面格式如何，`Fᵣ` 内容相同——这是"风格无关性"的来源。

**（4）事实匹配**
- 由 agentic harness 在 `Fᵣ` 与 `F_g` 之间做**一对一映射**，得到匹配集 `F_rg`；
- 每个匹配是**二元决策，无部分分**：匹配即明确正确，未匹配即明确错误。

**（5）量化指标**
- 准确率 `A = |F_rg| / (|F_g| + |Fᵣ| − |F_rg|)`
- 精确率 `P = |F_rg| / |Fᵣ|`（低 P ⇒ 幻觉）
- 召回率 `R = |F_rg| / |F_g|`（低 R ⇒ 遗漏）
- 评分卡逐条记录 `Fᵣ \ F_rg`（幻觉断言）与 `F_g \ F_rg`（遗漏事实），可直接归因失败模式。

**（6）定性维度**
- 由 rubric 引导的 LLM 评判器打分：**Question Coverage**（子问题覆盖度）、**Tone**（礼貌与专业度）、**Conciseness**（相对信息量的冗长度）；
- 所有指标（含 factoid 级）统一线性缩放到 **0–9** 分（即乘以 9）。

**（7）实现形态**：整个流水线实现为一个 **harness skill**，继承 harness 原生的并发执行、日志记录、子智能体编排、记忆与上下文管理等工程能力。

- **主结果（53 个用例，对照三名标注者的人类参考）**：

  | 配置 | MCC | Prec. | Rec. | F1 | Tokens/TC |
  |---|---|---|---|---|---|

- **相对自然语言真值基线：MCC 提升 29%（0.427 vs. 0.331），单测 token 消耗降低 16%**。
- **无显式真值的自导向基线（No GT）与人类判断呈负相关**：它只对照技能自身声明的"final checks"打分，从未构造替代计算路径，也从未访问实时数据——即"拿技能自己的断言当标准"，且 token 成本最高。
- **NL GT 的失败模式**：确实调用了正确的 API 函数，但**过指定了部分输入参数**，产生的参考携带多余 factoid，偶发地混淆 LLM 评判器，压低精确率，同时仍承担生成自然语言参考的 token 成本。

`transaction_id` 之类的虚构字段，即产生幻觉 factoid）、以及遗漏了若干画像相关事实。

**（附）走查结论的意义**：该用例中 `P` 与 `R` 双低，说明智能体既"说了错话"又"漏了正事"，而整体准确率仅 0.24——这一失败**无法被单一整体式 LLM 评判分数定位**，只有 factoid 级评分卡才能把它拆解为"数据集选择错误 + 代理指标误用 + 幻觉列名 + 事实遗漏"四条可行动的诊断。这恰好是论文方法论主张的直接证据。

## 7. 局限性与批判性评估

### 7.1 作者自述或隐含的局限
- **适用边界明确但狭窄**：方法仅适用于"期望输出可表示为对实时数据的可执行计算"的任务。对开放式、主观性或创造性任务（如战略建议、文案撰写、因果解释），"真值即代码"无法定义，方法论失效。
- **真值代码的正确性未被验证**：整套评估体系建立在"参考函数 `Gᵢ` 本身正确"的前提上。论文未提供 `Gᵢ` 自身的测试、审查或交叉验证机制——若专家写错真值，所有下游指标同步偏移。
- **factoid 提取算子的黑箱性**：`Φ` 由 LLM 实现，其自身的精确率/召回率未被单独测量。提取环节的误差会以**不可分离的方式**污染 P、R、A 三个指标：漏提一个真值 factoid 会被误判为智能体的"遗漏"，多提一个回答中的断言会被误判为"幻觉"。
- **一对一匹配的刚性**：二元匹配不允许部分分，对**语义等价但表述不同**的 factoid（如"约 1.2 万" vs. "11,800 左右"）如何处理未充分讨论；数值容差、单位换算、四舍五入等边界情形缺乏明确规则。

### 7.2 方法论层面的进一步质疑
- **"实时"带来的可复现性代价**：由于真值在评测时从实时数据重算，同一测试台在**不同时间运行会得到不同结果**。这虽然正是论文的立意，但也意味着结果**不可逐位复现**，对学术界的可比性构成挑战。论文未讨论如何记录数据快照或数据版本以支持事后审计。
- **数据状态同步假设**：论文假定技能执行与真值函数执行面对"同一时刻的同一数据状态"，但在真实分布式系统中，两次调用之间数据可能已变化（竞态条件）。论文未报告对这类竞态的处理或估计其发生频率。
- **LLM 评判器的双重角色**：Claude Sonnet 4.6 既是被测技能的基础模型，又是 factoid 提取与定性评判的算子。这种**同源耦合**可能引入系统性偏差（例如评判器对同族模型输出的偏好或盲区），论文未做交叉模型验证。
- **合成数据的生态效度**：尽管使用了真实 API、Poisson–DAG 事件引擎与诱饵数据集，数据仍是合成的。真实企业数据中的脏数据、schema 漂移、权限边界、历史遗留字段等复杂情形，合成环境难以完全复现。
- **成本指标的解读**：Token 成本以"每测试用例"计，但未报告**延迟、API 调用次数或美元成本**；对于"实时"评估而言，评测本身的延迟也是工程可行性的关键变量。

### 7.3 基线公平性的再审视
- Baseline-1（No GT）被要求"自行研究技能并自定标准"，其 MCC 为负、token 最高，结果看似戏剧性。但这一基线在**信息量上被极端削弱**——它既无真值也无参考，失败几乎是设计使然。作为"隔离显式真值价值"的对照可以理解，但不宜被解读为"现有实践的真实水平"。
- Baseline-2（NL GT）与本文方法的关键差异被归结为"结构化可执行" vs. "自然语言"，但两者共享同一底层模型；NL GT 的失败（过指定参数、携带多余 factoid）**部分可归因于提示工程而非范式本身**。若对 NL GT 做同等强度的提示优化，差距可能收窄。

## 8. 更广泛的意义与启示

### 8.1 对评估范式的影响
- **从"冻结答案"到"活参考"**：论文把评估的真值从静态资产（标注数据集、参考答案字符串）转变为**活的、可版本控制的可执行程序**。这一转向对任何运行在动态数据之上的智能体（BI 助手、运维 agent、金融风控 agent、供应链 agent）都具有直接借鉴意义。
- **事实级评分卡作为可观测性工具**：把一次回答拆成"匹配事实 / 幻觉事实 / 遗漏事实"三张清单，实际上把**评估输出变成了可归因的诊断报告**，而不仅是分数。这对智能体的迭代开发（定位到底是检索错、推理错还是表述错）价值显著。
- **格式无关性**：把"数据正确性"与"表述质量"解耦，是解决 LLM-as-a-judge 长期被诟病的"风格偏见"问题的一条务实路径。

### 8.2 对工程实践的启示
- 真值代码的**函数签名即 schema 契约**这一设计，使上游数据源变更时评估会**显式失败而非静默漂移**，这与生产代码的契约测试理念一脉相承。
- 评测流水线本身实现为 **harness skill**，可直接继承 harness 的并发、日志、子智能体编排能力，说明该方法论**工程落地成本可控**，不需要重建一套独立评测基础设施。
- 诱饵数据集与"过短 bundle"的设计，提示了一条通用经验：**评估环境应当包含有竞争性的错误选项**，否则无法区分"智能体找对了"与"智能体蒙对了"。

### 8.3 对后续研究的接口
论文留下的可扩展方向包括：把方法推广到多轮对话与有状态的智能体任务；为 `Φ` 提供独立的质量评估；构建跨 harness、跨模型的一致性实验以支撑"模型无关"论断；以及研究真值代码的自动化生成与验证。

## 9. 总体评价

本文是一篇**方法论贡献型**论文，核心创新不在于新模型或新数据集，而在于提出并验证了一套**面向实时、开放式数据科学智能体回答的评估范式**：以"真值即代码"解决时间不变性假设失效的问题，以"事实级、格式无关评判"解决表述与正确性混淆的问题。

**其最强的部分**是方法论的形式化清晰度（测试台四元组、非对称事实分解、三指标定义、走查透明）与基线设计的归因逻辑。**其最弱的部分**是实证规模：55 个用例、单一技能、单一模型、单一 harness，使得"GT-as-code 优于 NL GT"这一结论的**外部有效性受限**，且核心论断（模型/harness 无关）未获实证支持。

**总体判断**：作为一次范式性提案，论文提供了可复用、可审计、可归因的评估骨架，其思想价值可能超过其当前实验证据的强度；但若要作为"该方法显著优于现有做法"的普适性结论，仍需在更大规模、多模型、多 harness、多任务族上补足实证。
