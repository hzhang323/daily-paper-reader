## 摘要
诸如 TOFU 和 MUSE 等遗忘基准通过读取模型的最终答案来证明遗忘，模型只要拒绝回答就已算作遗忘。我们表明，一旦模型作为智能体部署，这种模型层面的证明便不再适用。我们提出 K-Bench，一个对智能体部署下的 LLM 遗忘进行评分的基准。K-Bench 检查 ReAct 智能体暴露的全部六个通道，包括其思维链（CoT）、工具调用和工具观察，以及引出的摘要。只要秘密出现在其中任一通道，该查询便计为泄露。每个实验将秘密恰好置于智能体的三个来源之一（权重、提示词或检索存储）。K-Score 针对每个来源单独计算，并且仅当智能体仍可用时才认可遗忘。清除答案通道并不能使秘密不可恢复。在结构化检索中，秘密仍逐字保留在工具观察通道中，总体泄露率不变。当秘密存在于提示词或检索存储中时，TOFU 和 MUSE 报告无泄露，而部署后的智能体仍在 22--86% 的查询中泄露它。当秘密位于权重中时，所评估的二十种已发表方法均无法明确将其移除，只有在所评估的观察者下，输入破坏干预才能实现选择性遗忘。排名最高的方法会随基座模型而变化。一种拒绝调优方法能抵御所评估的提取，但知识移除并未得到验证。

## Abstract
Unlearning benchmarks such as TOFU and MUSE certify forgetting by reading the model's final answer, where a model that refuses to answer already counts as having forgotten. We show that this model-level certificate does not transfer once the model is deployed as an agent. We introduce K-Bench, a benchmark that scores LLM unlearning under agentic deployment. K-Bench inspects all six channels a ReAct agent exposes, including its chain-of-thought (CoT), tool calls and tool observations, and elicited summary. A query counts as leaked if the secret appears in any of them. Each experiment places the secret in exactly one of the agent's three sources (the weights, the prompt, or the retrieval store). The K-Score is computed separately for each source and credits forgetting only when the agent remains usable. Clearing the answer channel does not make the secret unrecoverable. On structured retrieval, the secret stays verbatim in the tool-observation channel and the aggregate leak rate is unchanged. When the secret lives in the prompt or the retrieval store, TOFU and MUSE report no leakage, while the deployed agent still leaks it on 22--86\% of queries. When the secret is in the weights, none of the twenty evaluated published methods demonstrably removes it, and only an input-corruption intervention reaches selective forgetting under the evaluated observer. The top-ranked method changes across base models. A refusal-tuning method resists the evaluated extraction without verified knowledge removal.

## 1. 核心问题与整体含义

- **研究动机**：LLM智能体已在生产环境中处理个人身份信息（PII），GDPR第17条与加州删除法案等法规要求运营方按请求删除个人数据，这推动了机器遗忘研究。然而现有遗忘基准（TOFU、MUSE、WMDP、LUME）均通过"问一个问题、读一个最终答案"来验证遗忘——**模型只要拒绝回答就被算作已遗忘**。
- **核心问题**：这种模型级遗忘证书能否迁移到智能体部署？论文指出**不能**。智能体（ReAct框架）暴露远超最终答案的可观测通道，被抑制的信息可能迁移到未被监测的通道。
- **关键洞察**：秘密在智能体中的存储位置（权重/提示词/检索库）决定了它通过哪条通道泄露；针对单一通道的干预可能只是让泄露"改道"而非消除。
- **整体含义**：依赖TOFU/MUSE的合规审计可能把仍在泄露PII的智能体认证为"已遗忘"，需要以全通道视角重新定义遗忘评测。

## 2. 方法论：核心思想与关键技术细节

### 2.1 多通道观察者
- 以黑盒方式查询已部署的LLM智能体，观察其完整执行轨迹，聚合六个可观测通道。
- **多通道观察者指标**为逐查询的逻辑OR：某查询只要任一通道泄露目标PII即计为泄露，然后对查询群体取平均。该指标是任意单通道泄露率的上界。

### 2.2 六条可观测通道
1. **Z_CoT**：思维链推理文本
2. **Z_tool**：工具调用参数
3. **Z_tool_wide**：工具调用参数 + 工具返回观测（包含Z_tool）
4. **Z_RAG**：检索结果（文档ID与段落）
5. **Z_answer**：最终答案
6. **Z_summary**：后续提示诱导的事后摘要

### 2.3 四种子基底（记忆来源）
- **P（参数化）**：秘密通过LoRA微调写入权重
- **C（上下文）**：秘密逐字出现在系统提示中
- **R-text（自由文本检索）**：秘密插入RAG段落索引
- **R-struct（结构化检索）**：秘密存于数据库，经`lookup_record`等工具访问
- 核心设计：**单基底注入协议**——每次实验秘密只进入一个基底，隔离基底作为唯一因果变量。

### 2.4 遗忘三要件
- **D1 选择性遗忘**：忘集提取率显著下降，保留集变化在容差δ_retain=0.05以内
- **D2 跨通道稳健性**：不出现通道迁移（泄露从一条通道转移到另一条）
- **D3 基底通用性**：方法在其机制可作用的所有基底上都有效

### 2.5 K-Score与K类判定
- **K-Score**为三因子乘积：`(1 - OR_forget) · (1 - |Δ_sel|)⁺ · (1 - Δ_degen)⁺`，分别奖励跨通道遗忘、保留集保持、智能体完好。任一因子为0则总分为0。
- **K类判定**：K-REF ∞（完全抑制）、K-REF α×（至少两倍下降）、K-SUP（通道迁移但总体未降）、Measured failure（无迁移无显著下降）、Ambiguous（残余标签）。
- **有效性门控**：基线OR(all)<0.10或基线答案通道召回<0.10的单元格标记为invalid并排除。

### 2.6 统计协议（预注册）
- 种子池化配对McNemar检验（3种子×200查询=600配对观测）
- Benjamini-Hochberg FDR校正，分别在"忘集族"与"保留集族"内独立进行
- 1000次自助法95%置信区间
- 预注册基底泄露模式假设，阈值τ=0.1508
- 功效分析：n=600时可检测30%相对下降，功效>0.95

## 6. 主要结论与发现

1. **单通道评估高估遗忘**：在结构化检索上，StaR将答案通道从0.832降至0.463，但秘密迁移至工具观测通道，OR(all)维持0.857（基线0.855），判定为K-SUP。
2. **TOFU/MUSE对非参数基底完全失明**：当秘密在提示词或检索库时，这些探针返回恒定分数（召回0.025–0.073、KnowMem≤0.005、MCQ≈0.25、MIA AUC≈0.51–0.56），而部署智能体仍在22–86%查询中泄露（Qwen3.5-9B上下文达99.2%）。
3. **权重场景下无已发表方法可证移除**：20方法中，只有输入破坏ECO达到选择性遗忘（Mistral-7B K-Score 0.911、Qwen3.5-9B 0.920）；O3仅在完美oracle下达到K-REF ∞；其余方法要么无法遗忘、要么部分遗忘、要么以智能体崩溃或保留集损毁为代价抑制泄露。
4. **排名第一的方法随基座变化**：FLAT（Llama，0.763）→ RMU（Mistral，0.726）→ LoKU（Qwen3.5，0.743），无方法在两个以上基座领先；方法×模型交互解释K-Score方差的24%。
5. **通道迁移的机制**：干预点决定判定——ECO在编码前破坏实体嵌入，传播至全栈所有通道；StaR在输出token层面干预，只能抑制其下游通道。
6. **生态验证成立**：在LUME真实姓名与出生日期上，ECO将三个基线（99.4%、95.0%、37.5%）全部降至0.000，StaR仍漏掉工具观测通道（K-SUP）。
7. **拒绝微调≠知识移除**：FLAT在Llama-3.1-8B上抵抗所评估的提取（六通道逐字CER为0%），但无法验证知识是否真正移除；在其他基座上崩溃。

## 7. 优点

- **问题定义精准**：清晰揭示"模型级遗忘证书不迁移到智能体部署"这一被忽视的盲区，动机充分且有法规现实意义。
- **方法论严谨**：单基底注入协议隔离因果变量；多通道OR聚合保守下界；K-Score三因子乘积防止以崩溃换取消极得分。
- **统计规范**：预注册假设、FDR校正、自助法CI、功效分析、阳性对照校准端口一致性——在基准类论文中较为罕见。
- **实验覆盖广**：3基座×4基底×13/20方法，跨合成与真实格式PII，含API服务面验证（权重不可访问时智能体是唯一可观测面）。
- **可复现性强**：开源评测代码、PII生成器与固定分割、预注册推断计划、无干预基线轨迹、两个检索索引。
- **诚实披露**：明确标注移植偏差、端口不一致（如UNDIAL-corrected）、运行间波动范围、有效性门控排除的单元格。

## 8. 不足与局限

- **合成PII为主**：主评测使用Faker生成数据；生态验证仅覆盖出生日期字段，地址字段有47%转换伪影，电话/邮箱/SSN超出工具schema。
- **参数化注入方式单一**：仅用LoRA微调注入PII，未测试预训练记忆或全参数微调作为原生写入方式；结果可能不迁移到其他训练程序编码的PII。
- **仅纯基底**：每次秘密只在一个基底，未测量混合部署（如同时微调+检索）是否比纯形式之并集泄露更多。
- **权重案例研究范围有限**：单适配器注入目标、预算匹配而非逐方法调优，绝对数值不复现各方法已发表工作点；ReAct策略崩溃与遗忘的隔离需以智能体格式重训，属独立变体。
- **模型轴是门控样本**：三基座非完整全因子，Mistral-7B上下文块不达标、参数化基底需单独校准目标；跨模型主张仅在可测单元格上成立。
- **通道级二元检测**：OR-of-channels无阈值但每通道判定为二元；跨通道拼接碎片的重建攻击超出观察者模型。
- **仅针对被查询实体计分**：回复披露第三方真实记录不计为泄露；若第三方本身是忘集实体则构成未计入的泄露，粗略估计会使某方法在检索基底上的分级泄露翻倍至0.11–0.16。
- **运行间波动仅在子集界定**：重复测量仅覆盖36对检索单元格，其他单元格的差异分辨率未验证。
- **语言覆盖**：所有查询与PII字段均为英文，未测试非英语场景。
