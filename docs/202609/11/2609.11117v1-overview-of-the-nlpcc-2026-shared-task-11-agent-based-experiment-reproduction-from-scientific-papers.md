## 摘要
可复现性对科学进步至关重要，然而科学出版物数量和复杂性的不断增长，使得详尽的人工验证日益不切实际。尽管大语言模型（LLM）智能体的最新进展使自动化实验复现成为可能，但现有评估主要关注最终代码仓库，且通常局限于机器学习（ML）领域。我们提出 AgentActionBench，一个面向过程的基准，用于评估跨 ML 与 AI4Science 领域的基于智能体的实验复现。我们的框架使用基于 MCP 的 Action Recorder 来捕获智能体在整个复现过程中的行为，并用论文特定的评分标准评估生成的轨迹。AgentActionBench 包含 150 篇论文，其中包括 120 篇 ML 论文和 30 篇 AI4Science 论文。覆盖基准 10% 的人工标注子集提供验证数据，而模型辅助增强将完整基准扩展到超过 10,000 条评分标准项。实验结果表明，当前系统仍然有限，执行是主要瓶颈。同时，模型生成与人工标注评分标准之间强 Pearson 和 Spearman 相关性验证了我们可扩展评分标准生成方法的可靠性。

## Abstract
Reproducibility is essential to scientific progress, yet the growing volume and complexity of scientific publications make exhaustive manual verification increasingly impractical. Although recent advances in large language model (LLM) agents enable automated experiment reproduction, existing evaluations largely focus on final repositories and are typically limited to machine learning (ML). We introduce AgentActionBench, a process-oriented benchmark for evaluating agent-based experiment reproduction across ML and AI4Science domains. Our framework uses an MCP-based Action Recorder to capture agents' behaviour throughout the reproduction process and evaluates the resulting traces with paper-specific rubrics. AgentActionBench contains 150 papers, including 120 ML papers and 30 AI4Science papers. A human-annotated subset covering 10% of the benchmark provides validation data, while model-assisted augmentation expands the full benchmark to more than 10,000 rubric items. Experimental results show that current systems remain limited, with execution as the primary bottleneck. Meanwhile, the strong Pearson and Spearman correlations between model-generated and human-annotated rubrics validate the reliability of our scalable rubric-generation approach.

## 1. 核心问题与研究动机

- **可复现性危机**：可复现性是可信科学进步的基础，但实践中极难实现。Nature 调查显示超过 70% 的研究者曾无法复现他人实验；近期研究指出顶级计算机科学会议中仅约 20% 的论文发布了足以复现的代码。
- **人工验证不可扩展**：科学出版物在数量与复杂度上持续增长，规模化的人工验证日益不切实际。
- **LLM 智能体带来的机会**：LLM 在长上下文理解、代码生成、推理与工具使用上的进步，使其有望承担"论文理解 → 实现规划 → 代码生成 → 实验执行 → 结果验证"的完整复现流程。
- **现有评估的两大缺陷**：
  - **面向产物（output-oriented）而非面向过程**：Paper2Code、PaperBench 等基准主要评估最终代码仓库或描述文本，忽略复现过程。这会导致评估器把"从未被真正实现或执行"的内容误判为已完成——智能体可能生成看似合理的文件或描述，却漏掉论文关键内容、未执行代码，甚至伪造执行记录。
  - **领域局限**：绝大多数评估仅覆盖机器学习（ML）领域，缺少 AI4Science（生物、化学、天文、材料、医学等）。
- **本文定位**：提出 **AgentActionBench**，一个面向过程、跨 ML 与 AI4Science 的多领域基准，通过可审计的动作轨迹对复现全流程做细粒度评估。

## 2. 方法论

### 2.1 核心思想

- 不再只评判最终仓库，而是把复现过程拆解为细粒度阶段，验证智能体**是否真正执行了必要的操作**。
- 通过基于 **MCP（Model Context Protocol）的 Action Recorder** 中介智能体与执行环境的全部交互，自动生成结构化动作日志，作为评分标准（rubric）评估的**可审计证据**。

### 2.2 Action Recorder：关键技术与工具

- 智能体**不直接访问操作系统**，所有交互都通过少量 MCP 工具中介，每次工具调用被视为一个**原子化、标准化的动作**。
- 提供三个核心工具：
  - **Read**：读取文件内容，可选支持行范围（`start_offset`/`end_offset`）以高效查看大文件；返回 `content`。
  - **Write**：创建或修改源码、配置文件等复现产物；返回 `success`。
  - **Execute**：运行 shell 命令，返回执行状态、标准输出与标准错误，使智能体能开展实验并检查结果。
- 每次调用记录输入参数、返回结果与时间戳，按时间顺序写入 **JSON 日志**，智能体终止时自动导出（附录 A 给出示例）。
- 出于安全与公平，所有工具交互限制在指定工作区内；由于通过 MCP 接口中介，记录器**无需修改智能体**，兼容任何支持 MCP 的系统。

### 2.3 评分标准体系与评估流程

- 每条评分标准项形式化为 **rᵢ = (cᵢ, sᵢ, tᵢ)**：cᵢ 为评估准则，sᵢ 为重要性分数，tᵢ 为对应的复现阶段。
- 定义五类 rubric，覆盖完整复现工作流，并与记录工具一一对应：
  - **Paper Observation**（论文观察）→ Read
  - **Plan Writing**（计划撰写）→ Write
  - **Code Implementation**（代码实现）→ Write
  - **Command Execution**（命令执行）→ Execute
  - **Result Matching**（结果匹配）→ Read + Execute
- **评估算法流程**：
  1. 对论文 P 的每个 rubric 项，评估模型 M 先从完整日志 L 中抽取与 rubric 类型 tᵢ 相关工具对应的子集 **L′ᵢ ⊆ L**（缩短上下文、排除无关证据）。
  2. 给定 L′ᵢ、准则 cᵢ 与源论文 P，模型给出二值判定 **Jᵢ ∈ {Pass, Fail}**，即 Jᵢ = M(L′ᵢ, cᵢ, P)。
  3. 总体复现得分为**按重要性加权的通过比例**：score = Σᵢ[Jᵢ=Pass]·sᵢ / Σᵢ sᵢ，其中 [·] 为指示函数。

### 2.4 基准构建

- **论文来源（共 150 篇）**：
  - 120 篇 ML 论文，来自 ICML、ICLR、ACL、NeurIPS 等顶会；
  - 30 篇 AI4Science 论文，来自 Nature、Bioinformatics、npj Computational Materials 等期刊，覆盖天文、生物、化学、环境科学、材料科学与医学。
- **人工标注子集 AgentActionBench-Human**：随机抽取 12 篇 ML + 3 篇 AI4Science（占全基准 10%），由 3 名有顶会投稿与审稿经验的研究生标注；标注后由另外两人轮换独立复核并修订，直至达成共识。平均每篇 67.75 条 rubric，共 1,000+ 条人工标注项。
- **模型辅助扩充**：先用 **MinerU** 将论文转为 Markdown 以提供更干净、结构化的输入，再沿用前期工作 [15] 的 rubric 生成框架，将人工子集扩展为完整 AgentActionBench（150 篇，10,000+ 条 rubric，平均每篇 69.92 条）。
- **生成配置**：Claude Code 作为智能体脚手架，Claude-Sonnet 作为骨干模型，并使用从 Claude-Opus 蒸馏出的技能文档。
- **验证**：在 AgentActionBench-Human 上用相关性分析检验模型生成与人工标注 rubric 的一致性。

## 6. 主要结论与发现

- **当前系统能力有限**：最优系统 YNU-HPCC-Task11-AgentRep 总体仅 49.64%（ML 46.69%，AI4Science 61.25%），**无系统超过 50%**；zzunlp_wu 24.70%，Codex-GPT-5.4 基线 24.19%，QueenAgent 7.03%。
- **执行是主要瓶颈**：各系统在 Paper Observation、Plan Writing、Code Implementation 上表现相对较好，但在 **Command Execution 与 Result Matching** 上显著下降（如 Codex-GPT-5.4 的 CE 仅 2.84%、RM 7.67%）。说明智能体能生成看似合理的计划与代码，却难以应对运行时失败、环境与依赖问题，也难以复现论文报告的结果。这与既有研究对"实现与执行是科学智能体关键短板"的判断一致。
- **AI4Science 反而更易复现**：所有系统在 AI4Science 论文上的得分都高于 ML 论文，可能因为所选 AI4Science 论文采用更标准的 ML 方法或更简单的实验配置。
- **可扩展 rubric 生成方法可靠**：模型生成与人工标注 rubric 的评分相关性达到 **Pearson 0.93 ± 0.04、Spearman 0.88 ± 0.07**，置信区间窄，支持该方法用于大规模基准构建。
- **细粒度差异**：两类 rubric 的每篇平均条数接近（67.75 vs. 69.92），说明生成 rubric 基本捕捉到了人工标注的结构；但模型生成的准则平均更长（180.82 vs. 153.55 字符），且给 **Code Implementation** 分配了更大分值权重，给 **Plan Writing 与 Command Execution** 的权重偏小，提示生成 rubric 在粒度与类别侧重上仍需校准。

## 7. 优点

- **范式创新：从"看产物"转向"看过程"**。用可审计的动作轨迹替代对最终仓库的判定，直接针对"智能体生成貌似合理的文件/描述但未真正执行甚至伪造执行记录"这一评估失效模式。
- **非侵入式、通用性强的记录机制**。基于 MCP 中介所有系统交互，无需修改智能体即可兼容任何 MCP 系统，且通过工具白名单 + 工作区限制兼顾安全与公平。
- **评分标准与工具证据显式对齐**。五类 rubric 与 Read/Write/Execute 一一映射，使"哪类准则由哪些日志证据支撑"清晰可追溯；评估时按类型抽取日志子集，兼顾上下文长度与证据相关性。
- **重要性加权的连续评分**。相比纯二值通过率，按 sᵢ 加权更能反映不同准则的轻重差异。
- **跨领域覆盖**。突破以往仅限 ML 的局限，纳入 Nature、Bioinformatics 等期刊的 AI4Science 论文，覆盖天文、生物、化学、环境、材料、医学六大方向。
- **对基准构建方法本身做了元评估**。人工子集 + 模型扩充 + 相关性验证的组合，为"低成本规模化评测集"提供了可复用的方法论证据（Pearson 0.93 / Spearman 0.88）。
- **诚实的负面结果报告**。明确给出"无系统超过 50%""执行是瓶颈"等不利于现有技术的结论，并指出生成 rubric 的权重偏差。

## 8. 不足与局限

- **评估器单一且能力受限**（论文自述）：因预算限制仅使用 GPT-4o-mini 作为评估器，未验证更强模型是否给出更可靠判定；rubric 评估虽能大幅降低幻觉，但**无法完全消除**。
- **领域覆盖仍属初步**（论文自述）：AI4Science 仅 30 篇，覆盖广度有限，向更广泛科学领域扩展是未来方向。

- **人工标注子集规模小**：仅 15 篇（占 10%），3 名标注者的共识流程虽严谨，但样本量使相关性估计与类别级结论的稳定性受限。
- **基准构建存在潜在偏差**：
  - 模型生成 rubric 更冗长、对 Code Implementation 加权过高、对 Plan Writing/Command Execution 加权偏低，可能系统性影响排行榜分数结构（论文亦承认需校准）；
  - 论文选取偏向顶会/顶

刊，可能使基准偏向方法规范、代码与数据可得性较高的论文，从而系统性高估复现成功率，对代码缺失、依赖私有数据或实验成本高昂的论文代表性不足。

- **共享任务性质带来的样本偏置**：作为共享任务概述，参赛系统均为自愿报名，系统数量少且能力分布不均（7.03%–49.64%），难以代表领域整体水平，排行榜的区分度与稳定性受限。

## 9. 对后续研究的启示

- **执行与调试是科学智能体的核心短板**：CE 与 RM 的极低得分表明，未来系统需要重点强化环境搭建、依赖解析、错误诊断与迭代修复能力，而非仅停留在代码生成层面。
- **过程监督值得推广**：Action Recorder 的"工具中介 + 原子动作日志"思路可迁移到其他智能体评测场景（如软件工程、数据科学、机器人任务），为过程级评估提供通用基础设施。
- **基准构建可走"人工锚定 + 模型扩展"路线**：高相关性结果（Pearson 0.93 / Spearman 0.88）支持用少量人工标注校准大规模自动生成 rubric，但需针对类别权重与准则长度做后校准。
- **需要更严格的方法学**：后续工作应补充多评估器对比、多随机种子方差、显著性检验与消融实验，并对跨领域难度做匹配控制（如按代码可得性、方法类型、实验规模分层）。
- **AI4Science 评测应扩容**：30 篇的规模不足以支撑领域级结论，未来需覆盖更多学科、更多实验范式（如湿实验、仿真、观测数据分析），并引入领域专家参与 rubric 设计。

## 10. 总体评价

本文针对"智能体能否真正复现科学论文"这一核心问题，提出了一个面向过程、可审计、跨 ML 与 AI4Science 的基准 AgentActionBench。其最大贡献在于**评估范式的转变**：以 MCP 工具中介的动作日志作为证据，把复现拆解为五类可验证阶段，有效规避了"只看产物"导致的伪完成问题；同时通过人工子集与模型生成 rubric 的相关性验证，为低成本规模化评测提供了方法论支撑。实验结果诚实且具有警示意义——即便最强系统也未突破 50%，执行与结果匹配是当前瓶颈。其主要局限在于评估器单一、参赛系统少、统计严谨性不足、领域与难度控制不充分，以及生成 rubric 的权重偏差。总体而言，该工作为科学智能体的过程级评测奠定了有价值的基准与工具基础，但其排行榜结论（尤其是跨领域比较）应视为初步证据，而非定论。
