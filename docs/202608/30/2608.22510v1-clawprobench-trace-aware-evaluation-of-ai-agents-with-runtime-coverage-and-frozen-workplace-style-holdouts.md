## 摘要
代理基准测试常常只评估最终答案，即使代理在有状态运行时上运行。我们认为这低估了被评估的对象：正确的单元是声明的模型加运行时配置，其失败可能发生在证据获取、运行时路由、安全边界或重复执行中。我们提出了ClawProBench，一个轨迹感知的基准测试，用于运行时原生代理评估，实例化在OpenClaw上，这是一个活体的代理运行时，具有工作区工具和用于浏览、记忆、消息传递、调度、技能和子代理的原生表面。ClawProBench定义了两个轨道：一个包含102个场景的完整配置文件，包含实时工作区和原生运行时路由任务；以及一个冻结的68场景保留集，具有封闭世界JSON输出契约，用于稳健排名。试验通过安全门控公式从执行轨迹中评分，结合正确性、过程质量和效率，保留失败证据以供审计。我们的匿名工件包括基准定义、评分代码、清单和消毒轨迹。我们在完整配置文件上评估了68个配置，在保留集上评估了37个。最高安全门控平均轨迹得分为0.7671。原生运行时任务表现不如工作区实时任务（0.5238对比0.6415）。在保留集上，pass@k-any优于严格三次试验通过（0.6638对比0.2890），而完整配置文件和保留集排名显示出弱对齐（Spearman 0.1300）。纯粹基于正确性的排名与过程感知、安全门控和严格通过视图有显著差异。最终答案排行榜可能隐藏原生表面弱点、一次性成功和轨迹局部代理失败模式。

## Abstract
Agent benchmarks often evaluate only final answers even when agents run on stateful runtimes. We argue this under-specifies what is being evaluated: the proper unit is a declared model-plus-runtime configuration whose failures can occur in evidence acquisition, runtime routing, safety boundaries, or repeated execution. We present ClawProBench, a trace-aware benchmark for runtime-native agent evaluation instantiated on OpenClaw, a live agent runtime with workspace tools and native surfaces for browsing, memory, messaging, scheduling, skills, and subagents. ClawProBench defines two tracks: a 102-scenario full profile with live workspace and native-runtime routing tasks, and a frozen 68-scenario holdout with closed-world JSON output contracts for robust ranking. Trials are scored from execution traces via a safety-gated formula combining correctness, process quality, and efficiency, preserving failure evidence for audit. Our anonymous artifact includes benchmark definitions, scoring code, manifests and sanitized traces. We evaluate 68 configurations on the full profile and 37 on holdout. The top safety-gated average trace score is 0.7671. Native-runtime tasks underperform workspace-live tasks (0.5238 vs. 0.6415). On holdout, pass@k-any outperforms strict three-trial pass (0.6638 vs. 0.2890), while full-profile and holdout rankings show weak alignment (Spearman 0.1300). Rankings based purely on correctness differ substantially from process-aware, safety-gated and strict-pass views. Final-answer leaderboards may hide native-surface weaknesses, one-off successes and trace-local agent failure modes.

## 一、论文的核心问题与整体含义（研究动机和背景）

- **背景**：大语言模型（LLM）越来越多地被部署为**在运行时环境中执行任务**的智能体（读取文件、调用工具、浏览网页、发送消息、调度提醒、委派子代理等）。然而，主流基准测试和排行榜仍然以**最终任务成功率**为主要甚至唯一评判标准，忽略了执行过程中的大量关键信息。
- **核心问题**：一个"最终答案正确"的智能体行为，可能在操作层面是失败的——例如使用了错误的运行时界面（surface）、跳过了关键证据、违反审批边界、进行低效重试、或未留下可供审计的执行痕迹（trace）。仅看最终答案（answer-only）的评估范式无法捕捉这些多维失败模式。
- **核心论断**：正确的评估单元不是"模型本身"，而是**"声明的模型加运行时（model-plus-runtime）配置"**——模型端点、提示词封装、控制器、运行时与工具、模式（schemas）、安全过滤器、执行策略、检查器（checker）捆绑包和评分代码组成的完整系统。
- **整体含义**：需要一种**轨迹感知（trace-aware）**的评估方法，将正确性、过程质量、安全性、效率、执行状态和重复可靠性整合为联合的每配置诊断（joint per-configuration diagnosis），以揭示仅看最终答案所隐藏的运行时敏感性、单次偶然成功、状态差异和轨迹局部的失败模式。

## 二、论文提出的方法论：核心思想、关键技术细节、公式与算法流程

### 1. 核心思想

- **评估单元**：声明的模型加运行时捆绑配置，而非独立于框架的纯模型智能。
- **两条轨道**：
  - **完整实时配置（Full live profile）**：102个场景，用于测试运行时覆盖率（66个工作区实时任务 + 36个原生OpenClaw任务）。
  - **冻结保留集（Frozen holdout）**：68个工作区风格、封闭世界JSON输出契约的场景，通过固定选择器 `realistic-holdout-68-20260511` 冻结，用于固定契约下的可靠性分析和跨运行时比较。
- **适应契约（Runtime Adaptation Contract）**：跨运行时评估从工作区保留集出发，要求适配器保留8个契约层：场景身份、模型身份、端状态模式、规范化轨迹事件、预期证据与工具元数据、工件后置条件、安全边界标签、确定性检查器/评分接口；并要求绑定运行时版本、适配器版本、哈希和重试策略等行溯源信息。

### 2. 关键技术细节

- **轨迹采集**：每个实时试验从产生的轨迹中评分——检查最终输出、工具调用、参数、工具顺序、恢复行为、文件工件和审计状态匹配。自定义确定性Python评分器用于声明式YAML检查不足的场景。
- **场景规范**：每个场景是结构化的YAML规范，包含元数据、工作区输入、预期运行时表面、评分检查和可选的自定义Python评分器。难度标签反映预期证据广度、动作深度和约束密度，而非人类任务难度。
- **冻结保留集校准**：候选批次在六模型面板上实时校准；保留标准为通过/失败分歧、数值分布或安全信号；饱和、聚集、相同失败或破碎任务被修剪或修订。

### 3. 评分公式

单个试验得分（核心公式）：

```
Strial = G_safety × (0.65 × C + 0.35 × P) × (1 − E)
```

- **C（正确性）**：最终输出与工件检查上的得分比例，是多数权重项（0.65）。
- **P（过程质量）**：所需工具集适当性、有序子序列覆盖率、冗余步骤控制或场景特定的自定义规则。P在场景内归一化，不要求精确轨迹身份；对于需证据前置、审批、安全或原生路由的场景才评分顺序。
- **E（效率惩罚）**：相对最优步骤估计的多余工具调用惩罚，默认上限0.30、速率0.15。
- **G_safety（安全门）**：严重度感知的非补偿性乘数——1.0（无安全失败）、0.7（轻微）、0.2（一次重大）、0（多次重大或关键失败）。严重安全违规无法由正确的最终内容补偿。

### 4. 聚合流程

1. 场景内三试得分先平均；
2. 场景均值按能力维度平均，使用场景权重乘难度权重（easy=1, medium=2, hard=4, expert=8）；
3. 六个能力维度按固定权重组合（工具使用和规划各0.20，其余各0.15）；
4. 同时报告效率惩罚前的能力得分（capability score）、严格三试通过（strict pass）、pass@1、pass@k-any、pass@k-all等重复试验指标。

### 5. 执行状态语义

将干净基线运行（clean base）、重跑后干净（clean-after-rerun）和未解决执行失败（unresolved execution-failure）区分为不同的测量条件，因为不同的运行/失败状态会改变排行榜的解释。

论文采用"基于环境的对比定位"方式：与MiniWoB、WebArena/VisualWebArena、OSWorld、TheAgentCompany/WorkArena、ToolBench/MCP-Bench、ClawBench/Claw-Eval、WildClawBench等基准进行描述性对比（附录表10），强调ClawProBench的差异点在于：**OpenClaw原生表面分类 + 联合每配置诊断 + 状态感知评分 + 冻结可靠性保留集 + 跨运行时工作区适应契约**。

## 四、资源与算力

- **论文未明确说明GPU型号、数量或训练/微调时长**——这是因为论文的评估对象是已部署的模型API端点（如GPT-5.5、GLM-5.1、Kimi-K2.6等），而非本地训练的模型。
- **运行时资源以API成本和token消耗呈现**（来自公共排行榜数据文件，非私有账单推算）：
  - 完整配置轨道：66个非零成本条目，消耗约41.5亿（4.150B）token，成本约2,486.96美元；
  - 保留集轨道：34个非零成本条目，消耗约6.845亿（684.5M）token，成本约669.45美元；
  - 合计：约48.35亿（4.835B）token，约3,156.41美元。
- 每个完整配置和保留集条目均为**每场景3次试验**。

## 五、实验数量与充分性

### 实验数量概况

- 完整配置：68个条目 × 102场景 × 3试；
- 保留集：37个干净条目 × 68场景 × 3试；
- 版本研究：16个模型-版本单元格 × 3,264条试验记录；
- 跨运行时研究：12个单元格 × 2,448条试验记录；
- 评分灵敏度：66行组件解析正确性对比；39报告重构信度权重扫描；60行正分过滤视图；29模型扩展交叉配置相关分析。

### 充分性评估

- **充分性较好**：
  - 评分灵敏度分析包含了无正分过滤的全分母视图（66行）和正分过滤视图（60行），提升了结论稳健性；
  - 权重扫描（0.50/0.50、0.65/0.35、0.80/0.20）检查了评分公式敏感性；
  - 多种聚合规则（best/mean/median/earliest/latest clean entry）用于保留集聚合灵敏度审计；
  - 报告级自助法（bootstrap）区间用于原生差距、可靠性差距和排名相关的置信度估计。
- **客观性**：论文对不确定性非常坦诚——例如29模型全-vs-保留集Spearman相关点估计仅0.1754，95%区间[−0.23, 0.54]跨越零，明确声明不构成稳定排序规律的证据；失败分类基于自动分组而非独立人工标注，被明确定位为审计优先级而非最终普遍率估计。
- **公平性**：跨运行时对比明确声明"非单组件因果消融"（wrapper、工具模式、路由、安全层共同变化），不做超出证据范围的因果归因。

## 六、论文的主要结论与发现

1. **非饱和性**：完整配置最高分仅0.7671（能力得分0.7796），前5名差距0.0661，最强模型仍有明显提升空间。
2. **原生表面难度偏高**：原生场景平均0.5238 vs 工作区实时0.6415；在难度分层、维度分层等简单分层下差距仍＞0.10——原生切片提供了工作区任务无法捕获的互补诊断信号。
3. **状态语义影响排行榜解释**：干净基线前15名与执行失败条目重叠仅1/15；隐藏运行状态会改变排行榜可比性判断。
4. **重复可靠性差距显著**：保留集pass@k-any均值0.6638 vs 严格三试通过0.2890——"偶发解决一次"远易于"稳定解决三次"。
5. **跨轨道排序不确定**：完整配置与保留集相关点估计低（Spearman 0.1754，Pearson 0.2174）但置信区间很宽（[−0.23, 0.54]），不支持精确排序声明；保留集是"高不确定性的补充排序诊断"，而非冗余的小型排行榜。
6. **运行时版本和运行时捆绑具有可测量的经验影响**：同一模型在四个OpenClaw版本间最大得分差约0.052，严格可靠性差最多10/68场景（14.7个百分点）；跨运行时最大得分差0.0716，严格可靠性差最多13/68场景（19.1个百分点）——且没有单一运行时在所有模型上占优。
7. **评分视图不可互换**：无权重正确性均值与源复合排名Spearman 0.8060，最大排序移动46位——纯正确性排名与过程感知、安全门控、严格通过视图存在实质差异。
8. **失败模式异质**：主要失败类型包括：结构化输出/精确约束失败（10,718次检查失败）、缺失证据（6,674）、审批/时间/权限边界错误（6,357）、工具/运行时路由失败（6,115）、恢复/幂等性问题（3,763）、安全/披露边界（3,710）。

## 七、优点

1. **评估单元清晰**：明确以"模型加运行时配置"为评估对象，避免将框架效应误归因于纯模型能力。
2. **联合诊断框架**：将正确性、过程质量、安全门、效率、执行状态、重复可靠性和运行时间敏感性整合为可审计的多视图诊断，而不是单一分数。
3. **冻结保留集设计**：通过固定选择器、哈希和封闭世界JSON契约，支持固定契约下的跨运行时比较和重复试验可靠性分析。
4. **安全门非补偿机制**：严重安全违规（如凭证泄露、禁用审计、向私有频道泄漏）无法由正确输出抵消，符合高风险智能体场景的实际需求。
5. **替代路径处理**：明确允许任务通过不同证据顺序或内部推理路径获得满分/过程信用，避免过度执着于精确轨迹匹配。
6. **状态与溯源透明**：区分干净基线、重跑和未解决执行失败；每行绑定运行时版本、适配器版本、基准/检查器哈希、超时/重试策略等溯源字段。
7. **不确定性量化**：对排名相关、原生差距和可靠性差距提供bootstrap区间；对跨轨道对齐的弱结论保持诚实声明，不夸大。
8. **评价协议可适应**：运行时适应契约（8层）使跨运行时比较可复现，同时不将运行时特定原生分区伪装成可移植。

## 八、不足与局限

1. **非纯模型能力衡量**：结果是模型加运行时捆绑的度量，不独立于框架；跨运行时比较未隔离wrapper、路由、工具模式、安全层或控制器机制——是配置级证据而非单组件因果消融。
2. **原生表面覆盖范围有限**：完整的原生配置仅针对OpenClaw；跨运行时证据仅覆盖4个模型身份和3个运行时在工作区保留集上的表现，未覆盖所有智能体运行时、原生表面实现或组织工作流。
3. **任务覆盖面有限**：受限于当前任务域、语言、模型访问路径和提供商配置；不含多语言、视觉/多模态或长时多日任务（与ClawMark对比）。
4. **冻结保留集非"永久不可见私有测试集"**：它是校准后的选择器冻结；公开发布可复现性但增加过拟合/泄漏风险。
5. **原生 vs 工作区差距非因果**：原生场景可能还伴随检查器密度、输出格式或任务构建上的差异，简单分层控制不能完全排除混淆。
6. **跨轨道排序结论弱**：全-vs-保留集相关区间跨越零，无法得出稳定排序规律；此方向仍是高不确定性诊断。
7. **失败分类非金标准**：失败分类从失败检查详情自动分组，非独立人工标注本体，被视为审计优先级而非最终普遍率估计。
8. **无模型训练/微调信息**：未涉及GPU算力细节、训练时长或模型内部实现，限制了从模型侧复现或理解性能差异的能力。
