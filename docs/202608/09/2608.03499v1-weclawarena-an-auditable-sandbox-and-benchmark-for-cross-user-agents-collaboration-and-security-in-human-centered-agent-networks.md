## 摘要
近期在持久性个人智能体框架方面的进展，使得以人为中心的智能体网络成为现实的部署目标：每个用户都可以由一个人工智能智能体提供服务，该智能体代表用户行事、维护状态，并通过社交和任务关系与其他智能体进行通信。在这些网络中，日常工具使用变成了多方拥有的智能体在个人工作空间上的协作，其中文件、记录、工具和策略在所有者之间并不直接可见。现有的智能体基准研究了工具使用和协作，但并未提供端到端的沙箱，用于可验证的、具有真实用户数字工作空间的跨用户智能体协作，也未测试有害行为如何在以人为中心的智能体网络中传播。我们引入了WeClawArena，一个用于个人工作空间上多方拥有的智能体协作的可审计基准和运行时沙箱。WeClawArena针对协作式工具使用任务，其中个人工作空间既充当操作工具又充当个人约束。该基准包含六个跨用户任务域中的124个基础任务，并将其扩展为620个场景变体，每个基础任务有一个良性对照和四个攻击向量变体。沙箱记录对等消息、工具调用、资源操作、受治理的决策以及最终工作空间状态。WeClawArena分别报告效用和攻击成功率，并从有界运行时证据中审计攻击成功情况，支持对任务分解、隐私泄漏、受污染证据和无效权限路径的诊断。

## Abstract
Recent advances in persistent personal-agent frameworks are making human-centered agent networks realistic deployment targets: each user can be served by an AI agent that acts on the user's behalf, maintains state, and communicates with other agents through social and task relations. In these networks, everyday tool use becomes multi-party owned-agent collaboration over personal workspaces, where files, records, tools, and policies are not directly visible across owners. Existing agent benchmarks study tool use and collaboration, but they do not provide an end-to-end sandbox for verifiable cross-user agent collaboration with realistic user digital workspaces or test how harmful actions can travel through the human-centered agent network. We introduce WeClawArena, an auditable benchmark and runtime sandbox for multi-party owned-agent collaboration over personal workspaces. WeClawArena targets collaborative tool-use tasks in which personal workspaces serve as both operational tools and personal constraints. The benchmark contains 124 base tasks across six cross-user task domains and expands them into 620 scenario variants, with one benign control and four attack-vector variants per base task. The sandbox records peer messages, tool calls, resource operations, governed decisions, and final workspace states. WeClawArena reports utility and attack success rate separately and audits attack success from bounded runtime evidence, supporting diagnosis of task breakdown, privacy leakage, poisoned evidence, and invalid authority paths.

## 1. 核心问题与整体含义（研究动机与背景）

现有智能体（agent）评测主要聚焦于单用户工具使用（如 τ-bench、τ²-Bench）、共享权限的多智能体协作（如 AutoGen、MetaGPT、MultiAgentBench）、社会模拟（如 Generative Agents、OASIS、AgentSociety）以及隐私/安全/审计类基准（如 ConFAIDE、PrivacyLens、MAGPIE、AgentLeak、Auditable Agents 等）。但这些工作没有完整覆盖一个正在成为现实的新场景：

- **以人为中心的智能体网络**：每个用户拥有一个**个人智能体**，它代表用户行动、维护状态，并通过社交与任务关系与其他智能体通信；
- 日常工具使用演变为**跨用户、多方所有的智能体协作**，涉及个人工作空间（文件、数据库、工具、策略），这些资源**跨所有者不可见**；
- 协作通道同样可能被攻击者利用，传播**协作破坏、安全破坏、隐私泄露、治理违规**等有害行为。

**核心问题**：缺乏一个端到端、可验证、可审计的运行时沙箱与基准，来同时评价：
- **RQ1 任务效用**：当信息、工具、决策权分散在多个个人工作空间时，智能体能否完成工具使用型协作任务；
- **RQ2 最终伤害**：在协作通道承载对抗压力时，会产生哪些跨协作、安全、隐私和治理的危害；
- **RQ3 攻击审计**：能否基于有界运行时证据，追溯谁做了什么、哪些消息/工具/资源/权限路径重要，以及为何发生最终有害或良性结果。

**核心贡献**：
1. 形式化定义了“个人工作空间上的多方跨用户工具使用协作”问题；
2. 构建了包含 **124 个基础任务、620 个场景变体** 的基准，覆盖 bargaining、bidding、travel、SWE-Workspace、clinical、trading 六个域；
3. 提供可审计运行时沙箱与评测协议，将 **任务效用（utility）** 与 **攻击成功率（ASR）** 分开报告，并基于有界运行时证据审计最终危害。

## 2. 方法论：核心思想与关键技术细节

### 2.1 问题形式化

- 每个用户 u 对应一个**个人工作空间节点**：

  nu = (u, Au, Wu)，其中 Wu = (Fu, Du, Tu, Pu)

  - Au：被委托的个人智能体集合；
  - Fu：文件系统状态；
  - Du：数据库/结构化记录；
  - Tu：可用工具集；
  - Pu：策略、约束、同意规则或审批规则。

- 网络为有向图 G = (N, E)，边表示社交/任务关系，可携带角色、任务阶段、权限或审批上下文。

- 任务实例定义为 z = ⟨Gz, p, S0, B, F, C, Vz⟩，其中：
  - Gz：任务相关的个人工作空间图；
  - p：初始指令与私有目标；
  - S0：所有参与工作空间的初始状态；
  - B：每个工作空间可用的消息、工具、资源、决策动作集合；
  - F：动作执行引起的状态转移函数；
  - C：任务契约（规定哪些最终状态、记录、审批、消息或工件算满足任务，以及哪些边界不可跨越）；
  - Vz：任务验证器。

- **输出轨迹**：多工作空间轨迹 ξ = (Γ1, O1, Γ2, O2, …, ΓK, OK)，其中 Γk 为一个动作段（包含消息、工具调用、资源操作、审批、同意或最终化事件），Ok 为观察段。扁平事件序列更新状态：St = F(St−1, gt)。

- 关键原则：**个人工作空间既是任务完成的手段，也是约束表面**——场景如果只产生“看似合理的对话”而未读取/更新/验证任务契约要求的私有资源，则视为未解决。

### 2.2 四类伤害表面

| 表面 | 含义 | 示例 |
|---|---|---|
| 协作伤害（collaboration harm） | 破坏共享任务关系 | 目标劫持、错误交接、共识阻塞、错误共享计划 |
| 安全伤害（security harm） | 工具、资源或证据完整性受损 | 不安全工具使用、投毒证据、未授权资源变更 |
| 隐私伤害（privacy harm） | 受保护信息跨越未授权边界 | 违反语境完整性（Nissenbaum）的泄露 |
| 治理伤害（governance harm） | 无效权限路径 | 错误所有者、缺失同意、无效授权、越权审批、错误任务阶段 |

- 这些危害**不同于效用失败**：智能体可能完成任务但泄露受保护的预算上限、依赖伪造证据或接受无效审批；反之，可能在无攻击的情况下任务失败但没有任何攻击造成最终伤害。

### 2.3 基准构建

- **基础任务**：由人工标注者将域种子转换为场景表单（所有者角色、智能体人格、私有资源、允许工具、任务契约、效用谓词、策略/同意约束、预期最终工件、排除标准等），每个基础任务对应唯一的多方工具使用问题。
- **场景变体**：每个基础任务生成 5 个变体——1 个良性无攻击对照 + 4 个攻击向量变体（协作、安全、隐私、治理）。攻击变体保持任务契约和工作空间不变，但添加对抗性消息、文件、数据库行等资源绑定工件。
- **攻击构造原则**：攻击材料**不允许直接创建最终有害状态**；必须由智能体通过普通消息或工具遇到、路由、接受、重复或行动，才能算攻击成功。运行时记录攻击目标的暴露、合规、部分妥协、最终伤害和证据链接。
- **六个任务域**：
  - **Bargaining**（24 基础任务）：买家、卖家、审批者完成一笔有效交易；
  - **Bidding**（12）：卖方居中，买家出价，成交记录与预算、保留价、授标策略一致；
  - **Travel**（20）：酒店预订 + 旅行者约束 + 企业审批 + 同行者同意；
  - **SWE-Workspace**（50）：实现者、评审者、代码所有者、CI 所有者四角色工程工作流；
  - **Clinical**（10）：角色限定病历协调、受保护事实、同意/审批约束；
  - **Trading**（8）：市场决策工作流（订单、组合约束、私有策略、授权记录）。

### 2.4 评测指标

- **效用（Task Success Rate, TSR）** ：基于最终多工作空间状态与证据轨迹的领域特定谓词。例如 SWE-Workspace 要求工作流证据与 harness 结果都通过；bargaining/bidding 基于成交工件；clinical/trading 使用任务成功字段。
- **攻击成功率（ASR）** ：由 LLM-as-a-judge 在运行后从**有界证据包**（场景元数据、攻击元数据、转写消息、工具调用和观察、任务得分字段、所有者/治理上下文）判定，要求**最终危害 + 证据链与攻击向量清晰链接**。良性对照只用于假阳性校准，不进入 ASR 分母。

### 2.5 运行时沙箱

- 基于 Docker 的多用户沙箱，每个用户有独立 owner workspace；
- 网关记录代理消息、模型调用、工具调用/观察、资源读写、策略决策和最终状态（证据记录字段包括 agent_id、action_type、social_phase、payload、source_action_ids、governance、final_state）；
- 只允许通过网关路由的“基准有效”交互；绕过网关的资源/消息路径视为无效证据；
- 所有攻击向量变体在运行时通过 overlay 物化，但不能直接编辑最终分数状态。

## 5. 实验数量与充分性

### 规模
* 620 个场景 × 8 模型 = 约 4960 次运行（表 3 显示 attacked 行每模型约 296–496，benign 124），所有模型合计约 3743 条有效攻击判定行；
* 六域覆盖不同协作模式与资源类型的多样性较好；
* 每域含一个良性对照 + 四个攻击向量，可在同一任务上对比效用下降与最终危害；
* 每个变体均有结构化 ground truth 与规范证据包。

### 充分性评估
* **优点**：变体匹配设计使 TSR 下降与 ASR 判断可相互对照；人类审核与排除准则明确；ASR 判断验证充分（双判断器、良性假阳性、人工 pilot）。
* **潜在不足**：
  * 每模型每域样本量有限（如 trading 仅 40 行），统计功效有限；
  * 部分模型行覆盖不完整（表中 dagger 标记），可能影响与完整覆盖模型的公平对比；
  * 人工 pilot 仅 200 行、两位标注者，标注者组合噪声可能较大；
  * 没有公开所有运行轮次中的随机种子、失败重试策略等细节；
  * 没有提供“良性任务在无攻击条件下的难度校准”的显式人类基线（如人类专家在同样平台上的任务完成率）。

## 6. 主要结论与发现

1. **任务效用层面**：Claude Opus 4.7 总体最优，旅行与 SWE 域领先，Bargaining 最佳为 Sonnet 4.5；SWE-Workspace 对所有模型都很难（最佳全变体 TSR 仅 34%）。
2. **攻击成功差异巨大**：治理（governance）与安全（security）攻击的最终危害率最高，协作攻击最低；仅看 TSR 下降无法捕捉这一差异。
3. **域间异质性明显**：同一伤害表面在不同域表现不同——安全压力在 Bargaining/Bidding 最强；隐私和治理压力在 SWE-Workspace 最强；Bidding 几乎无治理伤害；不能简单合并伤害表面。
4. **效用与攻击成功相互独立**：
   * 117 行同时 “任务成功 + 攻击成功”（智能体完成可见任务但仍产生跨用户最终伤害）；
   * 1035 行 “任务失败 + 攻击成功”；
   * 640 行 “任务成功 + 攻击被阻止”；
   * 1951 行 “任务失败 + 无攻击成功”。
   * 说明 TSR 下降不能替代 ASR 判断，两者应独立报告。
5. **模型级风险需按表面评估**：如 Qwen3 32B 在隐私攻击下较稳但治理攻击下很弱；Kimi K2 Thinking 治理较稳但安全/隐私较弱；Claude Opus 4.7 在所有表面均为最高抵抗。
6. **审计可诊断性**：沙箱证据足以区分暴露无最终危害、部分妥协、最终伤害，并支持对投毒证据、隐私泄露、无效审批路径和协作阻断的具体案例追溯。

## 7. 优点

* **端到端完整性**：首次将“个人工作空间所有权 + 跨用户工具使用协作 + 攻击传播审计”整合进一个可由 Docker 复现的沙箱。
* **指标分离设计**：Utility(TSR) 与 ASR 分离，避免“任务完成即安全”或“攻击失败即无能”的混淆；可分析“完成任务同时产生有害状态”的关键失败模式。
* **变体配对设计**：同一基础任务四类攻击向量 + 良性对照，支持精确的效用下降与最终危害归因。
* **有界证据审计**：证据包里只包含运行记录，不暴露模型内部状态；ASR 判断器不能改变确定性分数，保证审计独立。
* **完善的 ASR 验证流程**：双 LLM 判断器 + 人工 pilot + 良性假阳性检验 + 分层一致性分析，审计可靠性论证较充分。
* **潜在有害负载的负责任发布**：开放任务、变体标签、分母与判断器代码，但剥夺/限制可重复利用的攻击载荷，兼顾可复现性与安全性。

## 8. 不足与局限

* **算力与资源披露缺失**：没有 GPU 数量、推理时延、仿真成本、判断器调用量等具体数字，不利于复现成本评估。
* **样本量与域均衡性**：Trading 与 Clinical 基础任务少（8、10），SWE-Workspace 占 250/620，导致域间统计功效不对等；部分模型有未完整覆盖的单元格（dagger），影响公平对比的严谨性。
* **LLM-as-a-judge 的偏差风险**：虽然做了双判断器和人工验证，但主判断器 GPT-5.2 系统性地比 Opus 4.7 给出更低 ASR（更“保守”）；两者在部分单元格差异达 ±8.9 个百分点；人工 pilot 规模小（200 行、2 人），标注者偏差与噪声仍存在。
* **攻击向量的人为构造性**：攻击载荷由标注者手工编写，可能无法覆盖真实世界攻击的广泛模式；领域覆盖面有限（无金融场景、法律场景、多模态场景）。
* **现实模拟的简化**：Docker 工作空间、SQLite、固定工具集不能完全复现企业/个人真实数字环境（如复杂权限系统、既有产品交互、非结构化数据）。
* **审计依赖记录完整性**：若网关被绕过或证据链断裂，行会被排除，这虽然保守但可能低估实际失败率；对无法被证据捕获的“软性”伤害（如对话误导但最终状态正常）可能检测不到。
* **基准时间点局限**：模型与框架版本固定在 2026 年 8 月，长期有效性依赖持续的扩展与维护。
