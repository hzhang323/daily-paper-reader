## 摘要
大语言模型（LLM）智能体为工业自动化分析带来了新机遇。然而，对此类智能体——例如在电力系统场景中——进行严格评估仍面临阻碍：真实运行数据是保密的，而现有公开资源未能充分刻画链式依赖关系和异构证据。为弥补这一空白，我们提出 PowerBench，包括（1）一个生成框架，通过共同依赖链推导出相互关联的异构运行数据，以及（2）由该框架生成的合成数据集。该数据集涵盖 100 种设备类型下的 761 台设备，包含跨越两年的 1335 万条小时级遥测记录和 24,939 份运行文档。基于该数据集，我们构建了覆盖三个任务家族的 300 道问题，用于评估前沿 LLM 在受限工具调用和时间预算下，完成需要自主证据检索与跨相互关联异构数据推理的分析任务的能力。结果表明，所评估的前沿 LLM 在这些任务上仍面临挑战：最佳模型仅达到 74.2% 的联合准确率。我们的轨迹分析进一步揭示，模型性能在证据发现、内容检索、工具使用、证据推理和答案提交等环节存在差异。这些发现为评估 LLM 智能体并指导其在工业中的可靠部署提供了详细见解。框架、数据集和基准任务可在 https://github.com/open-compass/PowerBench 获取。

## Abstract
Large language model (LLM) agents offer new opportunities for automated analysis in industry. However, rigorous evaluation of such agents-for example, within power system scenarios-remains hindered: real operational data are confidential, and existing public resources fail to fully capture the chained dependencies and heterogeneous evidence. To address this gap, we propose PowerBench, comprising (1) a generation framework that derives interconnected heterogeneous operational data through a common dependency chain, and (2) a synthetic dataset generated by this framework. The dataset covers 761 devices across 100 device types, with 13.35 million hourly telemetry records spanning two years and 24,939 operational documents. Building on this dataset, we construct 300 questions across three task families that evaluate frontier LLMs' ability to complete analysis tasks that require autonomous evidence retrieval and reasoning across interconnected and heterogeneous data under restricted tool calls and time budgets. Results demonstrate that the evaluated frontier LLMs remain challenged on these tasks: the best model reaches only 74.2% joint accuracy. Our trace analysis further reveals that model performance varies across evidence discovery, content retrieval, tool use, reasoning over evidence, and answer submission. These findings provide detailed insights for evaluating LLM agents and guiding their reliable deployment in industry. The framework, dataset, and benchmark tasks are available at https://github.com/open-compass/PowerBench.

## 2. 方法论

### 2.1 核心思想

以**设备实例**（而非单一模态）为组织中心，通过统一依赖链生成相互关联的异构数据：

$$O_d = (M_d, R_d, T_d, D_d)$$

依赖结构为：$M_d \to R_d$，$(M_d, R_d) \to T_d$，$(M_d, R_d, T_d) \to D_d$。可执行规则既用于**构建数据**，也用于**验证真值**。

### 2.2 四阶段生成框架

1. **设备与度量建模**：
   - 人工构建四级分类体系 $\mathcal{C}$（100 种设备类型），每种类型有原型 $p_c$。
   - LLM 推断类型特定维度 $Z_c = G_{dim}(p_c)$（区分性维度 + 实例化维度），再生成实例集 $I_c = G_{inst}(p_c, Z_c)$。
   - 设备元数据 $M_d = (a_d, K_d, H_d)$：配置向量、原子度量（含配置触发的特殊度量）、派生度量（多原子复合，禁含时间窗统计）。

2. **可执行规则构建**：
   - 两阶段 LLM 流程：先枚举监控对象（常见/特殊度量、特殊关注点），再生成结构化规则。
   - 规则 $R_c$ 含：规则 ID、目标对象、适用条件、输入度量、点条件、时序条件、布尔 DSL 表达式、命名阈值。
   - 设备绑定：$R_d = \{r \in R_c : Applicable(r, a_d)=1,\ Inputs(r) \subseteq (K_d \cup H_d)\}$，仅保留可在该设备上执行的规则。

3. **遥测与事件合成**：
   - 背景遥测 $X^{(0)}_d = B(T, K_d, H_d, a_d)$，需满足 $\forall r \in R_d,\ Eval(r, X^{(0)}_d, a_d)=0$（无规则触发）。
   - 采用安静带 + AR(1) 均值回归 + 配置感知 pin；用 6 个探测点检验，若触发则重采样（最多 3 次）。
   - 事件注入：$X^{(e)}_d = I_r(X^{(0)}_d, w, a_d)$，要求 $Eval(r, X^{(e)}_d, a_d)=1$。
   - **近失事件**（near-miss）：通过 $\alpha$ 混合 $X^{(\alpha)} = (1-\alpha)X_{base} + \alpha X_{inj}$，取最大使规则不触发的 $\alpha^\star$。
   - 最终 $T_d = (X_d, E_d, L_d)$（时序、事件集、调度与验证记录）。

4. **基于文档生成**：
   - 文档由程序从事实渲染（表格、结构化章节），LLM 仅填充标记的叙述槽位，禁止编造故障、时间戳、数值或规则 ID。
   - $A_d = G_{archive}(M_d, R_d, T_d)$，$C_d = G_{inspection}(M_d, T_d)$，$F_d = G_{fault}(M_d, R_d, T_d)$。

### 2.3 三类评测任务

- **TRR（时序检索与推理）**：从巡检报告识别需追查的度量，分析后续 72 小时遥测，输出所选度量、z 分数、单位、窗口均值/最大值、最大值首现时间。
- **CRR（上下文检索与推理）**：从故障叙述中恢复运行上下文，按负载类别调整规则阈值（高×0.8、低×1.2、其他×0.9，双匹配时低优先），在评估窗口内重放规则。
- **CoRR（比较检索与推理）**：对 3–5 台设备各自独立分析，选出峰值绝对 z 偏差最大的“最高风险设备”，并报告组内风险分数跨度。

## 6. 主要结论与发现

- **整体表现**：最佳模型 GPT-5.6-Sol 仅达 74.2% Macro-JA，说明前沿 LLM 在工业级链式检索与推理上仍受挑战。
- **任务族差异显著**：
  - 单设备 TRR/CRR 表现较好（Doubao-Seed-Evolving TRR 86.7% JA；GLM-5.3 CRR 96.7% JA）。
  - 多设备 CoRR 极难，最佳仅 48.7% JA，多数模型接近 0；FA 与 JA 差距大（如 GPT-5.6-Sol CoRR FA 74.0% vs JA 48.7%；Kimi-K3 FA 30.4% vs JA 2.7%）。
- **失败模式多样**：
  - 证据检索成功 ≠ 答案正确：DeepSeek-V4-Pro 在 TRR 上 RER 96.61%、AER 95.72%，但 JA 仅 50.0%。
  - 工具可靠性高 ≠ 推理正确：Kimi-K3 在 CoRR 上 RER 68.86%、AER 67.86%、TR 97.27%，但 JA 仅 2.7%。
  - Qwen3.8-Max / MiniMax-M3 工具调用多但错误率高，阻塞证据获取。
  - Llama-4-Maverick 工具调用极少，几乎不检索证据。
- **核心瓶颈转移**：许多失败发生在证据已获取之后，主要瓶颈在于**跨设备比较、逐设备计算与最终聚合**，而非单纯检索。
- **规模效应**：CoRR 中设备数从 3 增至 5，GPT-5.6-Sol JA 从 60.0% 降至 40.0%，FA 从 83.3% 降至 66.6%，TBR 从 4.0% 升至 48.0%，说明交互预算压力随任务复杂度上升。

## 7. 优点

- **数据生成框架创新**：以共享依赖链统一生成元数据、规则、遥测与文档，保证跨源一致性，且规则同时用于构建与验证真值，形成闭环。
- **可验证真值**：所有题目答案由程序化离线重放计算，通过 replay 匹配方可进入冻结集，避免真值模糊。
- **细粒度阶段诊断**：不仅报告最终准确率，还通过 RER/AER/TR/VS/TE/TBR 将失败归因到证据发现、内容检索、工具使用、推理、提交等具体环节，这是多数基准所缺乏的。
- **任务设计贴近实践**：TRR/CRR/CoRR 三族分别模拟“巡检后诊断”“故障后规则重评”“多设备比较”真实工作流，而非简化的网页浏览或列表过滤。
- **工程可复现**：提供完整代码、生成提示、解码参数、过滤标准、随机种子与环境说明，便于社区复现与扩展。
- **可扩展性**：基准不局限于评测的 9 个模型，可作为通用诊断工具评测新智能体。

## 8. 不足与局限

- **任务覆盖有限**：TRR/CRR/CoRR 仅覆盖三类工作流，未涉及拓扑推理、保护配合等电力系统任务；Macro-JA 对不同难度任务族等权平均。

- **公平性细节**：不同厂商 API 的默认解码参数、上下文窗口、工具调用协议可能存在差异，论文未完全披露是否做了严格对齐。

## 9. 总体评价与启示

- **定位价值**：PowerBench 是一份“诊断型”而非“排名型”基准，其核心贡献不在于给出模型排行榜，而在于揭示“智能体在工业链式任务中究竟卡在哪一步”。这种阶段级归因视角对后续智能体架构改进具有直接指导意义。
- **关键洞察**：
  - **检索不是瓶颈，聚合才是**——多数失败发生在证据获取之后，跨设备比较、逐设备计算与最终汇总成为主要障碍，提示未来工作应聚焦“结构化多源证据的整合推理”而非单纯提升检索召回。
  - **工具可靠性 ≠ 任务成功**——高 TR、高 RER 与低 JA 的并存说明，当前智能体缺乏将分散证据转化为一致性结论的“编排能力”。
  - **复杂度放大效应明显**——CoRR 中设备数增加会同时恶化准确率与预算占用，说明现有智能体的规划效率随任务规模快速衰减。
- **对研究社区的意义**：为工业智能体评测提供了可复用的方法论模板（依赖链驱动生成 + 规则双用 + 阶段诊断），可迁移至制造、能源、交通等其他异构数据密集领域。
- **对工程实践的启示**：在真实部署前，应优先补强智能体的“多源证据聚合”与“预算感知规划”能力，并建立类似的阶段级监控指标，而非仅关注端到端准确率。
- **未来可拓展方向**：引入真实脱敏工业数据、增加拓扑/保护等电力系统任务、加入成本与延迟指标、设计人机对比实验、支持多轮交互与主动澄清，从而向更完整的工业智能体评测体系演进。
