## 摘要
LLM智能体越来越多地被期望支持企业工作流，其中的任务通常涉及信息缺失、不确定性、反馈和长期权衡。然而，现有的企业和金融基准主要测试静态能力，如信息抽取、数值计算、领域知识和金融问答，而对交互式和长时程决策的探索仍不充分。为弥补这一空白，我们提出EnterpriseBench，一个评估LLM智能体在上述谱系上表现的基准，涵盖从静态问答到动态决策的任务。具体而言，EnterpriseBench将现有的企业和金融问答数据集重组为一个统一的基础套件，并按能力与难度进行标注，同时引入三个专业交互式场景：Consulting（咨询），基于管理咨询式商业案例，通过多轮信息搜寻诊断客户问题；Beer Game（啤酒游戏），改编自经典的供应链管理模拟，用于延迟反馈下的库存控制；以及Enterprise Digital Twin（企业数字孪生），一个基于项目的业务模拟器，用于劳动力、风险和项目规划。在四种骨干模型下对九种智能体方法进行的实验表明，当前智能体在企业场景中尚未实现稳定、全面且跨任务的可靠性。这些结果表明，EnterpriseBench为评估LLM智能体在真实企业战略推理与决策中的表现提供了一个实用基准。

## Abstract
LLM agents are increasingly expected to support enterprise workflows, where tasks often involve missing information, uncertainty, feedback, and long-term trade-offs. However, existing enterprise and financial benchmarks mainly test static capabilities such as information extraction, numerical calculation, domain knowledge, and financial QA, leaving interactive and long-horizon decision-making underexplored. To bridge this gap, we introduce EnterpriseBench, a benchmark that evaluates LLM agents across this spectrum, from static question answering to dynamic decision-making. Specifically, EnterpriseBench reorganizes existing enterprise and financial QA datasets into a unified foundational suite annotated by capability and difficulty, and introduces three professional interactive settings: Consulting, based on management-consulting-style business cases for client problem diagnosis through multi-turn information seeking; the Beer Game, adapted from a classic supply-chain management simulation for inventory control under delayed feedback; and Enterprise Digital Twin, a project-based business simulator for workforce, risk, and project planning. Experiments with nine agent methods under four backbone models show that current agents have not yet achieved stable, comprehensive, and cross-task reliability in enterprise scenarios. These results show that EnterpriseBench provides a practical benchmark for evaluating LLM agents in realistic enterprise strategic reasoning and decision-making.

- **背景**：LLM 及其智能体被越来越多地期望承担企业工作流任务，这类任务的典型特征是**信息缺失、不确定性、延迟反馈与长期权衡**，要求智能体主动搜集信息、在动态环境中行动、观察延迟反馈并随时间调整策略。
- **问题**：现有企业与金融基准（FinQA、DocFinQA、BizBench、Sec-QA、CFLUE、FinBen、XFINBENCH 等）主要评测**静态、固定输入**的能力——财报理解、表格数值推理、领域知识、信息抽取、金融问答。
- **缺口**：这些任务无法回答"LLM 智能体能否支撑真实企业工作流中的**交互式、长时程、战略性决策**"，因为静态问答既不含隐藏信息搜寻，也不含延迟反馈与跨期权衡。
- **整体含义**：论文提出 **EnterpriseBench**，把评测从"静态能力"扩展到"静态能力 + 交互式决策"的连续谱系，并给出经验可靠性证据，用以刻画当前智能体在企业战略推理与决策中的真实强弱。

## 2. 方法论

### 2.1 总体设计：两层评估原则

- **第一层（基础企业推理）**：评测做出决策前应具备的基础能力——从文档中抽取证据、执行数值计算、应用领域知识、完成复杂推理。
- **第二层（交互式企业决策）**：评测智能体能否在信息不完整、反馈延迟、行动影响未来结果的情形下运用上述基础能力。
- 两层的设计意图是：**静态 QA 只是必要条件，而非充分条件**；交互层用于暴露静态评测看不到的能力差异。

### 2.2 基础层：异构 QA 数据集重组为统一套件

- 将既有企业/金融 QA 数据集统一输入输出格式，按**四类能力**组织：
  - **Information Extraction（信息抽取）**：从企业文档、财报、表格中定位并抽取显式信息，无需外部知识或计算。
  - **Numerical Calculation（数值计算）**：算术运算、公式计算、代码化计算（如净变化、百分比、增长率、最大值/均值等）。
  - **Domain Knowledge（领域知识）**：会计/财务概念、XBRL 或 US-GAAP 标签、财务公式、会计准则、CFA 风格知识题。
  - **Complex Reasoning（复杂推理）**：受约束条件下的判断与决策（情景型 CFA 题、商业伦理/微观经济/专业会计的"应当怎么做"类问题）。
- **难度标注**：每样本赋 0–10 分难度，依据上下文长度、推理深度、歧义性、标签空间复杂度、所需推理步数；分为 Easy(0–3)、Middle(4–6)、Hard(7–10)。标注先由专家 LLM 以专用提示词初始化，再经人工审计验证（Pearson r = 0.96）。
- **关键分类规则**：只要涉及任何计算（哪怕简单相减），即归为 Numerical Calculation；仅当答案可逐字复制且无需计算时才归为 Information Extraction。对"标签选择/分类"类任务（如 US-GAAP 标签映射）设有专门的高难度规则。

### 2.3 交互层：三个专业交互任务

**（1）Consulting（咨询案例面试）**

- 素材来源：MBA 咨询案例库与咨询社团面试准备材料（多基于真实咨询公司面试案例），共 **423 个案例**。
- 每个案例包含：可见的问题陈述、**隐藏的案例事实**、参考答案。
- 机制：由一个 LLM 扮演**面试官**，被测智能体扮演**候选人**，进行多轮对话（最多 12 轮，以专用 `{INTERVIEW_END_TOKEN}` 结束）。面试官只在候选人提问明确指向某一维度（市场、成本、客户、竞争、运营、风险等）时，才**逐条解锁**"如被问及"类门控事实；绝不允许泄露 Solution / Analysis / Interviewer notes 等内部指导，也不得编造事实。
- 被测智能体必须：澄清目标、主动索取缺失信息、结构化分析、必要时做定量估算、最终给出商业建议。
- 评测：LLM 裁判基于完整对话记录与最终建议，从**四个维度**打分——Structure（结构化）、Quantitative Reasoning（定量推理）、Business Sense（商业判断）、Communication（沟通），Overall 取四维平均。
- 与常规 QA 的关键差异：**不只看答案对错，而看问题求解过程与信息搜寻质量**。

**（2）Beer Game（啤酒游戏，供应链库存控制）**

- 来源：Sterman (1989) 经典啤酒分销博弈，系统动力学传统，用于研究供应链协调、延迟反馈、库存振荡与牛鞭效应。
- 环境：四级供应链（零售商—批发商—分销商—工厂），被测智能体控制**零售商**，仅能观察本地状态（库存、缺货、在途货物、已实现需求），每步决策**订货量**。
- 关键参数：仿真 **25 个时间步**；订单信息延迟 1 周、实物运输延迟 2 周；初始稳态目标库存 400；需求在初始阶段为 100，第 2 周起跳升至 400（非平稳需求冲击）。
- 成本：单位库存持有成本 0.5/步，单位缺货惩罚 1.0，另设最低库存成本 200。
- 对手策略：其余三方采用固定方程策略——订货量 q_t = d_t + α(I* − I_t) + βB_t（α = β = 1），或用四步移动平均平滑需求后再代入（smoothing_4）。
- 评测指标：**总累积成本（越低越好）**。挑战在于延迟后果、非平稳动态与部分可观测性。

**（3）Enterprise Digital Twin（EDT，企业数字孪生）**

- 来源：改编自 transentis 的 Enterprise Digital Twin 项目（专业服务型公司业务模型）。
- 机制：与逐步决策的 Beer Game 不同，EDT 采用**场景级决策协议**——智能体接收一个模板企业场景（仿真期限、人力、候选项目、工作量、收入费率、风险、默认排期），一次性输出完整企业战略 **{C, R, P}**：保留的顾问人数 C、全局收入风险水平 R、项目组合排期 P（是否接受项目，以及接受的项目的开始与截止步）。
- 仿真执行：该配置被物化为新场景并在 BPTK 仿真器中完整运行，计算收入、支出、利用率、利润率与累积收益。
- 关键动力学：
  - 顾问成本：每步 Cost_c,t = N_c · (salary + workplace_cost) · dt（无论是否被利用均计费）。
  - 人力约束：顾问是唯一交付能力，每人每步最多服务一个项目，每个项目有并发人力上限 req_j，且**粘性分配**（一旦开始即锁定至该项目当前工作量完成）——这带来显著机会成本。
  - 交付与收入：每步交付努力 e_j,t ≤ k_j,t · dt；剩余工作量更新 E_j,t+1 = max(0, E_j,t − e_j,t)；项目收入 Rev_j,t = e_j,t · Rate_j。
  - 企业会计：Exp_t = fixed_cost·dt + Cost_c,t；累积收益 Earnings_T = AcRev_T − AcExp_T；利用率 Util_t = busy_t / N_c。
  - 随机机制：若项目在截止前完成基础范围，可能触发**范围扩展（extension）**；在截止步可能生成**跟进项目（follow-on）**，二者均由全局风险 R 与项目级概率门控。高 R 提高收益上限但锁定人力、增加不确定性；低 R 收益轨迹更可预测但上行空间小。
- 评测指标：**累积收益（越高越好）**，要求智能体在收入机会、人力成本、产能约束、截止期限与风险不确定性之间权衡。

### 2.4 AOA：自适应智能体选择（概念验证方法）

- 动机：主实验显示不同方法在不同任务/样本上各有所长，没有单一方法稳定最优。
- 流程：（i）**轨迹级经验抽取**——对每个样本与每个智能体的推理轨迹，抽取一条可复用经验（JSON 格式，含 bullet、tags、outcome、diagnosis、routing_hint、confidence）；（ii）**元级经验综合**——把大量经验聚合为可执行的**路由策略**（default_agent、tie_breaker、min_margin、rules），规则条件基于 task_name、capability、difficulty_bucket 及文本特征（是否有表格、是否有代码、数字个数、上下文/问题字符数、表格行数估计）。
- 关键约束：规则合成**不使用留出测试集的标签**，避免标签泄漏。

### 3.1 数据与场景

- **基础 QA 套件**（来自现有数据集的精选重组）：CodeFinQA、CodeTAT-QA、ConvFinQA、FinCode、finer、FinKnow、formula、FormulaEval、SEC-NUM、TAT-QA。

### 3.2 对比方法（9 种代表性智能体方法）

- **单智能体推理与自我改进**：CoT（思维链）、Self-Refine（自反馈迭代精炼）、Reflexion（带失败记忆的反思）。
- **多智能体协作**：Debate（对抗式辩论）、Discussion（合作式讨论，固定交互轮数）。
- **自适应/检索/记忆增强**：DC（Dynamic Cheatsheet，检索推理模式）、GEPA（自然语言反思 + Genetic-Pareto 的提示词进化）、ACE（从成功轨迹演化程序性 playbook）、AMEM（外部记忆存储与检索推理轨迹）。

### 3.3 骨干模型与评测协议

- **四种骨干**：DeepSeek-V3、
