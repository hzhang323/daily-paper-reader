## Abstract 

LLM-driven agent systems have emerged as a promising paradigm for electronic design automation (EDA), demonstrating strong po-tential for automating complex design workflows. However, exist-ing evaluations primarily examine individual language models on isolated EDA tasks, providing limited insight into how different agent systems perform across complete EDA flows. In this work, we present FluxBench, a systematic evaluation of AI agents on end-to-end EDA workflows under unified prompts, tool environments, and technology library settings. Our evaluation covers representative scenarios, including RTL generation with open-source toolchains and an RTL-to-GDS flow using closed-source commercial EDA tools for industrial applications. Through these workflows, we assess agents’ capabilities in RTL code generation, iterative repair, tool-feedback utilization, logic synthesis, placement and routing (P&R), and Engineering Change Order (ECO) automation. To further char-acterize the efficiency of agent systems, we introduce Token ROI, a cost-efficiency metric that measures effective improvements in EDA artifacts relative to token usage and runtime cost. Experimental results show that, even when built on the same foundation model, different agent system architectures can exhibit performance gaps of up to 86.27%. Moreover, among systems with comparable task performance, Token ROI can differ by as much as 105 .92 ×. In the RTL-to-GDS flow using PicoRV32 as a case study, FluxEDA achieves an end-to-end score of up to 97.94, outperforming Claude Code equipped with domain-specific EDA skills by up to 8.39 ×. These results indicate that domain-specific skills alone are insufficient to improve agent performance in large-scale EDA scenarios. Instead, both agent system design and foundation model capability play critical roles in enabling effective automated EDA workflows.

## 1 Introduction 

Large language models (LLMs) have recently shown strong po-tential in electronic design automation (EDA). Prior work has ex-plored LLMs for Verilog generation, RTL assistance, EDA script-ing, bug summarization, and domain-specific chip-design support [ 6, 12 , 16 , 18 ]. Building on these advances, recent studies have fur-ther moved toward LLM-based agents that can interact with EDA tools, decompose design tasks, execute scripts, analyze feedback,

and iteratively refine designs [ 8 , 11 , 13 , 14 ]. This shift suggests a broader transition from LLMs as passive design assistants to au-tonomous agents capable of participating in end-to-end EDA flows. Unlike general natural-language or coding tasks, EDA tasks are inherently tool-centric, requiring agents to invoke simulators, syn-thesizers, physical-design tools, and log analyzers through repeated multi-round interactions. Such tool use not only increases task complexity but also introduces token and cost overhead. As shown in Figure 1, moving from single-turn RTL reasoning to multi-turn RTL chat and agentic RTL design increases the input/output ratio from 1.80 to 12.38, average token usage from 1.02K to 213.82K, and average task cost from $0.007 to $0.734. To better advance AI agents for EDA, high-quality benchmarks are therefore essential. Exist-ing benchmarks, such as VerilogEval and RTLLM, have provided valuable evaluation platforms for LLM-based Verilog/RTL genera-tion, mainly focusing on functional correctness, syntax, and design quality [ 7, 9]. However, they are primarily designed for model-level generation tasks and provide limited support for reliably evaluating token consumption and multi-round tool-use behaviors. Conse-quently, the field still lacks a standardized, cost-aware, and tool-interactive benchmark for process-level evaluation of EDA agents in realistic end-to-end optimization flows. To fill this gap, we present FluxBench, which, to the best of our knowledge, provides the first systematic benchmarking of AI agents in realistic, end-to-end, and long-horizon EDA scenarios. In addition to conventional agent-level metrics and EDA-specific task metrics, FluxBench introduces Token ROI, a cost-efficiency metric for evaluating the return on agent usage. Specifically, we first define the task reward for each EDA task according to its design objective, and then divide it by the agent’s time and token consumption. Token ROI reflects how much useful EDA optimization improvement an agent can achieve per unit token and time cost, which is particularly important for long-horizon EDA tasks where tool interaction and iterative debugging can lead to substantial token and time overhead. Our benchmarking results show that AI agents producing similar final design outcomes can still exhibit substantially different opti-mization trajectories. In particular, the final Token ROI varies by up to 105.92 × across agents. As shown in Figure 2, stronger agents typically reach the optimization target within only a few iterations, whereas weaker agents often require many more trials to identify a valid or near-optimal configuration. This leads to significant differ-ences in both token consumption and runtime cost, highlighting the importance of process-level evaluation beyond final design quality. We further evaluate the effectiveness of domain-specific EDA skills. The results show that such skills provide moderate improvements under loose timing constraints, but offer limited benefits under more stringent timing requirements. In contrast, under the same foundation model, FluxEDA achieves an average performance im-provement of 57.00 points. These results suggest that both the agent architecture and the underlying foundation model are key factors for building effective automated EDA workflows. Our contributions can be summarized as follows: 

• To the best of our knowledge, FluxBench provides the first systematic benchmarking of AI agents in realistic, end-to-end, and long-horizon EDA flows. 

• We benchmark AI agents across conventional LLM-for-EDA evaluation tasks, classical RTL generation tasks using open-source tools, and PicoRV32 RTL-to-GDS flows using closed-source commercial tools, enabling comprehensive evaluation across EDA workflows of different scales and complexities. 

• We propose Token ROI, a cost-efficiency metric that measures the optimization gain toward EDA task objectives per unit token and time cost. 

## 2 Related Work 

LLMs and Benchmarks in EDA. LLMs show significant potential in streamlining EDA processes [ 16 , 18 ], with models like Chip-NeMo [ 6] and VeriGen [ 12 ] focusing on domain adaptation and direct code generation. To evaluate these capabilities, early bench-marks such as RTLLM [ 9] were introduced for basic RTL generation tasks. Recently, the scope of evaluation has expanded significantly: RealBench [ 5] assesses models on real-world IP-level designs, and CVDP [ 10 ] introduces comprehensive Verilog design problems to test broader reasoning skills. However, despite this growing diver-sity, these datasets primarily evaluate static outcomes or single-turn Can AI Agents Really Complete RTL-to-GDS? generations. A critical gap remains: existing benchmarks still pro-vide limited support for evaluating autonomous agents in realistic end-to-end, long-horizon, and tool-interactive EDA flows. 

Autonomous Agents for EDA. To overcome single-turn limi-tations, recent research has shifted toward autonomous agents capable of managing multi-step EDA workflows. Frameworks like ChatEDA [ 13 ] and AutoEDA [ 8 ] introduced LLM-driven task plan-ning and modular tool automation. Building on this paradigm, FluxEDA [ 3 ] has emerged as a prominent framework, offering ro-bust, agent-driven workflow automation to effectively streamline the hardware design process. 

## 3 Benchmark Construction 3.1 Execution Environment 

As illustrated in Figure 3, we encapsulate all tasks in a containerized environment to reduce the impact of host-dependent variation on evaluation results. The container provides a complete open-source EDA toolchain for RTL generation tasks. For tasks requiring commercial EDA tools or restricted PDKs, the benchmark does not directly distribute these dependencies; instead, they are accessed from the user environment through read-only mounts at runtime, balancing reproducibility and compliance. Each task runs in an independent agent session, where the agent can access only the task description, public inputs, and editable files, without visibility into hidden tests, reference solutions, or internal scoring data. 

## 3.2 Data Collection 

The selected tasks mainly consist of RTL generation and RTL-to-GDS tasks. The RTL generation tasks are selected from the spec-to-RTL subsets of RealBench [ 5 ] and CVDP [ 10 ]. RealBench contains three circuit families: AES, e203_hbirdv2, and SDC. We classify the e203_hbirdv2 tasks as hard and the tasks from the other two fami-lies as easy. For CVDP, we select 112 tasks based on their scores, including 18 hard tasks and 94 easy tasks. These tasks require agents to generate RTL modules from natural-language specifications and validate their functionality using testbenches, thereby evaluating their hardware semantic understanding, Verilog/SystemVerilog pro-gramming, and simulation debugging capabilities. For RTL-to-GDS tasks, we select the PicoRV32 design with a 55 nm technology node. PicoRV32 is a compact open-source RISC-V processor core whose datapath and control logic are more represen-tative than those of small toy circuits, while its moderate scale keeps full physical implementation and iterative optimization tractable. The mature 55 nm process exposes agents to realistic synthesis, timing, floorplanning, placement, routing, and ECO constraints without excessive complexity. This combination enables a con-trolled and meaningful evaluation of end-to-end implementation capabilities. 

## 3.3 Quality Control and Reproducibility 

The agent can only access public materials at runtime, while ref-erence results and final evaluation logic are used by the evaluator only after the task is completed. Each task runs independently from a consistent initial workspace, and all commands, logs, reports, and final artifacts are preserved. For commercial-tool tasks, missing tools, files, or process data are recorded as environment failures rather than being masked by substitute flows. 

## 4 Experiments 4.1 Experimental Setup 

Agent architectures. We evaluate three representative agentic coding frameworks: FluxEDA-Agent, Claude Code, and CC+EDA Skills. FluxEDA-Agent targets EDA-oriented agent workflows [ 3], while Claude Code serves as a general-purpose coding agent [ 1 ]. CC+EDA Skills extends Claude Code with domain-specific skills, which provide domain-specific IC/EDA workflow knowledge [4]. 

Models. We use three representative language models as the un-derlying reasoning and coding backbones: Deep Seek-V4 Flash, GLM-5.2, and Claude Sonnet 5. These models represent some of the most widely used and advanced systems in current agentic coding workflows, and are selected for their strong capabilities in coding, reasoning, long-context understanding, and tool use [2, 15, 17]. 

Task inputs and constraints. For RTL generation tasks, agents are provided with natural-language functional specifications, together with a small set of auxiliary scripts and RTL code. For RTL-to-GDS tasks, the technology files are provided locally, and two timing constraints are considered: a loose constraint of 350 MHz and a tight constraint of 700 MHz, both specified through SDC files. The die size is fixed in the prompt, requiring agents to optimize design quality under the given timing constraint.

## 4.3 Main Results 

RTL generation. Table 2 reports the results of three representative agent architectures combined with different foundation models on the easy and hard subsets of RealBench and CVDP. Overall, the results reveal substantial differences across benchmark difficulty levels. CVDP-Easy is nearly saturated, with six of the nine evaluated configurations achieving a perfect score of 100.00 and the remaining scores exceeding 98.00. In contrast, RealBench remains considerably more challenging: the best scores on its easy and hard subsets are only 57.10 and 53.58, respectively, both achieved by FluxEDA with GLM-5.2. CVDP-Hard also retains strong discriminative capability, where scores range from 52.35 to 100.00, and FluxEDA with GLM-5.2 is the only configuration that achieves a perfect score. From the perspective of efficiency, the architectures and founda-tion models exhibit clear trade-offs in score, ROI, cost, and runtime. DeepSeek-V4 consistently provides the most favorable cost profile, with costs generally below 18 RMB and substantially higher ROI than GLM-5.2 and Claude Sonnet 5. When paired with DeepSeek-V4, FluxEDA improves the RealBench-Easy, RealBench-Hard, and CVDP-Hard scores from 41.26, 22.00, and 69.58 under vanilla Claude Code to 46.62, 32.74, and 78.04, respectively. It also reduces the runtime on all four subsets, while lowering the cost on RealBench-Hard and CVDP-Hard from 9.83 and 7.76 RMB to 9.50 and 5.68 RMB. CC+EDA Skills shows more mixed behavior: it improves DeepSeek-V4 on RealBench-Hard from 22.00 to 31.09 while reducing the cost from 9.83 to 8.77 RMB, but does not consistently improve perfor-mance on CVDP. FluxEDA with GLM-5.2 achieves the strongest overall scores, although this advantage is accompanied by substan-tially higher costs and longer runtimes. 

RTL-to-GDS. Table 3 summarizes the end-to-end PicoRV32 RTL-to-GDS results under the loose 350 MHz and tight 700 MHz timing targets. Overall, FluxEDA delivers the strongest and most consistent optimization performance across both settings. Under the loose tar-get, FluxEDA with DeepSeek-V4 achieves the highest score of 97.94 and the highest ROI of 39.91. Although Claude Code with DeepSeek-V4 attains the lowest cost and shortest runtime in this setting, its score is only 13.33, indicating a substantial trade-off in final design quality. Under the tight 700 MHz target, FluxEDA with GLM-5.2 obtains the best score of 93.70, while FluxEDA with DeepSeek-V4 achieves both the highest ROI of 48.06 and the shortest runtime of 94.28. Notably, all three models paired with FluxEDA achieve scores above 90 under both timing targets, demonstrating strong robustness across different LLM backends. In contrast, the Claude Code and CC+EDA Skills baselines exhibit considerably greater performance variation across models and timing constraints. These results demonstrate that FluxEDA provides a favorable balance between final QoR and optimization efficiency, particularly in chal-lenging end-to-end physical design scenarios. Meanwhile, Figure 4 further shows that FluxEDA achieves these improvements with a reasonable token overhead. 

## 5 Observation 5.1 The Role of Skills in Agentic EDA 

Observation 1: The impact of skills is limited. Although the domain-specific EDA skills improves performance over Claude Code on easy RTL generation tasks and the 350 MHz RTL-to-GDS task, it shows almost no advantage under the more stringent 700 MHz constraint and may even have a negative effect. This suggests that, in realistic EDA RTL-to-GDS scenarios, simply relying on skills does not necessarily lead to better outcomes. Instead, stronger foundation models and more effective system architectures are the key to achieving stable capability improvements.

## 5.3 Stability of the RTL-to-GDS Flow 

Observation 3: The MCP-based architecture of FluxEDA pro-vides substantially higher process stability than conventional CLI-based approaches. As shown in Table 5, FluxEDA success-fully completes all stages of the RTL-to-GDS flow, including logic synthesis, place-and-route, and physical-aware ECO, across all evaluated models and target frequencies. In contrast, the conven-tional Claude Code configuration exhibits notable instability at several stages. For example, Claude Code with DeepSeek-V4 fails to complete I/O placement, CTS, and physical-aware ECO under the 700 MHz target, while several other configurations also termi-nate before completing the ECO stage. Moreover, introducing the domain-specific skills does not fundamentally resolve this issue: un-der the Claude Code + EDA Skills configuration, DeepSeek-V4 and Claude Sonnet 5 still fail to complete I/O placement and physical-aware ECO at both target frequencies. This indicates that Skills can improve the model’s understanding of EDA procedures and provide useful domain guidance, but they cannot fully compensate for the structural limitations of CLI-based interaction, such as weak state management, unstructured tool feedback, and limited error recovery. Although FluxEDA may consume more tokens because MCP introduces structured tool descriptions, execution feedback, and additional interactions, this overhead is acceptable for EDA workflows. Since RTL-to-GDS flows involve long execution chains, strong inter-stage dependencies, and low error tolerance, the im-proved reliability and end-to-end stability provided by MCP are more important than minimizing token consumption. 

## 6 Conclusion 

This paper presents FluxBench to systematically evaluate AI agents in realistic end-to-end EDA workflows. It covers RTL generation and industrial PicoRV32 RTL-to-GDS tasks, and introduces Token ROI to jointly measure performance, cost, and runtime efficiency. Results show that foundation models and agent architectures are key factors, while domain-specific Skills alone are insufficient for complex industrial EDA flows, as agents may still fail at critical steps of the RTL-to-GDS process.
