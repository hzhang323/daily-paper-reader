## 摘要
多智能体系统（MAS）基于大语言模型（LLMs）正在迅速激增，但它们的异构执行轨迹为跨方法评估提供了共同基础。仅结果基准丢弃了协作，而LLM作为评判的评估需要额外的、依赖模型的推理，并且可能随LLM和评分标准而变化。我们引入了一个可泛化的评估框架，将原生MAS轨迹映射到统一的协作图共享空间中，使得不同方法能够在相同的表示、参考集和指标面板下进行评估。候选图与查询特定的参考森林进行比较。每个森林都是基准提供的已验证成功图的集合：它记录了代表性MAS方法完成任务的各种方式，而不是规定一个唯一的最优过程。将该框架实例化为ForestBench，我们从七个公共数据集中筛选出844个需要协作的查询，为每个查询预计算十个成功的以目标为条件的参考图，并评估六个代表性的MAS框架。受控骨干、参考构建和扰动研究测试了评估的稳定性和范围。一旦建立了基准森林，ForestBench可以在毫秒内对轨迹进行评分，无需进一步的LLM推理，为比较不同的MAS协作轨迹提供了可复用的结构基础。

## Abstract
Multi-agent systems (MAS) built on Large Language Models (LLMs) are proliferating rapidly, but their heterogeneous execution traces provide no common basis for evaluation across methods. Outcome-only benchmarks discard collaborations, whereas LLM-as-Judge evaluation requires additional, model-dependent inference and can vary with the LLM and rubric. We introduce a generalizable evaluation framework that maps native MAS traces into a shared space of unified collaboration graphs, enabling different methods to be evaluated under the same representation, reference set, and metric panel. Candidate graphs are compared with a query-specific reference forest. Each forest is a benchmark-provided collection of verified-success graphs: it records diverse ways in which representative MAS methods can complete the task, rather than prescribing a unique optimal process. Instantiating the framework as ForestBench, we filter $844$ collaboration-necessary queries from seven public datasets, precompute ten successful target-conditioned reference graphs per query, and evaluate six representative MAS frameworks. Controlled backbone, reference-construction, and perturbation studies test the stability and scope of evaluation. Once the benchmark forests are built, ForestBench scores a trace in milliseconds without further LLM inference, providing a reusable structural basis for comparing diverse MAS collaboration traces.

## 1. 核心问题与研究动机

- 基于 LLM 的多智能体系统（MAS）快速发展，但不同框架的执行轨迹（trace）在事件格式、角色命名、通信协议上高度异构，缺乏横向比较的公共基础。
- 现有评估方式存在明显缺陷：
  - **仅结果评估**（如 GSM8K、MMLU、HumanEval 上的准确率）将整个执行过程压缩为最终答案，完全丢失了协作信息；
  - **LLM-as-Judge 过程评估**需要额外调用模型进行推理，成本高、可复现性差，且分数随模型和评分标准变动。
- 因此，论文提出需要一种**可泛化的统一表示**，将异构 MAS 执行轨迹规范化到同一结构空间，并支持确定性、可复用的结构比较。

## 2. 方法论

### 2.1 统一图抽象（Graph Abstraction）

- 将一次 MAS 执行轨迹映射为有向无环协作图：

\[
G(\tau) = (V, E, \phi)
\]

- 节点 \(V\)：每个原子动作；
- 边 \(E\)：动作之间的信息传递；
- 标签 \(\phi\)：节点对应的智能体、规范化角色、文本内容。
- 图是有向无环的，因为动作只能消费已产生的信息，边严格指向未来。
- 该投影是有损的：丢弃框架特定的运行时状态和精确时钟交错，保留角色、动作和信息流，使不同框架的原生轨迹可以同构比较。

### 2.2 参考森林（Reference Forest）

- 同一查询可用辩论、流水线、群体等多类协作模式完成，因此不指定唯一最优过程，而是构建“参考森林”：

\[
F(q) = \{(G_k, q_k)\}_{k=1}^{K(q)}
\]

- 每个 \(G_k\) 是已验证成功的参考图，来自不同代表性 MAS 范式；
- \(q_k\) 表示该参考图的权重，综合正确性、结构简洁性和 token 成本；
- 森林是 benchmark 提供的固定资产，新的候选轨迹可直接与同一参考集比较，无需重新生成或调用 LLM。

### 2.3 评估指标

- **成对图相似度**：

\[
sim(G,G') = \alpha s_{node} + \beta s_{edge} + \gamma s_{topo}
\]

默认权重 \((\alpha,\beta,\gamma)=(0.4,0.4,0.2)\)：
- \(s_{node}\)：角色多集合的 Jaccard 相似度；
- \(s_{edge}\)：角色类型化边指纹集合的 Jaccard 相似度；
- \(s_{topo}\)：基于节点数和边数规模的比值项。
- **Forest Match（FM）**：候选图与参考森林中所有参考树相似度的权重平均：
  \[
  FM(G,F(q)) = \frac{\sum_k w_k \cdot sim(G,G_k)}{\sum_k w_k}
  \]
  衡量候选与成功结构集合的整体对齐程度。
- **Best Similarity**：与最近参考树的相似度，衡量是否接近某个单一成功模式。
- **辅助指标**：
  - **Accuracy**：任务最终准确率；
  - **Node Validity**：被下游动作消费的有效节点比例；
  - **Mean Uptake**：下游内容是否语义上使用了上游内容（基于嵌入相似度）；
  - **Content Redundancy**：内容归一化后的重复程度；
  - **Tokens**：总 token 预算；
  - **Efficiency**：每个活跃智能体的图并行度。
- 打分过程是 \(G(\tau)\) 的确定性函数，无需额外 LLM 推理，单条轨迹毫秒级完成。

## 3. 实验设计

### 3.1 数据集与 Benchmark 构建

- 原始查询池来自 7 个公开数据集，覆盖 4 类任务：
  - 推理：GPQA、MMLU、MATH-500、GSM8K；
  - 代码生成：SWE-bench-Verified；
  - 工具使用：Terminal-Bench；
  - 多跳搜索：WideSearch。
- 使用 **Trace-Suitability Pipeline（TSP）** 筛选查询，要求同时满足：
  - 深度 \(d(q) \ge 5\)；
  - 宽度 \(w(q) \ge 0.5\)；
  - 可分解性 \(\delta(q) \ge 0.5\)。
- 最终得到 **844 个“协作必要”查询**，分布为：推理 55.9%、多跳问答 23.7%、代码 15.8%、工具使用 4.6%。

### 3.2 参考森林生成

- 使用 6 个代表性 MAS 框架作为参考生成器：**Multi-agent Debate、Swarm、AutoGen、MetaGPT、MAS-GPT、AFlow**，另含单智能体 CoT-SC 结构锚点。
- 每个查询预计算 **10 个已验证成功、目标条件化的参考图**，共 **8,440 个参考图**。

### 3.3 候选方法与主干模型

- 评估 6 个候选 MAS 框架：Debate、Swarm、AutoGen、MetaGPT、MAS-GPT、AFlow。
- 默认主干为 DeepSeek-V4-Flash；另用 Claude-Sonnet-4.6、GPT-5.5、Qwen3.6-Plus 做稳健性验证。
- 每个查询跑 3 个随机种子，约 2,532 条轨迹/框架，总计约 15,192 条轨迹。

## 4. 资源与算力

- 论文**没有报告 GPU 型号、数量或训练/评估的硬件时长**，只给出了 token 层面的开销：
  - 构建参考森林的一次性成本：DeepSeek-V4-Flash 消费约 **20.5M tokens**，平均每个查询约 **24.3k tokens**，覆盖 8,440 条目标条件化参考轨迹。
  - 线上评估成本：ForestBench 评估 1,000 条轨迹约 **0.7 秒、0 推理 token**；LLM-as-Judge 基线约需 34 分钟和大量 token，二者差距约 **2,900 倍**。
- 参考森林是一次性构建、重复使用，后续每次评估不产生额外推理成本。

## 5. 实验数量与充分性

- **主实验**：6 个框架在 844 个查询上的全局指标对比（约 15,192 条轨迹）。
- **参考森林稳健性实验**：
  - 跨后备模型（Claude-Sonnet-4.6、GPT-5.5）构建参考森林，排序完全一致（Kendall/Spearman=1.00）；

  - 逐源剔除 8 个设置的排名分析。
- **受控扰动实验**：节点删除、边重连、角色交换、干扰插入、重复内容注入，两种强度（\(p=0.3, 0.5\)）。
- **超参数敏感性**：
  - 5 种非退化权重方案（Kendall \(\tau\ge0.73\)，Top-3 全部保持；仅拓扑权重会失效）；
  - 36 种 TSP 阈值组合，框架排序全部保持 \(\tau=1.00\)。

- **总体评价**：实验数量充足、覆盖面广泛，包含横向对比、消融、扰动、成本分析，设计较为客观和公平；为避免候选框架与同源参考图“自我比较”，采用 Leave-One-Out 处理，增强了结果可信度。

## 6. 主要结论与发现

- **仅靠准确率难以区分不同 MAS 方法**：6 个框架准确率仅相差 0.038（0.531–0.569），但结构指标差异显著（Forest Match 0.316–0.421）。
- **参考森林能提供可复现的结构判别信号**：例如 Debate 准确率最高，但 Forest Match 和 Best Similarity 最低，token 消耗最大；MAS-GPT 的 Forest Match 最高。
- **辅助指标可揭示最终答案隐藏的问题**：AFlow 内容冗余度最高（0.167）；Swarm 是唯一 Node Validity 低于 1 的框架（0.968）。
- **结构信号稳定**：跨主干模型、剔除参考生成器、开放式构建、TSP 阈值变化下，整体排序基本稳定。
- **编排收益依赖骨干能力**：相对于单智能体 CoT，DeepSeek-V4 平均增益 −0.002，GPT-5.5 为 −0.039，Claude-Sonnet-4.6 为 −0.069，说明更强骨干下盲目增加智能体并非总是有效。
- **聚合排名会掩盖领域特化**：Debate 全局最差，但在 SWE-bench-Verified 上却是最对齐的方法，反映其“评审-修订”结构更适合代码任务。
- **失败模式可分为结构性和内容性两类**：前者需要自适应的角色/拓扑选择，后者需要更强的验证、聚合和证据吸收。
- **效率优势显著**：ForestBench 评估速度比 LLM-as-Judge 快约 2,900 倍，且每次评估零推理 token。

## 7. 优点

- **统一图表示**：能够将异构 MAS 轨迹映射到同一 DAG 表示，实现横向、可复用的结构比较。
- **参考森林思想**：以多种已验证成功结构而非单一路径作为参考，避免偏向某一协作范式。
- **确定性评估**：打分过程无需额外 LLM 推理，毫秒级完成，成本低、可复现性强。
- **丰富的指标面板**：同时覆盖结果、结构对齐、信息消费、冗余、效率，能够刻画不同维度差异。
- **稳健性验证充分**：对骨干模型、参考构建方式、权重、阈值、扰动等进行了系统的敏感性和消融实验。
- **实用性**：提供了 844 个查询、8,440 个参考图和适配器，下游用户可直接复用参考森林，避免重复构建。

## 8. 不足与局限

- **参考森林并非“唯一最优过程”**：Forest Match 衡量的是与参考成功结构集的相对对齐程度，不能直接解释为通用协作质量；结构相似性也不等于因果意义上的协作有效性。
- **TSP 筛选只是启发式**：筛选出的查询并不严格证明“必须多智能体才能解决”，单智能体也可能完成。
- **图抽象有损**：丢弃了精确时钟交错、运行时状态等细节，可能丢失部分动态协作信息。
- **数据分布偏斜**：推理任务占 55.9%，工具使用仅占 4.6%，可能影响对不同任务类型的泛化结论。
- **LLM 失败诊断存在标签敏感性**：论文明确报告细粒度标签对 rubric 措辞敏感（结构失败 Cohen’s \(\kappa\) 仅 0.129–0.351），因此诊断结果只宜用于粗粒度修复方向，不能作为严谨的 benchmark 分数。
- **权重选择影响结论**：仅用拓扑权重时框架排序显著变化（Kendall \(\tau=0.20\)），说明语义角色和边类型信息对维持结果很重要。
- **参考森林构建存在一次性成本**：约 20.5M tokens，且论文未报告 GPU 等硬件资源细节，无法据此评估训练/推理能耗。
- **没有真正意义上跨框架的端到端公平性保证**：虽然采用 Leave-One-Out 和跨骨干验证，但各框架本身的自带提示、默认流程和参数各异，仍可能存在额外的框架偏差。
