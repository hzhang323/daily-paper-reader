## 摘要
尽管自主智能体通过迭代浏览开放网络来综合信息，在“深度研究”方面取得了显著进展，但现实世界的问题求解很少局限于单一环境。复杂分析任务本质上要求智能体将来自模糊非结构化文本（如开放网络）和高度精确结构化数据（如关系数据库）的证据编织在一起。然而，现有基准孤立地评估这些模态，未能捕捉关键的“交接”——在系统之间迁移证据时保持约束的能力。我们提出 HybridDeepResearch，据我们所知，这是首个要求同时使用网页搜索和 SQL 来形成完整、可验证答案的深度研究基准。该基准包含 380 个依赖工具的任务，基于 LiveSQLBench-Base-Lite 数据库和公共网页语料库，经过自动检查和人工审核验证，涵盖三种推理模式：SQL2S、S2SQL 和 Parallel。在多种智能体脚手架下对专有模型和开放权重模型的评估显示，即使是最先进的模型，如 GLM-5.2、Claude-Sonnet-4.6 和 GPT-5，在困难子集上也仅达到约 50-54% 的 Pass@8。值得注意的是，结果表明定向推理比并行交集困难得多，这凸显出在不丢失约束的情况下弥合结构化与非结构化信息空间，仍然是智能体系统面临的重大开放挑战。代码和数据集已在 GitHub（https://github.com/Snowflake-AI-Research/HybridDeepResearch）和 Hugging Face（https://huggingface.co/datasets/Snowflake/HybridDeepResearch）公开提供。

## Abstract
While autonomous agents have made significant strides in "deep research" by iteratively navigating the open web to synthesize information, real-world problem-solving is rarely confined to a single environment. Complex analytical tasks inherently require agents to weave together evidence from both ambiguous unstructured text (e.g., the open web) and highly precise structured data (e.g., relational databases). However, existing benchmarks evaluate these modalities in isolation, failing to capture the critical "handoff" - the ability to preserve constraints when moving evidence between systems. We introduce HybridDeepResearch, to our knowledge the first deep-research benchmark that requires both web search and SQL to form a complete, verifiable answer. The benchmark contains 380 tool-dependent tasks grounded in LiveSQLBench-Base-Lite databases and public web corpora, validated through automated checks and human review, and covering three reasoning patterns: SQL2S, S2SQL, and Parallel. Evaluations across proprietary and open-weight models under various agentic scaffolds reveal that even state-of-the-art models like GLM-5.2, Claude-Sonnet-4.6 and GPT-5 achieve only about 50-54% Pass@8 on the hard subset. Notably, results show that directional reasoning is substantially more difficult than parallel intersection, highlighting that bridging structured and unstructured information spaces without losing constraints remains a major open challenge for agentic systems. Code and datasets are publicly available at GitHub (https://github.com/Snowflake-AI-Research/HybridDeepResearch) and Hugging Face (https://huggingface.co/datasets/Snowflake/HybridDeepResearch).

## 1. 核心问题与整体含义（研究动机与背景）

- **现实需求**：金融审计、供应链风险评估、科学研究等高风险场景，要求智能体同时融合**模糊的非结构化文本**（开放网页、新闻、公开文件）与**高度精确的结构化数据**（关系数据库）。
- **现有基准的割裂**：文本到 SQL（如 Spider、BIRD、LiveSQLBench）与开放网页检索/深度研究（如 BrowseComp、BrowseComp-Plus）被**分别评估**，无法衡量真实任务中两类工具的协同。
- **关键失败模式——“交接（handoff）”**：当证据需在系统间转移、交叉验证时，智能体常**丢失约束**。一个模型可能单独在 Text-to-SQL 或浏览任务上达到 SOTA，却在需要协调两者时完全崩溃。
- **论文定位**：提出 **HybridDeepResearch**，据作者所知是首个要求**同时使用网页搜索与 SQL** 才能形成完整、可验证答案的深度研究基准，作为诊断混合深度研究能力的工具。

## 2. 方法论

### 2.1 核心思想：三种混合推理模式

- **SQL2S（SQL-to-Search）**：数据库先给出刚性锚点（如某供应商），该实体必须约束后续网页搜索。典型失败是“显著性陷阱”——用泛化关键词搜索，返回了其他公司的高排名新闻。
- **S2SQL（Search-to-SQL）**：网页搜索发现实体或条件，须转化为严格的 SQL 谓词（如 `WHERE vendor_name = 'Company A'`）。典型失败是“丢失锚点”——实体识别对了，但 SQL 未施加必要过滤。
- **Parallel（并行交集）**：SQL 与搜索各自独立产生候选集，最终答案只能是两者的**精确交集**。典型失败是“过早融合”——只返回网页命中的公司，未与数据库约束交叉核对。
- 三者共同考察同一底层能力：**跨结构迥异的模态保持、翻译与调和语义约束**。

### 2.2 构建流水线（三大机制）

- **双接地实体锚定（Dual-Grounded Entity Anchoring）**：从数据库单元格提取具体实体，用 Google Knowledge Graph 验证全局显著性；再用 SQL 探索智能体分析该实体在具体 schema 中的用法，生成“数据库接地描述”，避免同名歧义（如 "Monaco" 可为国家/城市/赛事）。
- **角色感知的对称生成（Role-Aware Symmetric Generation）**：
  - *非结构化轨道（搜索题）*：① 从 Wikidata 属性三元组、Wikipedia 及 FineWeb-10BT 长尾文档构建**多跳证据图**；② 证据精炼，剪除弱/歧义/过时关系；③ **受控线索模糊化**，将实体名抽象为描述性属性（如 "2012"→"2010年代"）以防单词捷径；④ LLM 按目标模式将模糊图改写为自然语言问题。
  - *结构化轨道（SQL 题）*：从 BIRD-SQL 与 LiveSQLBench 人工查询中提炼 **35 个高级 SQL 模式**（6 类、3 个难度级），按种子实体角色实例化：S2SQL 生成严格谓词；SQL2S 返回含种子的单行结果；Parallel 返回含种子的多行候选集。
- **跨模态组合与“混合锁（Hybrid Lock）”**：S2SQL/SQL2S 采用**方向性组合**（一方的精确输出成为另一方的刚性约束）；Parallel 采用**集合交集**，仅保留交集能唯一确定共享实体的配对。最终对每题做**单工具消融**：仅用搜索或仅用 SQL 各尝试一次，凡可被单一模态解出（参数记忆、查询泄漏、过宽检索命中）的题目一律丢弃，再经人工复核。

## 3. 实验设计

- **数据基础**：9 个 LiveSQLBench-Base-Lite 数据库 + 公开语料（Wikipedia、FineWeb-10BT）。
- **基准规模**：全量 **380 题**（SQL2S 203、Parallel 119、S2SQL 58），证据深度集中在 5–6 步；另构建**平衡困难子集 120 题**（每类 40 题），用于有限 API 预算下的受控比较。每题关联 1–4 条 `sql_knowledge` 片段，仅 2.6%（10 题）含显式提示。
- **智能体框架**：单智能体 **smolagents** 与多智能体 **MiroFlow**（主智能体向专业 worker 分派子任务）。
- **检索后端**：**Real Web**（Serper + Jina Reader 实时网页）与 **Corpus Search**（Wikipedia + FineWeb-10BT 固定索引，两阶段文档级/块级检索）。
- **评测模型**：
  - 开源权重：Qwen3.5-4B/9B/27B/122B-A10B/397B-A17B（FP8，vLLM 服务）、GLM-5.2-FP4，在全量集上评测。
  - 专有：GPT-5、Claude-Sonnet-4.6（medium reasoning effort），在平衡困难子集上用 smolagents 评测。
- **工具接口**：`run_sql`（只读 SQLite，仅允许 SELECT/WITH/PRAGMA/EXPLAIN，不注入 schema，需自行探索）、知识库查询工具、`web_search`/`web_fetch`/`pdf_read`/`read_file` 或语料版 `web_search`/`visit_web`。
- **评测协议**：每题 **8 次独立试验**；Pass@8（至少一次成功）与 Avg@8（平均成功率）。S2SQL 通过执行预测与金标 SQL 并比对结果表；SQL2S/Parallel 用 BrowseComp 式 LLM judge（Qwen3-30B-A3B-Instruct-2507）比对自由文本答案。
- **对比维度**：脚手架、检索后端、模型家族与规模、混合模式、专有 vs 开源、全量集 vs 困难子集。

## 6. 主要结论与发现

- **整体成功率低**：在平衡困难子集上，最强模型 GPT-5 的 Pass@8 为 **54.17%**，Claude-Sonnet-4.6 的 Avg@8 最高仅 **28.12%**；图 1 显示代表性模型整体 Avg@8 **低于 30%**，说明成功既不高频也不可靠。
- **方向性推理远难于并行交集**：GLM-5.2 在 MiroFlow 下 S2SQL Pass@8 为 62.07，而 Parallel 高达 93.28；GPT-5 在困难子集 S2SQL 45.0、Parallel 77.5。跨模态“交接”是主要瓶颈。
- **多智能体脚手架提升 Pass@8 但不稳定提升 Avg@8**：MiroFlow 使 Qwen3.5-397B 的 Pass@8 从 58.95 升至 66.32（Real Web），但 Avg@8 基本持平；原因是更多 worker 尝试带来更多调用与超时。
- **固定语料后端具竞争力**：Corpus Search 与 Real Web 的 Avg@8 差异很小，提供更可控的评测设置。
- **规模并非单调增益**：Qwen3.5 家族中 27B dense 在若干设置下优于 122B-A10B MoE；GLM-5.2-FP4 是开源最强（MiroFlow 下 75.79 Pass@8 / 49.24 Avg@8）。
- **三类反复出现的失败模式**：Parallel 的候选仅由单一来源支持（未做交集）；SQL2S 在后续搜索中丢失数据库约束；S2SQL 实体识别正确但 SQL 操作/公式错误。
- **排名受类型分布影响**：全量集上 Claude 整体优于 GPT-5，而困难子集上 GPT-5 Pass@8 更高，因 S2SQL 在全量集仅占 15.3%，而在困难子集占三分之一。

## 7. 优点

- **首个明确定位“结构化 + 非结构化”交叉的深度研究基准**，填补了现有评测在数据库查询与网页搜索协同上的空白。
- **Hybrid Lock 机制**：通过单工具消融强制题目必须同时依赖两种工具，从构建层面抑制单模态捷径，这是方法论上最关键的亮点。
- **双接地实体锚定 + 角色感知对称生成**：有效缓解命名歧义与同义实体干扰，并让搜索题与 SQL 题在共享种子实体上严格对齐。
- **受控线索模糊化与证据图精炼**：抑制单词捷径与参数记忆泄漏，提高题目质量。
- **SQL 模式目录**（35 个模式、6 类、3 难度）保证结构化组件的复杂度与多样性，避免 LLM 生成浅层重复查询。
- **评测设计细致**：Pass@8 与 Avg@8 双指标、单/多智能体、实时/固定语料、开源/专有、全量/平衡困难子集，并配有轨迹统计与失败案例分析，诊断价值高。
- **完整的人工审核流程**（SQL 模式验证、最终题质控、困难子集选择，四人共识决策）与公开的代码/数据。

## 8. 不足与局限

- **数据覆盖面有限**：仅基于 9 个 LiveSQLBench-Base-Lite 数据库与 Wikipedia/FineWeb-10BT 公开语料，**不覆盖专有 schema、专业科学数据库及真实网络的完整多样性**。
- **类型不平衡**：全量集中 S2SQL 仅 58/380，SQL2S 占多数；困难子集虽平衡但规模仅 120 题。
- **评测范围不一致**：专有模型仅在困难子集（smolagents + Corpus Search）上做 8 次试验，全量集仅 2 次试验，跨表比较需谨慎；多智能体框架下 MiroFlow 超时率高达 41.3%，可能低估其真实能力或引入偏差。
- **评分器依赖**：SQL2S/Parallel 使用 LLM judge，可能引入判断噪声；S2SQL 的表比对虽客观，但列对齐规则可能影响结果。
- **困难子集选择偏差**：由作者人工挑选并结合试点结果，虽非唯一标准，仍可能偏向特定失败模式。
- **证据可靠性风险**：公开网页证据可能继承事实错误、偏见或不当内容；智能体输出也可能包含无依据主张或错误数据库结果，需独立验证，不适合高风险部署。
- **计算成本**：多智能体重复评测开销显著，论文未报告总算力消耗，也未给出训练层面的资源信息（因为不涉及训练）。
- **扩展性未知**：作者计划在新数据库上扩展并发布公开榜单，说明当前版本仍是受控的初步版本。
