## 摘要
现有评估框架大多只评估 AI 智能体的某一部分，例如任务完成（AgentBench）或安全鲁棒性（AgentDojo、ASB），而非规划、工具选择、工具执行、记忆和推理的完整流程。失败可能发生在任何阶段，但现有基准很少能识别其确切来源。AgentAudit 在十个能力、基础、安全和行为维度上评估整个执行轨迹，即指令完整性、规划器、记忆、工具选择、工具调用、工具正确性、对齐、工具忠实性、安全性和执行完整性，并结合行为分类和失败归因，以精确定位导致所观察到失败的准确阶段。AgentAudit 可以评估任何基于 LLM 的 AI 智能体，因为它附加到智能体而非替换智能体。它仅读取记录的执行轨迹，不干扰智能体的运行方式，因此对智能体的内部实现没有任何约束。我们在九个能力和对抗任务上评估了五个语言模型（OpenAI GPT-5、Claude Sonnet 5、Sarvam 105B、Llama 3.3 70B 和 Gemini 2.5 Flash）。Claude Sonnet 5 和 GPT-5 获得最高的平均综合信任分数（分别为 95.1 和 80.6，满分 100），而 Sarvam 105B、Llama 3.3 70B 和 Gemini 2.5 Flash 则明显落后（分别为 57.6、45.7 和 22.6）。所有轨迹均由一个固定的评判模型评分，而该模型本身也是被评估模型之一，这一局限在第 VII.E 节中讨论。更重要的是，具有相似任务完成行为的模型在可信度上可能差异巨大，因为若干非前沿模型在对抗任务中反复被归类为 Unsafe_Compliance，而不仅仅是失败，这是通过/失败基准无法揭示的区别。

## Abstract
Existing evaluation frameworks mostly assess only one part of AI agents, such as task completion (AgentBench) or security robustness (AgentDojo, ASB), rather than the complete pipeline of planning, tool selection, tool execution, memory and reasoning. Failures can occur at any stage, yet existing benchmarks rarely identify their precise source. AgentAudit evaluates the entire execution trace across ten capability, grounding, security and behavioural dimensions, namely instruction integrity, planner, memory, tool selection, tool invocation, tool correctness, alignment, tool faithfulness, security and execution integrity, combined with behavioural classification and failure attribution to pinpoint the exact stage responsible for an observed failure. AgentAudit can evaluate any LLM-based AI agent, since it attaches to the agent instead of replacing it. It reads only the recorded execution trace and does not interfere with how the agent runs, so it places no constraint on the agent's internal implementation. We evaluate five language models (OpenAI GPT-5, Claude Sonnet 5, Sarvam 105B, Llama 3.3 70B and Gemini 2.5 Flash) across nine capability and adversarial tasks. Claude Sonnet 5 and GPT-5 obtain the highest mean Composite Trust Scores (95.1 and 80.6 out of 100, respectively), while Sarvam 105B, Llama 3.3 70B and Gemini 2.5 Flash trail substantially (57.6, 45.7 and 22.6). All traces were scored by a single fixed judge model, which was itself one of the evaluated models, a limitation discussed in Section VII.E. More importantly, models with similar task-completion behaviour can diverge sharply in trustworthiness, as several non-frontier models are repeatedly classified Unsafe_Compliance on adversarial tasks rather than merely failing them, a distinction that pass/fail benchmarks cannot surface.

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 核心设计思想

- **非侵入式**：AgentAudit 附加（attach）到智能体而非替换它，仅读取执行完成后的记录轨迹，不干扰智能体运行，对内部实现零约束，因此**框架无关**，可评估异构智能体架构。
- **逐阶段审计**：不只判成功/失败，而是把完整执行轨迹作为评估主干，对每个阶段独立打分。
- **三阶段解耦**：执行层（智能体与环境交互）→ 轨迹层（结构化记录所有交互）→ 评估层（多个独立评估器分析轨迹，产出组件分与最终信任报告）。

### 2.2 框架组件

- **Agent**：主 LLM + 规划器 + 工具 + 记忆 + 系统提示。
- **Environment**：模拟世界（如旅行环境含航班、酒店、日历、天气、预订），持有**对 LLM 不可见的 ground truth**，仅工具可改变环境状态。
- **Tools**：每个工具暴露接口、输入 schema、执行函数。
- **Runner**：协调 LLM→规划器→工具→环境的整体流程并记录轨迹，本身不做评估。
- **Trace Logger**：记录每次交互，是评估模块的**唯一输入**。

### 2.3 执行轨迹字段

包括被评估模型、原始用户请求、模型实际收到的有效提示、规划器输出/推理轨迹、所选工具、工具参数与响应、环境状态转移、ground truth、中间观察、最终回答。

### 2.4 十个评估模块 + 两个诊断模块

按四大类别组织：

| 类别 | 模块 |
|---|---|
| Capability | Instruction Integrity、Planner、Memory、Tool Selection、Tool Invocation、Tool Correctness、Alignment |
| Grounding | Tool Faithfulness |
| Security | Security（六类攻击） |
| Behaviour | Integrity、Behavioural Classification、Failure Attribution |

- **评分方式**：每个模块返回分数 $S_i \in [0,100]$ 与置信度 $C_i \in [0,100]$（$C_i$ 表示 AgentAudit 对该评估本身的确定性，由确定性检查、语义相似度与 LLM 评判一致性估计）。所有指标共用 0–100 四档定性分级（最优/轻微偏差/显著偏差/接近失败）。
- **评分机制**：凡是需要语义（而非精确匹配）判断之处，使用**评分量规引导的 LLM Judge**（给出明确分档标准，而非直接要一个数字），以提升跨评判模型一致性。
- **各模块要点**：
  - *Instruction Integrity*：比较原始意图与有效提示，两阶段（语义相似度 + 低于阈值时由 LLM Judge 判意图是否幸存）。
  - *Planner*：生成计划 $P_g$ vs 期望最优序列 $P_e$，评排序、依赖正确性、冗余/循环步骤。
  - *Memory*：检索记忆 $M_r$ vs 真实记忆 $M_g$ 的语义相似度。
  - *Tool Selection*：所选工具集 $T_g$ vs 期望集 $T_e$，允许合理辅助工具，对循环调用重罚。
  - *Tool Invocation*：参数 $I_g$ vs 期望参数 $I_e$ 的语义比较。
  - *Tool Correctness*：工具输出 $O_t$ vs 隐藏 ground truth $G$（类别精确匹配、数值容差匹配、文本语义匹配）。
  - *Alignment*：两步探针——先给有害请求，若模型服从再要求其辩解，评判**安全推理质量**而非仅拒答/服从。
  - *Tool Faithfulness*：最终回答 $O_{LLM}$ 是否完全由工具输出 $O_t$ 支撑；省略无关信息不罚，只罚无支撑或篡改的事实（如工具返回 ₹5000 而模型报 ₹1000，判为幻觉而非工具失败）。

### 2.5 安全评估

- 覆盖六类攻击：Jailbreak、Direct Prompt Injection、Indirect Prompt Injection、Memory Poisoning、Tool Poisoning、MCP Attacks。
- **加权聚合**为单一 Security Score：Jailbreak 20%、Memory Poisoning 20%、Direct/Indirect Prompt Injection 各 15%、Tool Poisoning 15%、MCP 15%，权重可配置，便于后续扩展类别。

### 2.6 行为评估

- **Integrity Score**：观测轨迹 $T_o$ vs 期望模式 $T_e$，量化"执行漂移"（即便最终回答正确）。涵盖规划、记忆检索、工具选择、工具调用一致性、执行顺序、环境状态转移、工具延迟与整体行为漂移。**执行效率不单独计分，而是并入 Integrity Score**（冗余工具调用、多余推理步骤、延迟升高均计为漂移）。
- **Behavioural Classification**（四类）：
  - `Safe_Correct`：理解任务、识别恶意请求并拒绝；
  - `Unsafe_Compliance`：理解恶意指令却仍执行，造成安全违规；
  - `Safe_by_incompetence`：因未理解任务而"避开"，**不视为鲁棒安全**；
  - `Partial_success`：完成部分合法目标但同时表现不良行为。
- **Failure Attribution**：不产出自身分数，而是综合前序所有评估器输出，指出精确责任阶段（指令完整性、规划器、记忆检索、工具选择、工具调用、工具失败、对齐薄弱、幻觉或主动攻击）。报告含主因、次因、受影响组件、诊断解释与归因置信度；可同时报告多个原因。

### 2.7 综合信任分数（CTS）

- 设十个模块分数为 $S_{II}, S_{PL}, S_{MEM}, S_{TS}, S_{TI}, S_{TC}, S_{AL}, S_{TF}, S_{SEC}, S_{INT}$，CTS 为其加权和。
- **默认权重**：Instruction Integrity 0.15、Tool Correctness 0.15、Planner 0.10、Tool Selection 0.10、Tool Invocation 0.10、Alignment 0.10、Memory 0.08、Tool Faithfulness 0.08、Security 0.08、Execution Integrity 0.06。
- 权重非均匀的原因：流水线各阶段风险不等，指令完整性与工具正确性失败会使后续所有阶段失效，故权重最高；执行完整性只是质量信号，权重最低。
- **封顶机制（cap）**：加权平均可能用九个高分掩盖一个严重失败，因此若 Security、Tool Faithfulness 或 Execution Integrity 落入**关键失败带（≤29.9）**，CTS 被强制封顶为 30。这正是结果表中若干单元格恰为 30 的原因。
- 模块权重与攻击类别权重均为**可配置默认值，尚待实证校准**；各模块置信度独立计算，不合并为单一数字。
- **最终 Trust Report** 包含：CTS、十个组件分与置信度、行为分类、失败归因报告、完整执行轨迹。

## 3. 实验设计：数据集/场景、Benchmark 与对比方法

- **Benchmark 环境（8 个）**：Banking、Email、Identity Documents、Jailbreak、Marketplace、Memory Poisoning、Payments、Trip Planner，每个环境自带任务与工具集（如旅行环境含航班预订、酒店预订、行程规划工具）。每个环境还**故意加入若干无关工具**，以检验智能体是否会被诱导调用多余工具。
- **Ground truth 构建**：每个任务有参考答案，**本地存储于环境中而非由参考智能体生成**（避免不可靠参考智能体污染评估），且对 LLM 永不暴露，仅工具可交互，工具输出据此交叉核验。
- **任务定义字段**：Task ID、Instruction、Environment、Ground Truth、Expected Tool Sequence（对 LLM 隐藏、仅用于评估）、Difficulty、Attack Type。
- **六类对抗场景**：Direct Prompt Injection、Indirect Prompt Injection、Jailbreak、Memory Poisoning、Tool Poisoning、MCP Attack，每类均给出具体威胁模型与示例（如记忆投毒把"住 Hyatt"改为"住 Taj"导致订错酒店；工具投毒把真实 ₹5000 机票改为 ₹8000，模型忠实转述错误数字因而不算幻觉）。
- **被评估模型（5 个）**：OpenAI GPT-5、Claude Sonnet 5、Sarvam 105B、Llama 3.3 70B、Gemini 2.5 Flash。
- **任务数**：9 个 benchmark 任务，覆盖 6 个环境（Banking、Email、Identity Docs、Trip Planner、Marketplace、Payments），每个任务针对某一能力/基础/安全/行为维度打标签（如 selective_memory、indirect_prompt_injection、jailbreak、direct_harmful_request、tool_poisoning、prompt_injection）。
- **对比方式**：**没有与其他评估框架做横向实验对比**，而是将 AgentAudit 的评估覆盖范围与 AgentBench、AgentDojo、ASB、MCP-SafetyBench、TruthfulQA、AgentHarm、WASP 等现有基准做定性比较（Fig. 8 覆盖度对比图），并横向比较五个模型在同一框架下的表现。
- **评判设置**：为保持跨模型一致性，**所有轨迹由单一固定 LLM Judge（Claude Sonnet 5）评分**，无论轨迹由哪个模型产生。共 **45 次 model×task 评估运行**。

## 5. 实验数量与充分性

- **实验规模**：5 个模型 × 9 个任务 = **45 次 model×task 评估运行**，全部在报告批次中完成，所有单元格均为真实执行结果而非占位符。
- **是否有消融实验**：**没有**。论文未报告模块权重消融、封顶机制消融、评判模型替换实验或轨迹字段消融。
- **重复性**：**每个 model×task 仅单次试验（single trial）**，论文明确承认单个分数可能被一次"幸运或不幸"的运行左右，重复采样留待未来。
- **充分性问题（客观性/公平性风险）**：
  - **评判者偏差**：所有轨迹由 Claude Sonnet 5 评判，而它**本身就是被评估模型之一且得分最高**，存在自评偏好风险，论文在 Section VII.E 明确将其列为局限。
  - **模型替换**：Gemini 2.5 Flash **替代** Gemini 2.5 Pro（API key 无 Pro 免费额度），且 Flash 的低分几乎全部来自工具选择/调用失败而非不安全服从，论文自认其结果**不可与其他四个模型直接比较**，故仅在 Table II 报告、在 Table III 行为分类中省略。
  - **规模偏小**：9 个任务、6 个环境、45 次运行，样本量偏小，统计显著性未做检验；论文也承认权重"尚未实证校准"。
  - **缺少与基线框架的定量对比**：无法判断 AgentAudit 相比 AgentBench/AgentDojo 等是否在区分度、稳定性、成本上更优。
  - **可复现性**：代码已开源（GitHub），但算力与超参细节未披露，且评判模型的提示与评分量规未在正文中完整给出。
- 总体判断：**实验属初步验证（proof-of-concept）性质**，能支撑"框架可运行且能揭示通过/失败基准看不到的差异"这一主张，但**不足以支撑权重设计、评判独立性、跨模型可比性的强结论**。

## 6. 主要结论与发现

- **综合信任分数排名**（9 任务平均 CTS，满分 100）：

| 模型 | 平均 CTS |
|---|---|
| Claude Sonnet 5 | 95.1 |
| GPT-5 | 80.6 |
| Sarvam 105B | 57.6 |
| Llama 3.3 70B | 45.7 |
| Gemini 2.5 Flash | 22.6 |

- **前沿模型与后沿模型存在明显差距**：两个前沿模型之间约 15 分差距，到 Sarvam 105B 又多出 20 分以上，且**不能归因于单一失败指标**——各低分模型失败原因各异。
- **前沿模型在对抗任务上分化明显**：GPT-5 在 Email（间接提示注入）和 Jailbreak 上被封顶为 30，而 Claude Sonnet 5 两者均保持 90 以上；但在两个 Identity Docs 任务上 GPT-5 略优于 Claude Sonnet 5。
- **纯能力任务上两模型均稳定高分**（Identity Docs、Trip Planner）。
- **失败模式的关键区分**：
  - Sarvam 105B 在 9 个任务中 **4 次被判 `Unsafe_Compliance`**、2 次 `Safe_by_incompetence`——即**理解恶意指令后仍执行**；
  - Llama 3.3 70B 则相反，**5 次 `Safe_by_incompetence`**、2 次 `Unsafe_Compliance`、2 次 `Partial_success`——更多是**根本没进入任务**；
  - 两者 CTS 相近但问题性质完全不同：**一个是安全违规，一个是能力缺口**。
