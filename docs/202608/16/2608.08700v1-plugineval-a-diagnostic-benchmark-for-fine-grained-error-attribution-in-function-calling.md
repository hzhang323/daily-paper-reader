## 摘要
随着大型语言模型日益作为自主代理运行，工具路由的可靠评估变得至关重要。当前的基准存在三个结构性局限：遵循幂律分布的数据使得罕见场景代表性不足；缺乏对抗性硬负样本掩盖了不同模型之间的性能差异；以及标注流程依赖于未经执行验证的LLM判断。在本文中，我们介绍了PluginEval，这是一个通过两阶段框架构建的基准，系统性地缓解了这些局限。首先，我们将工具路由表述为三个决策序列，并将生成与验证分离。LLM提出候选调用，而确定性验证和真实API执行提供可靠的质量信号。其次，我们按功能、意图和边界对每个插件进行分解，以识别触发场景和排除场景。然后，我们在不同难度级别生成查询以填补覆盖缺口，包括针对三种失败模式的对抗性负样本，并将其返回第一阶段进行标注。这一过程形成了一个闭环，迭代直至覆盖收敛。在评估方面，我们超越了总体准确率。锚定于黄金标注的LLM评判器将失败分类为遗漏调用、虚假调用或参数错误，为每个模型生成详细的错误画像。我们评估了五个模型家族，包括专有模型和开放权重模型，分析了它们在不同难度级别和错误类别上的表现，并通过与人工标注的一致性验证了评判器的有效性。

## Abstract
Reliable evaluation of tool routing is critical as Large Language Models increasingly operate as autonomous agents. Current benchmarks face three structural limitations: data distributions that follow a power law leave rare scenarios underrepresented; the absence of adversarial hard negatives obscures performance differences across models; and annotation pipelines depend on LLM judgments that have not been validated through execution. In this paper, we introduce PluginEval, a benchmark constructed through a two-stage framework that systematically mitigates these limitations. First, we formulate tool routing as a sequence of three decisions and separate generation from verification. LLMs propose candidate calls, while deterministic validation and real API execution provide reliable quality signals. Second, we decompose each plugin by capability, intent, and boundary to identify trigger and exclusion scenarios. We then generate queries at different difficulty levels to fill coverage gaps, including adversarial negatives targeting three failure modes, and return them to the first stage for annotation. This process creates a closed loop that iterates until coverage converges. For evaluation, we move beyond aggregate accuracy. An LLM judge anchored to gold annotations classifies failures as missed calls, spurious calls, or parameter errors, producing a detailed error profile for each model. We evaluate five model families, including proprietary models and models with open weights, analyze their performance across difficulty levels and error categories, and validate the judge through agreement with human annotations.

## 2. 方法论：PluginEval Closed-Loop Construction Framework（PCCF）

### 2.1 任务形式化：三层路由决策

将工具路由建模为三个层级决策（高层错误会使下游决策失效）：

- **f₁：工具必要性**——查询是否需要调用工具；
- **f₂：插件相关性**——目标插件是否提供请求的功能（对每个查询-插件对独立评估）；
- **f₃：调用可执行性**——能否将请求实例化为 schema 合法的参数调用；信息不足时返回 ⊥（合理拒答）。

标签空间：Y = {(0,0,⊥), (1,0,⊥), (1,1,⊥)} ∪ ({(1,1)} × Θₜ)，分别对应工具不必要、插件不相关、信息不足但相关、有效调用。

### 2.2 Stage I：执行接地的集成标注

- **生成与验证分离**：M 个 LLM 生成器独立提出完整调用或拒答，互不组合字段形成混合答案，避免交叉污染。
- **验证流程**（对每个候选 z）：
  1. **确定性 schema 校验**：结构化合法性检查；
  2. **参数评估器 S_arg**：判断参数是否被查询支持且符合插件语义；
  3. **模型上下文协议（MCP）真实执行**：执行调用并观察响应 o；
  4. **结果评估器 S_out**：检查执行结果是否满足用户请求；
  5. **综合得分**：s = λ_arg·S_arg + λ_out·S_out，其中 λ_arg + λ_out = 1；得分 ≥ τ 即被接受为黄金标注。
- **迭代修复**：被拒绝的候选保留其失败痕迹（schema 错误、执行异常、超时等），作为下一轮生成器的修订信号，最多 R_max 轮。拒答候选不执行，由参数评估器判断是否属于合理拒答。
- **与自精化的区别**：非依赖生成器自身的自我反馈，而是借助独立评估者、确定性校验和执行结果作为修复信号，降低自我评估偏差。

### 2.3 Stage II：场景驱动的合成与行为校准

- **场景目录构建**：从插件描述中提取 **触发场景**（应调用插件的请求）和 **排除场景**（无需工具 / 需其他插件 / 超出目标插件能力），每个示例标注一个主场景 + 辅助标签。
- **难度分层**：
  - 正样本：按推理深度分难度——0 步推理 = Easy，1 步 = Medium，≥2 步 = Hard；
  - 负样本：按类型设定难度目标——Type A 按领域距离、Type B 按表面相似度、Type C 按能力边界证据。
- **覆盖缺口驱动合成**：每个覆盖单元的缺口 Δr(u) = max{0, b(u) − n_r(u)}，只对缺口 > 0 的单元合成新样本。
- **行为难度校准**：用冻结的参考路由器运行 K 次评估 p_K(x)，行为难度 = 全部正确 → Easy，部分正确 → Medium，全部错误 → Hard。若校准难度低于目标，则加强负样本的"识别证据"（recognition evidence）后重新验证校准。

### 2.4 闭环整合

- Stage I 返回标注、执行证据、失败痕迹；Stage II 据此更新覆盖、合成缺失场景、强化弱负样本，再将新查询送回 Stage I 验证，循环直至覆盖预算全部满足、覆盖改进低于阈值（连续 L 轮），或合成预算耗尽。
- 关键设计：将"样本是否可信"（Stage I 验证）与"样本是否必要"（Stage II 覆盖分析）彻底分离，每个被接受样本都关联覆盖缺口、验证记录和校准难度。

### 2.5 黄金锚定的评估框架

- **语义一致性标准**：设计 gold-anchored LLM judge，以人工验证的黄金调用 G 为唯一评估锚点，查询 q 仅用于解释语义等价性，禁止扩展或覆盖黄金规范。预测调用即使表面合理也不算对，必须与黄金参数语义一致。
- **三层验证流程**：
  1. **工具对齐**：按工具名精确匹配交集 I = T_P ∩ T_G，未匹配工具记录为工具选择错误；
  2. **参数过滤**：任一侧参数为空则跳过该对齐对；
  3. **语义验证**：LLM judge判定语义等价性（允许别名、格式差异、等价数值表示等；时间范围严格比对），返回二元判定和理由。
- **查询级评估与错误归因**：
  - 多工具查询需全部工具召回且参数全部正确才算成功；
  - 混淆矩阵：TP 完整正确；FN 漏工具、参数错误或判定失败（再细分为 miss recall / parameter error / judge failure）；FP 在负样本上误调用；
  - 参数错误进一步分为：时间错误、缺失参数、值错误。

## 6. 主要结论与发现

1. **难度组成对分数影响巨大**：从原始分布切换到易加权分布后，五个模型的 Recall 提升 14.73–21.15 个百分点、Accuracy 提升 14.20–22.49 个百分点；整体函数调用分数对测试集难度组成高度敏感。
2. **难样本是普遍瓶颈**：所有模型 Recall 从 Easy（74.5%–93.9%）到 Medium（31.5%–65.3%）到 Hard（2.8%–10.8%）单调骤降；最强模型 Claude Opus 4.6 在 Hard 上也仅 10.8%。
3. **聚合分数掩盖不同失败模式**：GPT-5.4 参数错误率最低，但极高的 Miss Recall（33.72%）和 Over Recall（33.20%）拖垮了总分；Claude Opus 4.6 召回最强但拒答能力弱（Over 29.10%）；Gemini 3.1 Pro 错误分布最均衡，Over 最低（18.55%）。不同失败模式可产生相近总分。
4. **时间参数是共同弱点**：Temporal Error 是每个模型占比最大的参数错误类别（7.96%–10.41%），是所有模型族的共性短板。
5. **排名跨基准不稳**：Claude 在 PluginEval 和 BFCL 上第一，Gemini 在 APIBench 和 NexusRaven 上第一；DeepSeek 在 PluginEval 超过 GPT-5.4，却在 APIBench/NexusRaven 上低于它；模型能力评估受基准侧重显著影响。
6. **PluginEval 更具区分度**：比 BFCL 分数更低、Accuracy 跨度更宽（体现对抗负样本和严格参数约束的难度），且四个基准总体表现低于其他以英语为主的基准。
7. **人工审计支持可靠性与 judge 有效性**：参考标注总体验证率 ≥96.33%（Fleiss' κ 0.70）；judge 与三位评审者 Cohen's κ 达 0.9451 / 0.9585 / 0.9221，Miss 和 Over 类别 100% 确认，分歧集中在参数错误。
8. **PCCF 各组件互补且重要**：移除内容验证 FP 率 0%→78%；禁用迭代校准累计通过率 39.7%→11.1%；闭环合成替代单次生成使通过率 64%→27%、覆盖倍数 3.88×→1.38×、难度偏差 0.40→1.16。

## 7. 优点

- **明确路径依赖的方法论**：从"可验证标注→覆盖缺口→行为校准难度"层层递进，逻辑自洽；将"样本可信"与"样本必要"两个常被混淆的问题分离开。
- **可执行验证优于"LLM 判同意"**：schema 校验 + 真实 API 执行 + 结果评估三层信号显著提升标注可信度，失败痕迹被回收用于迭代修复，形成闭环。
- **细粒度错误归因**：gold-anchored judge 把失败分成 miss / over / parameter errors，参数错误进一步细分时间/缺失/值错误，首次在函数调用评测中区分"工具选择错误"和"参数错误"这两类本质不同的失败模式。
- **难度行为化校准**：以参考路由器真实表现定义难度（而非启发式标签），并以"识别证据"强化不合格负样本，机制设计新颖。
- **证据扎实**：人工审计同时覆盖了参考标注质量与 judge 可靠性两个层面，消融和敏感性分析系统考察了框架每个组件的贡献，统计显著性有报告（p < 0.001），并给出最优超参数（R=3, M=3, K≥5）。

- **算力信息缺失**：未报告 GPU 型号、数量、训练/评估耗时，复现成本难以预估。

- **judge 本身为 LLM**：虽然 gold-anchored 设计缓解了标准漂移，但 GPT-5.2 仍可能对特定模型（如 GPT-5.4）存在偏好偏差；论文未做 judge 替换敏感性测试（如换用 Claude 或本地模型）。
- **评估面向单次调用而非完整代理任务**：3,000 例为静态查询-调用对，未覆盖多轮对话、状态依赖、嵌套 API 调用等 agentic 场景，与其对标的 τ-bench、AppWorld 类基准相比交互性较弱。
- **相对性能差异的解释不深入**：报告了跨基准排名变化，但未分析变化的具体原因（如"English vs Chinese gap"或"API 生态差异"），限制了结论的可迁移性。
- **真实性与成本平衡**：使用真实 MCP 执行验证标注，但模型评估时并未真实执行预测调用，而是由 judge 对比预测与黄金标注；这意味着评估只能验证"预测是否等同黄金"而非"预测是否在实际环境中成功"，与 Stage I 的验证逻辑不完全一致。
