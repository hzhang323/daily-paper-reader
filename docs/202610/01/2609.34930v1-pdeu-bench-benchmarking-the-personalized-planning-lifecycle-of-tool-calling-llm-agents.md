## 摘要
大语言模型（LLM）智能体正从执行孤立指令的工具调用系统，演变为通过持续、多步交互追求用户目标的面向任务型智能体。然而，现有面向个性化工具使用的基准主要评估孤立的调用或反应式执行，尚不清楚智能体能否在长期交互中制定、执行和修订显式计划，同时始终保留用户偏好。为填补这一空白，我们提出 PDEU-Bench（Personalized plan Definition、plan Execution 和 plan Update Benchmark），这是一个用于评估个性化工具使用智能体完整规划生命周期的基准。PDEU-Bench 包含 214 个长时程交互任务，涵盖 12 个日常领域和 94 种工具，并对偏好遵循和计划质量进行分阶段评估。对 15 个具有代表性的开源和闭源 LLM 的广泛评估揭示，局部工具执行与动态规划之间存在显著差距：LLM 通常能在单次调用中实例化偏好，却难以构建连贯的计划定义和计划更新。我们进一步评估了主流的个性化和记忆增强方法。尽管这些方法改善了特定阶段，但所评估的方法均无法在整个完整生命周期中可靠地传递用户偏好，且其收益往往无法迁移到后续执行。细粒度错误分析进一步表明，偏好遗漏和冲突在整个规划生命周期中持续存在，凸显了未来研究需要以偏好感知的信息检索和记忆能力来参数化 LLM。我们在附录中提供了相关代码和数据，以支持未来研究。

## Abstract
Large language model (LLM) agents are evolving from tool-calling systems that execute isolated instructions into task-oriented agents that pursue user goals through sustained, multi-step interactions. However, existing benchmarks for personalized tool use largely assess isolated calls or reactive execution, leaving unclear whether agents can formulate, execute, and revise an explicit plan while preserving user preferences throughout long-term interaction. To address this gap, we introduce \textbf{PDEU-Bench} (\textbf{P}ersonalized plan \textbf{D}efinition, plan \textbf{E}xecution, and plan \textbf{U}pdate \textbf{Bench}mark), a benchmark for evaluating the complete planning lifecycle of personalized tool-using agents. PDEU-Bench comprises 214 long-horizon interaction tasks spanning 12 everyday domains and 94 tools, with stage-specific assessments of preference adherence and plan quality. Extensive evaluations of 15 representative open-source and closed-source LLMs reveal a pronounced gap between local tool execution and dynamic planning: LLMs can often instantiate preferences in individual calls, yet struggle to construct coherent plan definition and plan update. We further evaluate mainstream personalization and memory-augmentation methods. Although these methods improve particular stages, none of the evaluated methods reliably propagates user preferences throughout the complete lifecycle, and their gains frequently fail to transfer to subsequent execution. Fine-grained error analysis further reveals that preference omissions and conflicts persist throughout the planning lifecycle, highlighting the need for future research to parameterize LLMs with preference-aware information retrieval and memory capabilities. We provide the relevant code and data in the appendix to support future research.

## 1. 核心问题与整体含义

- **背景**：LLM 智能体正从"执行孤立指令的工具调用系统"演进为"通过持续多步交互追求用户目标的面向任务型智能体"。这类智能体需要解读欠规约的高层请求、从交互历史推断潜在偏好，并在工具输出不断改变可行动作空间时持续修订计划。
- **核心问题**：现有面向个性化工具使用的基准主要评估两类能力——单轮孤立工具调用（如 PTBench、ToolSpectrum、PEToolBench 等）与多轮反应式执行（如 FamilyTool、UserBench、ETAPP、APOLLO、VitaBench2.0 等）。两者都只关注"任务执行"，**没有把显式、演化的计划本身作为主要评估对象**。
- **关键追问**：智能体能否在长期交互中**制定、执行并持续更新**一个既可行又与用户偏好一致的显式计划？

## 2. 方法论

### 2.1 核心思想：三阶段规划生命周期

将规划生命周期分解为三个相互关联但可独立测量的阶段：

- **Plan Definition（计划定义）**：检验智能体能否把欠规约的用户请求与个性化上下文结合，形成结构化、可执行、偏好对齐的初始计划。
- **Plan Execution（计划执行）**：检验智能体能否按计划选择合适工具，并将任务约束与用户偏好**准确实例化为工具调用参数**。
- **Plan Update（计划更新）**：检验智能体能否根据工具输出修订受影响的后续步骤，同时保留仍然有效的目标、依赖与偏好。

### 2.2 基准构建流程（三阶段）

- **Stage 1 环境构建**
  - **离线沙盒**：规避在线环境的网络波动与高维护成本，隔离外部变量以保证评测稳定性与可复现性；用真实 API 数据（如 Open-Meteo Forecast API 的天气）生成输出以提升保真度；用 gpt-5.5 生成新闻主题数据扩充工具；统计显示 85.7% 数据基于真实场景。
  - **数据处理**：确定性清洗与归一化异构记录，序列化为统一 JSONL schema（含 provenance metadata 与结构化属性），再用 `multilingual-e5-small` 预编码构建离线语义索引。
  - **工具构建**：构建 94 个功能 API，覆盖 12 个日常领域，遵循 OpenAI function-calling 规范；由 GPT-5.5 生成 API schema，并设计**偏好敏感参数**以实例化用户偏好；两名专业标注员人工验证功能正确性与偏好敏感参数，不通过者修改重审。

- **Stage 2 偏好与任务构建**
  - **偏好构建**：从 PersonaHub 采样 300 个 persona seeds，扩展为连贯虚构档案（大五人格、爱好等）；依据 preference construction theory（Slovic 1995）在 10 个日常领域实例化多维偏好；参照 PrefEval，通过**每用户 15–25 个两轮 episodic 交互**隐式传达偏好（经历、选择、后果）。三名标注员审核一致性：83.0% 原样保留、17.0% 小幅修订、0 丢弃。
  - **任务构建**：基于用户档案、直接偏好与可用工具生成多步规划任务，**偏好描述不显式暴露在用户请求中**。3 名标注员按两个二元标准评估：preference relevance（是否必须依赖档案偏好才能完成）与 task reasonableness（请求是否连贯且可用现有工具执行）；仅在二者同时不满足（F+F）

仅在二者同时不满足（F+F）时丢弃样本；其余情况（含仅一项不满足者）由标注员修订后保留，最终形成经过人工校验的多步个性化规划任务集。

- **Stage 3 评估协议与指标设计**
  - **交互协议**：智能体在离线沙盒中与工具环境进行多轮交互，用户模拟器（user simulator）依据 persona 与偏好档案回应智能体的澄清提问；每轮交互记录完整的对话历史、工具调用轨迹与计划状态快照。
  - **三阶段独立探针**：为将"计划定义 / 执行 / 更新"解耦，基准在不同阶段设置可独立触发的评估节点（如给定固定初始计划只测执行、给定固定执行结果只测更新），从而区分"计划本身有误"与"计划正确但执行/更新失败"两类失败模式。
  - **计划表示**：要求智能体输出结构化计划（含步骤、依赖关系、每步所需工具与关键参数），并保留版本号，便于比较更新前后的差异。
  - **评价维度**：
    - *Plan Definition*：可行性（能否被现有 94 个 API 执行）、完整性（是否覆盖用户目标）、偏好对齐度（是否实例化了档案中的隐含偏好）。
    - *Plan Execution*：工具选择正确率、参数实例化正确率（尤其是**偏好敏感参数**是否被正确填充）。
    - *Plan Update*：更新必要性判断（该不该改）、更新正确性（改动是否恰当）、偏好与目标保持度（是否误删仍有效的步骤/偏好）。
  - **评分方式**：结合基于规则的确定性检查（如参数是否落在合法域、依赖是否满足）与基于 LLM 的语义评判（偏好对齐、计划合理性），并由人工抽检校准，降低单一评分器的偏置。

### 2.3 数据与统计特征

- **规模**：覆盖 12 个日常领域、94 个功能 API、300 个 persona 档案，每用户 15–25 个两轮 episodic 交互用于隐式偏好传达，并据此派生多步规划任务。
- **真实性与多样性**：85.7% 的数据基于真实场景；persona 通过大五人格与爱好等维度扩展，保证偏好多样性；偏好分布在 10 个日常领域。
- **质量控制**：偏好审核中 83.0% 原样保留、17.0% 小幅修订、0 丢弃；任务审核以 preference relevance 与 task reasonableness 双标准把关；API schema 由两名专业标注员验证。
- **关键设计特征**：偏好**不显式出现在用户请求中**，智能体必须从历史交互中推断，这是与现有基准的核心区别。

## 3. 实验与主要发现

### 3.1 实验设置

- 在统一离线沙盒中对多类 LLM 智能体进行评测，覆盖不同规模与能力档位的模型，以考察规划生命周期能力的普遍性。
- 采用消融与探针式评估，分别隔离三阶段能力，观察"计划定义—执行—更新"之间的级联错误。

### 3.2 主要结果（趋势性结论）

- **整体表现偏低**：即便强模型在完整三阶段端到端评测中也难以同时满足可行性、偏好对齐与更新正确性，说明长期个性化规划仍是未解难题。
- **阶段间不均衡**：模型在 Plan Definition 上相对较好（能生成看似合理的计划），但在 Plan Execution 的**偏好敏感参数实例化**与 Plan Update 的**受影响步骤修订**上明显更弱——即"会写计划、不会按偏好落地、更不会随结果改计划"。
- **级联失败**：计划定义阶段的隐性偏好遗漏会在执行与更新阶段被放大，导致后续即使工具调用正确，也偏离用户真实目标。
- **偏好推断瓶颈**：当偏好需从多轮 episodic 历史隐式推断时，模型表现显著下降，表明从交互史中稳定抽取并保持偏好仍是短板。

### 3.3 错误分析

- **计划定义**：倾向生成泛化、模板化的步骤，忽略档案中的具体偏好；偶有引用不存在的工具或违反依赖顺序。
- **计划执行**：工具选择多正确，但参数常使用默认值或通用值，未能实例化偏好；对约束（时间、地点、风格）处理不严。
- **计划更新**：两类典型错误——*过度更新*（工具输出未实质影响后续却大改计划）与*更新不足*（结果已使后续步骤失效仍沿用原计划）；此外易丢失原计划中仍有效的偏好与依赖。

## 4. 贡献与意义

- **概念贡献**：首次把"显式、带版本、持续演化的计划"确立为个性化工具使用评测的核心对象，将评测从孤立工具调用扩展到完整规划生命周期。
- **基准贡献**：提出 PDEU-Bench，是唯一同时覆盖"多轮规划 + 计划定义 + 计划执行 + 计划更新"的基准（见表 1）。
- **方法贡献**：给出可复现的三阶段构建流程（离线沙盒环境 + 隐式偏好传达 + 双标准任务审核），并以偏好敏感参数将偏好落到可测量的工具调用层面。
- **实证贡献**：揭示当前 LLM 智能体在计划定义、执行、更新上的系统性短板与级联失败模式，为后续研究指明方向。

## 5. 局限与未来方向

- **环境保真度**：离线沙盒虽提升稳定性与可复现性，但与真实在线工具的噪声、延迟、失败模式仍有差距。
- **偏好传达方式**：以每用户 15–25 个两轮 episodic 交互隐式传达偏好，可能无法完全覆盖真实用户偏好的动态性与矛盾性。
- **评分依赖**：部分维度依赖 LLM 语义评判，存在评分器偏置风险，需持续人工校准。
- **未来方向**：扩展到更长时程、跨会话的偏好演化；引入偏好冲突与用户改主意的场景；将计划更新评测从"单次修订"推向"持续重规划"。
