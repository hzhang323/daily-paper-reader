## 摘要
递归自我改进要求智能体将累积的经验转化为未来更好的行为。个人AI智能体为研究这一能力提供了具体场景，因为它们在会话之间保留偏好、任务历史、工具例程和学习到的技能。然而，保留的经验是否实际上随时间改善了它们尚未被系统测试。我们引入PAST-Bench，一个旨在隔离这个问题的基准。每个智能体在匹配条件下运行有序的新会话任务序列，这些条件可以打开或关闭保留的经验。它涵盖26个场景和204个情节，涉及记忆、程序复用、信息收集和更新。我们报告了后期任务的收益，以及这些收益是否遵循预期的保存、检索和更新路径。在七个基础模型和四个智能体框架中，改进是真实的，但在能力上不均匀。具有相同总体收益的智能体在收益是否得到预期路径证据支持方面可能差异很大。在这些发现的指导下，我们开发了Hermes+，它通过智能体循环各阶段的五项针对性干预扩展了Hermes。Hermes+提高了从保留经验中获得的平均收益，并提供了更清晰的路径证据，其最强的改进出现在需要替换过时状态的任务上，尽管效果仍然依赖于能力和模型。总之，PAST-Bench和Hermes+为研究持久智能体如何从保留经验进步到通过经验系统性改进提供了评估和诊断基础。代码：https://github.com/Gen-Verse/PAST-Bench

## Abstract
Recursive self-improvement requires agents to turn accumulated experience into better future behavior. Personal AI agents offer a concrete setting for studying this capability because they retain preferences, task histories, tool routines, and learned skills across sessions. Yet whether retained experience actually improves them over time has not been systematically tested. We introduce PAST-Bench, a benchmark designed to isolate this question. Each agent runs through ordered sequences of fresh-session tasks under matched conditions that turn retained experience on and off. It spans 26 scenarios and 204 episodes across memory, procedural reuse, information gathering, and update. We report both later-task gains and whether those gains follow the intended save, retrieve, and update pathway. Across seven base models and four agent frameworks, improvement is real but uneven across capabilities. Agents with the same headline gain can differ markedly in whether that gain is supported by evidence of the intended pathway. Guided by these findings, we develop Hermes+, which extends Hermes with five targeted interventions across stages of the agent loop. Hermes+ raises the average gain from retained experience and provides clearer pathway evidence, with its strongest improvement on tasks requiring outdated state to be replaced, although the effect remains capability- and model-dependent. Together, PAST-Bench and Hermes+ provide an evaluation and diagnostic foundation for studying how persistent agents can progress from retaining experience to systematically improving through it. ## 1. 核心问题与研究动机

- 背景：递归自我改进（Recursive Self-Improvement, RSI）要求智能体将自身运行中积累的经验转化为未来能力的提升。个人AI智能体（如 Hermes、OpenClaw 等）在会话间保留偏好、任务历史、工具例程和技能，是研究这一能力的天然场景。
- 关键未解问题：**保留的经验是否真的能改善智能体未来的行为**？现有基准要么只评估单次任务的分数，要么将记忆/技能要素孤立测试，无法区分“后来性能提升”是来自保留经验，还是来自基础模型能力、运行时、提示词捷径、任务难度或评分噪声。
- 论文将这种能力定义为“在线自我进化”（online self-evolution）：智能体在不重训练、不优化提示词、不依赖长上下文的情况下，通过重利用先前交互积累的经验改变未来行为。这是完整 RSI 的行为与基础设施基础，但积累经验并不保证改进，可能存储错误证据、检索无关记忆、复用脆弱流程或应用过时状态。
- 因此需一个**性能归因（performance-attribution）基准**，将模型能力、框架设计、保留经验三个因素分离开来。PAST-Bench 旨在填补这一空白。

## 2. 方法论

### 2.1 核心思想
- 评估单元从“单个任务”变为“任务家族”（task family）：一系列有序的新会话情节，共享一个潜在规则（记忆）、可复用工件（程序复用）、一次修正（更新）或预置参考（信息收集）。且**严格清空上下文**——每个情节都是全新会话，框架的易失性上下文被清空，因此后续任务提升必须经过持久化渠道（记忆库、技能文件、剧本、编辑过的规则）而非残留的提示词重叠。
- 每个任务家族包含四类情节：
  - 冷启动情节（cold）：首次接触，无任何持久化；
  - 学习情节（learn / update）：将目标存入持久化层；
  - 评估情节（evaluation）：在后续新会话中检验是否重用了已存状态（且不明确提示）；
  - 控制情节（control）：无保留、干扰项、过时状态、错误机制等，用于排除捷径、表面记忆、陈旧复用、错误写入通道等混淆解释。
- 匹配消融：每个评估情节在两种条件下运行——`w/o evolve`（禁止访问家族产生的状态）和 `w/ evolve`（允许访问）。两者共享相同提示、评分器、工具栈和随机种子，因此分数差距最可能来自持久化层。

### 2.2 核心指标
- 主指标：自进化差距 \(\Delta_f = S^{w/}_f - S^{w/o}_f\)，其中 \(S_f\) 是家族内评估情节的任务分数均值。能力级 \(\Delta\) 是家族宏平均。
- 任务分数 \(s_e\)：由完成度、鲁棒性、安全性加权组成：\(s_e = \sigma_e \times (0.8 c_e + 0.2 r_e)\)。
- 机制证据分数 Mech：验证智能体是否沿预期路径（写入→检索→正确应用）完成持久化循环，而非仅凭分数提升。Mech 由五个子分数平均：
  - Write precision (wp)：学习情节写入工件质量；
  - Recall accuracy (ra)：使用预期检索信号时内容正确率；
  - Update correctness (uc)：更新情节的陈旧抵抗与内容正确性；
  - Retention horizon (rh)：远距离/近距离评估分数比，衡量持久化在跨领域时的保持能力；
  - Pollution rate (pr)：写入条目中无关或越界比例，越低越好。
  - 即 \(Mech_f = \frac{1}{5}(wp + ra + uc + rh + (1-pr))\)。

### 3.3 Hermes+ 设计
基于诊断出的五类失败提出五项运行时干预，分别作用于代理循环的不同阶段：
- E1 Plan：计划阶段强制咨询已保存状态，防止计划不基于持久化状态；
- E2 Render：记忆以类型化绑定存储，渲染时只暴露当前有效的绑定，隐藏被替代旧值；
- E3 Route：将工作流保存为查询排序的、可修补的技能，避免流程只存在于对话文本中；
- E4 Gate：对依赖先前状态且会产生不可逆动作的任务，在回答前强制检索持久化通道；
- E5 Close：情节收尾时同步将最终修正写入持久化层，覆盖旧值并刷入存储，使下一新会话只读到正确状态。

## 6. 主要结论与发现

1. 自我进化是真实但能力不均匀：所有 7 个基础模型在保留经验下均获得正增益（Overall Δ +0.13～+0.24），但增益分布因模型而异；例如 GPT-5.4 均匀分布于 Memory 和 Update，GLM-5.1 更集中于 Update。
2. 表面相同的 Δ 可能对应非常不同的机制路径：如 Hermes 和 nanobot 都达到 Δ = +0.13，但 Mech 分别为 0.64 与 0.57，说明 nanobot 的增益缺乏完整的写入–读取证据。
3. 不同框架展示出不同的能力聚焦点：ZeroClaw 提升 Memory 但损失 Procedural；Agent-Zero 在四能力中三个退化；Hermes 是唯一四个能力都为正的基线框架。
4. Hermes+ 的效果：
   - 在 MiniMax-M2.7 上，Overall Δ 从 +0.13 提升到 +0.15，Mech 从 0.64 提升到 0.73；
   - 最强增益在 Update：单 E5 机制已达 +0.16，完整 Hermes+ 达 +0.24，具有超加性组合效应；
   - 但 Overall 的 +0.02 提升小于 run-to-run 波动（Δ 标准差：Hermes 0.04，Hermes+ 0.06），因此不能视为稳定总体增益；
   - Hermes+ 在跨模型迁移上并非普遍正效果：在 DeepSeek-V4-Pro 和 Claude Opus 4.6 上有轻微回退，在 GPT-5.4、Claude Sonnet 4.6 上保持或提升。
5. 机制交互存在：表 5 显示去掉 E2（Render）反而提升 Procedural Δ 从 +0.085 到 +0.108，而去掉 E3 或 E5 则显著降低，说明机制并非可随意叠加，需考虑相互作用。
6. 结论：PAST-Bench 和 Hermes+ 为“从保留经验到系统改进”提供评估和诊断基础，但自我进化仍高度依赖于能力和模型。

## 7. 方法论的优点

- 严格的归因设计：配对 w/ 与 w/o 持久化控制，将保留经验的影响从模型/运行时/任务难度中剥离出来。
- 双轴评估：任务分数（行为效果）与机制证据（路径对齐）分离，避免“分数提升但原因错误”的假象。
- 轨迹级诊断：任务家族序列设计，使得跨会话重用的是唯一提升来源；控制情节排除捷径、陈旧状态、表面记忆等混淆。
- 灵活的框架适配：通过适配器可在不同代理框架上迁移协议，且支持模型固定/框架固定两种比较。
- 干预可消融：Hermes+ 的五项机制对应五个独立的循环阶段（Plan/Render/Route/Gate/Close），可以逐机制验证因果关系，并揭示非平凡交互。
- 谨慎的统计报告：给出运行方差，不夸大小幅度均值差异，诚实标注机制的局限。

## 8. 不足与局限

- 生态效度有限：所有 26 个任务家族均为合成构造，且单家族独立运行，未包含人类真实交互数据和跨家族干扰；缺乏长时序、领域迁移的测试。
- 能力覆盖不全：仅覆盖记忆、程序复用、信息收集和更新，未包括更高级的自我改进（如工具策略生成、长期规划、多代理协调、自我修改学习机制）。
- 机制归因仍非因果：Mech 衡量的是“与预期路径的吻合度”，而非因果必要性；未做反事实干预（删除/替换/污染工件后重测）。
- 偶然性与统计差异：Hermes+ 的 Overall +0.02 改进小于 run-to-run 波动，不构成显著提升；Update 的改进虽大但方差也增加。
- Hyperparameter 依赖：Hermes+ 调音于 MiniMax-M2.7，向 DeepSeek-V4-Pro 和 Claude Opus 4.6 迁移时出现回退，说明机制存在模型特定性。
