## 摘要
在越来越多的智能体基准上评估智能体颇具挑战性，因为这些基准通常需要复杂的环境和智能体集成。我们引入了 Harbor Adapters，一个统一的智能体基准评估基础设施。我们的工作有三项贡献。首先，我们开发了基准适配器，将超过 80 个基准移植到任意智能体的评估中，并通过严格的代码审查和一致性实验对其进行了验证。其次，我们对跨越能力层级的 8 个模型在 54 个基准上进行了大规模评估；每个模型均使用 Terminus-2 以及三种原生测试框架之一运行。这使得我们能够比以往更广泛地分析智能体的能力与失败模式。第三，我们引入了 Harbor-Index，这是一个从适配套件中通过难度过滤、AI 与人工审计以及审计-修复循环提炼出的精选集合，包含 29 个基准中的 82 个困难、多样且高质量的任务。Harbor-Index 在保持大规模智能体评估的挑战性与广度的同时，运行成本可控；所有评估的模型-测试框架配置均未超过 30% 的通过率，最强的配置（GPT-5.5 与 Codex）达到了 28.0%。我们开源了适配器、评估结果、深入分析以及 Harbor-Index，以支持对语言模型智能体进行更可靠和全面的评估。

## Abstract
Evaluating agents on the growing number of agentic benchmarks is challenging because they often require complex environments and agent integrations. We introduce Harbor Adapters, a unified evaluation infrastructure for agentic benchmarks. Our work makes three contributions. First, we develop benchmark adapters that port more than 80 benchmarks to evaluate arbitrary agents, and validate them through rigorous code review and parity experiments. Second, we conduct a large-scale evaluation of 8 models spanning capability tiers across 54 benchmarks; every model is run with Terminus-2 and with one of 3 native harnesses. This enables a broader analysis of agent capabilities and failure modes than was previously possible. Third, we introduce Harbor-Index, a curated set of 82 difficult, diverse, and high-quality tasks spanning 29 benchmarks, refined from the adapted suite through difficulty filtering, AI and human audit, and an audit-and-fix loop. Harbor-Index preserves the challenge and breadth of large-scale agentic evaluations while being affordable to run; no evaluated model-harness configuration exceeds 30% pass rate, and the strongest (GPT-5.5 with Codex) reaches 28.0%. We release the adapters, evaluation results, in-depth analysis, and Harbor-Index as open-source artifacts to support more reliable and comprehensive evaluation of language-model agents.

## 2. 论文提出的方法论：核心思想、关键技术细节与算法流程

### 2.1 Harbor Adapters（统一智能体评估基础设施）

- **核心思想**：将异构的基准格式翻译为 Harbor 的统—任务模式：**instruction（指令）、environment（环境）、tests（测试）和 solution（解决方案）**。这一抽象将智能体执行与基准特定的逻辑解耦。
- **技术细节**：
  - 每个基准只需一个适配器暴露其任务、环境和评分逻辑；每个智能体只需一次 Harbor 集成，集成复杂度即从 O(m×n) 降为 O(m+n)。
  - 适配器基础设施支持 GPU 交互、LLM-as-a-judge 验证器、自定义指标聚合、多沙箱后端（Daytona、Modal、E2B）。
  - 截至 2026 年 5 月，Harbor Adapters 支持 22 个智能体和 80 多个基准。
- **一致性验证（Parity Experiment）**：在相同的智能体、模型、工具集、提示模板、解码参数和执行配置下，将 Harbor 适配版本与原始基准对比。每组至少运行 3 次（k=3）以刻画随机性，报告均值 ± 标准误（SEM）。通过标准为两侧均值在标准误允许范围内一致。
- **三类集成场景**：
  - 场景 1（Harbor 原生智能体）：原始基准已使用 Harbor 支持的智能体，仅需对齐版本与配置；
  - 场景 2（Vanilla LLM）：在原始仓库中添加 Harbor 支持的 CLI 智能体，两侧对称修改；
  - 场景 3（自定义智能体）：将基准自带的自定义智能体移植进 Harbor，或同时维护原始智能体版与 CLI 智能体版。

### 2.2 Harbor-Index 构造流程（多阶段漏斗过滤）

1. **难度过滤**：从 6,627 个初始任务中保留在最严苛 18 次试验（3 个前沿模型 × 各自原生 harness 和 Terminus-2 × 3 次重复）中成功率 ≤33% 的 1,311 个任务。
2. **AI 审计**：用 Gemini-3-Flash 审计器对候选任务按质量规则评分（指令-验证一致性、难度是否源于真正的推理/算法/领域知识/长周期交互等），过滤到 307 个任务。
3. **人工复审计**：14 位领域经验审核者使用同一套规则，每位候选者至少得到 1 次资深审核或 2 次初级审核，剩余 110+ 个任务。
4. **资深小组评审**：3 位资深成员基于难度、多样性和洞见选出 100 个任务。
5. **审计-修复循环**：≥2 位资深评审检查轨迹级失败分析及假阳性/假阴性分析，修复可修复的任务并删除仍损坏或修复后过易的任务，最终得到 **82 个任务、涵盖 29 个基准**。
- **发现**：在 30+ 个基准中约三分之一的"最难"候选任务因结构性缺陷被拒绝而非真正的难——例如 GAIA2 的模拟事件从未触发、SWE-bench Pro 的验证器断言了指令从未规定的细节、CRUST-Bench 强制使用固定手写 Rust 接口导致正当的安全解法被拒。

## 6. 论文的主要结论与发现

1. **评测空间低秩性**：54 个基准的主成分分析显示，绝大部分变异由单一"通用能力"轴解释（PC1 在固定 harness 下 73.7%、混合 harness 下 67.1%），第二个轴（harness 效应）加入后仍为低秩。在 54 个基准中选择约 12 个核心基准即可覆盖大多数独立排名信号。
2. **基准有饱和趋势**：在已评的 54 个基准中，13 个基本饱和（SOTA 超过 90%），包括曾经的难题 GPQA-Diamond；软件工程的函数级与竞赛代码任务近饱和，而仓库级功能实现和软件性能优化（GSO）仍保持高难度。
3. **模型能力 > harness 设计**：在控制基准难度后（LMM 随机截距模型），6/8 的模型系数显著（p<0.05），而 4 个 harness 中仅 2 个显著；模型固定效应的全距（0.451）是 harness（0.087）的 5.2 倍。
4. **前沿模型在效率-成本权衡中具有特色格局**：前沿模型在中等难度任务（0.3-0.7）的增量收益最大（钟形曲线），在最难和最简单的任务上边际收益都小；且前沿模型在各难度层级消耗的 token 更少（最易桶中仅弱模型的 42%），但更低的 token 消耗并没有抵消更高的单价——弱模型每次试验仍便宜 2-3 倍，成本差距峰值在 0.7-0.8 难度桶为每次试验 $0.37。
5. **失败模式中能力缺口和任务缺陷并存**：各模型的主要失败模式是"错误事实答案""算法缺陷"和"隐藏测试回归"；但大量低解决率实际上源于任务设计缺陷（如指令-验证不匹配、游戏化的测试、环境缺陷），而不是真正的难度。GPT-5.4 偏向简洁（要么快速正确要么放弃），Claude 各模型保持稳定的 token 数分布，Gemini 依赖外部搜索且出现"信息漂移"。
6. **Harbor-Index 的挑战性**：在 Harbor-Index 上没有任何模型-harness 配置超过 30% 的通过率；最强配置（GPT-5.5+Codex）达到 28.0%，未来仍有较大提升空间。

## 7. 优点：方法与实验设计的亮点

1. **基础设施贡献突出**：将集成复杂度从 O(mn) 降为 O(m+n)，并为此构建一套可复用的开源组件，极大降低了后续大规模智能体评测的进入门槛。
2. **严格质量保障体系**：全部 80+ 适配器均经历了 bot 审核、初级人工、资深人工的三级审计，并通过多轮 parity 实验验证；文中还明确并处理了 oracle 失败、非确定性评分和"代理破解面"等陷阱。
3. **大规模量化分析框架**：综合利用 PCA/SVD、Spearman 相关贪心选择、线性混合模型、失败分类注释和校准 LLM 评判等多元方法，对"模型 vs. harness 谁更关键"这类问题给出统计量支撑的结论。
4. **精心设计的 meta-数据集**：Harbor-Index 通过多阶段（难度过滤 → AI 审计 → 人工审计 → 修复循环）筛选，确保选出的任务是高难度、高多样性与高质量的结合，避免了简单复制基准冗余的陷阱。
5. **全程开源与可复现性**：适配器代码、评测工具、全部 0.3M 条轨迹、结果数据库和交互式网站（harbor-index.org）一并开源，最大化透明度和社区可持续利用价值。
6. **关注成本-性能均衡**：明确记录 token、美元成本和延迟统计，给出模型选择与评估预算的实操参考；对连续指标使用"SOTA 阈值化"设计避免评测虚高。
7. **多维公平性设计**：在适配器上执行 oracle 100% 通过率要求、原始版 vs Harbor 版 parity、三阶段 bot+初级+资深评审，考虑同模型/同 harness 对照条件并报告 SEM。

## 8. 不足与局限：实验覆盖、偏差风险与应用限制

1. **覆盖范围受限于计算成本**：只实际评测了 54 个适配器基准中的一部分（已集成 93 个），且每个模型仅有 2 个 harness 条件；结论并不涵盖所有 LLM、智能体架构与评估设置。
2. **任务抽样的 i.i.d. 假设与低采样率风险**：若原基准包含大量任务（如 SWE-smith 原始 59,136 个，仅采样 98 个），则选出的子集难以完全代表全局任务分布；某些任务虽在验证集中容易通过，但困难长尾可能出现偏差。
3. **模型版本不稳定与污染风险**：gemini-3.1-pro-preview 等属于预览/别名端点而非冻结快照，运行时间（2026 年 4 月）与论文截稿之间存在模型漂移；未来更强的 agent 可能利用基准 artifact 或评测漏洞实现当前不可探测的奖励设计利用，使评测可靠性下降。
4. **LLM-as-a-judge 偏差**：论文广泛使用 LLM 评判（如 HLE、GAIA、GPQA、SimpleQA），尽管综合了多家模型与多次重复，仍存在评分偏差、方差与系统性错误的风险。
5. **任务质量审计不均衡**：人工审计流程描述为"工程化策展流程"而非固定 panel 注释研究，不同任务评审量存在变化，未给出统一的逐任务逐一审计覆盖清单。
6. **实验与成本曲线推理以特定上下文为准**：token 效率结论基于三家公司默认配置（温度、reasoning effort）下的行为，与公共排行榜上"extra-high reasoning effort"等设定不同，直接对比需谨慎；成本以官方 API 与 OpenRouter 定价重构，受缓存命中率影响。
7. **Harbor-Index 的通用性有限**：作为一个轻量子集（82 任务），它并不替代全量评测；对需要细粒度能力画像的研究，低秩的分数矩阵可能造成"排名正确但细节丢失"的困境。
