## 摘要
基于大型语言模型的多智能体系统正从固定交互拓扑向动态编排的智能体集群（Agent Swarms）演变。然而，现有基准测试仍主要基于单智能体或通用智能体任务，难以系统评估关键的编排能力。我们提出了SwarmBench，一个从准确性、效率、成本和过程质量等多个角度评估模型性能的基准测试。实验结果表明，当前模型在编排能力上表现出显著差异。这些差异不仅体现在最终准确性、效率和成本上，还体现在编排过程本身的整体质量上。基于这些发现，我们进一步提出了SwarmExp，一种基于经验提取和经验回放的简单而有效的方法，能够持续提升大型语言模型的编排性能。

## Abstract
Large language model-based multi-agent systems are evolving from fixed interaction topologies toward dynamically orchestrated Agent Swarms. However, existing benchmarks are still largely based on single-agent or general-purpose agent tasks, making it difficult to systematically evaluate key orchestration capabilities. We propose SwarmBench, a benchmark that evaluates model performance from multiple perspectives, including accuracy, efficiency, cost, and process quality. Experimental results show that current models exhibit substantial differences in orchestration capability. These differences are reflected not only in final accuracy, efficiency, and cost, but also in the overall quality of the orchestration process itself. Based on these findings, we further propose SwarmExp, a simple yet effective method based on experience extraction and experience replay, which consistently improves the orchestration performance of large language models.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究背景**：LLM 多智能体系统正从早期基于预定义角色与通信结构的固定协作范式（如辩论、SOP 流水线、经理-员工协作）向动态编排的 Agent Swarm 范式演进。在 Agent Swarm 中，一个主智能体（orchestrator）需要动态地分解任务、创建子智能体、协调并行执行，并整合子智能体的产出。
- **核心问题**：现有评估体系存在两个主要不足，无法有效支撑这一新兴范式：
  1. 许多 MAS 研究仍在沿用为单智能体或通用智能体设计的基准测试（如 GAIA、SWE-Bench、Terminal-Bench），这些基准无法系统性地暴露 Agent Swarm 所需的关键能力（如动态任务分解、子智能体配置与委派、并行协作与结果整合）。
  2. 即便是面向多智能体协作的任务，已有评估也主要关注最终答案的正确性，而忽视了编排过程本身的质量（如任务分解是否合理、子智能体创建是否有效、结果聚合是否完整）。
- **论文主张**：需要专门针对 Agent Swarm 编排能力设计的基准，从学术上系统回答“大语言模型能否充当智能体集群的有效编排者”这一核心问题，并以此为基础探索提升编排能力的方法。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### SwarmBench 基准设计
- **Agent Swarm 的形式化定义**：定义为一个层级式系统 `S(x) = ⟨o, H, Πo, Πh, U, B⟩`，其中：o 为编排者，H 为可配置的子智能体集合，Πo 为编排策略，Πh 为子智能体执行策略，U 为工具集合，B 为执行预算（步数、智能体数量、延迟或成本约束）。
- **三个核心特性**：
  - 层级编排：单一编排者负责规划、子智能体创建、协调与最终整合。
  - 动态异质子智能体实例化：运行时根据需求创建不同角色、不同骨干模型、不同工具集与独立上下文的子智能体。
  - 并行子智能体执行：多个子智能体可并发执行不同子任务后回报结果。
- **编排动作空间**：编排者在每个全局步骤中根据当前状态输出编排动作；其中"创建智能体"动作需指定子智能体配置 `ϕi = (ri, mi, τi, ci)`，分别对应角色描述、骨干模型、工具集和局部上下文/子任务提示。
- **三类核心能力与任务分类**：将任务分为分解导向（Decomposition-Oriented）、委派导向（Delegation-Oriented）、聚合导向（Aggregation-Oriented）三类。

### 评估框架（多维指标）
- **准确性（Accuracy）**：各任务采用任务专用的标准评估指标。
- **效率（Efficiency）**：提出两个指标——
  - 并行度（Parallelism Rate）：`ρ = Σ(nk·Δtk) / ΣΔtk`，即执行时间内并发运行的子智能体数量的时长加权平均值。
  - 并行增益（Parallelism Gain）：`Gain = (Tmodel + Ttool) / Twall`，即累积的串行模型/工具调用延迟与实际端到端耗时的比值。
- **成本（Cost）**：按各模型输入/输出 token 单价折算为实际美元成本。
- **过程质量（Process Quality）**：使用 LLM 作为评判者，沿任务分解（Decomp.）、子智能体委派（Del.）、结果聚合（Agg.）三个维度对主智能体的编排轨迹打分（0–100）。

### SwarmExp 方法论
- **核心思想**：编排能力可以通过从执行轨迹中提取可复用经验来增强。这是一个两阶段的简单管线：
  1. **轨迹生成**：在基础 Agent Swarm 框架上运行推理，收集完整轨迹。
  2. **经验总结**：从轨迹中提取三种类型的可复用知识——
  - **Skill（技能）**：经由 LLM 聚类轨迹中提炼出的高层工作流模式，组织成 SKILL.md 文件，内容涵盖元数据、工作流模板、示例和注意事项。
  - **Trick（技巧）**：细粒度的可操作经验，通常表达为"条件 → 动作"的快捷建议，存入技巧库。
  - **Model Card（模型卡）**：对子智能体骨干模型在实际任务中表现的经验型画像，涵盖总体质量、适用场景和优劣势。
  3. **经验回放**：推理时，将三类经验注入主智能体的上下文中，用于指导任务规划、子智能体委派与结果聚合。
- **与基线比较**：对比 Single-Agent、Best-of-N、Multi-Model Voting、AOrchestra。

## 3. 实验设计

### 数据集与任务
- **总计**：8 个任务 × 50 个样本 = 400 个样本，数据来源详见表 5。
- **分解类任务**：
  - **MATH**：基于 Omni-MATH，选取难度大于 7 的样本，要求模型将复杂数学问题分解为可验证的中间步骤。
  - **Batch Download（BD）**：完全新构造的合成环境，模拟网页文件批量化下载，平均每样本需下载 11.44 个文件，包含大量干扰文件（重复件、草稿、镜像等）。评估基于工作区最终文件系统的规则匹配（下载 F1）。
  - **Multi-Text Understanding（MTU）**：基于 Loong，平均上下文长度超过 200K，每个样本涉及超过 24 篇文档。
- **委派类任务**：
  - **Multi-Perspective Analysis（MPA）**：基于 DeepReview，系统须创建不同视角（新颖性、有效性、完整性、Bug 检查等）的子智能体协同生成评审意见。
  - **Root Cause Analysis（RCA）**：基于 OpenRCA，需要从日志、指标、追踪等多源证据推断软件故障根因。
  - **Treasure Hunt（TH）**：新构造的交互式寻宝任务（9×9 栅格地图、迷雾遮蔽、多种钥匙和宝箱），主智能体需动态创建侦察者（scout）和搬运者（carrier）两类角色，并持续监控全局状态与重规划。评估基于最终环境状态（成功送回基地的宝箱价值归一化分数）。
- **聚合类任务**：
  - **Long-Text Generation（LTG）**：基于 LongInOutBench，子智能体分别撰写论文章节摘要/画像，主智能体将其整合为一篇连贯的长文综述。评估涵盖事实一致性、写作质量和长度控制。
  - **Wide Search（WS）**：基于 WideSearch，子智能体经由真实网页搜索检索信息，主智能体整理聚合信息，最终输出表格。评估使用官方的 item-level F1。

## 6. 论文的主要结论与发现

- **性能差异显著**：GPT-5.4 是最强且最均衡的编排者，在 8 个任务中的 6 个取得最佳；Claude-Sonnet-4-6 紧随其后；闭源模型整体优于开源模型（开源中 Qwen3.5-397b-a17b、Deepseek-v3.2、GLM-5.1 各有专长但覆盖面有限）。单智能体基线在所有任务上全面落后于编排方法。
- **成本与性能并非简单线性关系**：任务层面，更高成本并不总是带来更好性能（MPA、LTG、MTU、RCA、WS 均存在"低成本即近最优"的情况）；模型层面，更强的编排者可凭借更高效的分解/委派/聚合，以更低成本取得更好性能。
- **并行数量 ≠ 并行效率**：并行增益取决于编排结构有效性（减少冗余等待、避免重复执行），而非并发子智能体的数量。
- **不同任务暴露不同的编排瓶颈**：分解类任务（以 MATH 最甚）主要卡在任务分解上；委派类任务（MPA、RCA、TH）最难的是角色构建与模型/子任务委派；聚合类任务（LTG、WS）最大的瓶颈是结果聚合。聚合维度（Agg.）是绝大多数模型整体得分最低、最不稳定的能力——当前模型更擅长发起和分派子任务，却不擅长整合多个本地结果形成连贯问答。
- **SwarmExp 有效且经验可迁移**：在 MTU、RCA、LTG、WS 上分别提升 +0.25、+6.42、+6.46、+2.92；四个目标模型中 14/16 的设置从跨模型经验注入中获益；三类经验均有贡献，其中 Model Card（子智能体模型能力知识）的消融损失最大，表明编排中对子模型能力的认知最为关键。

## 7. 优点

- **填补评测空白，选题新颖**：首次专门面向 Agent Swarm 动态编排范式设计基准，区别于通用 agent 或静态多智能体基准，评测视角定位清楚。
- **多维评估框架较全面**：同时覆盖准确率、成本、并行效率与过程质量四个维度，不仅回答“做得好不好”，还解析“为什么好/不好”。
- **任务设计层次清晰**：基于三类核心编排能力的任务分类提供了清晰的能力剖析结构，该分类在过程质量评分中得到验证。
- **过程质量分析机制较精细**：通过 LLM 评判对分解/委派/聚合分别打分，并做了与人类标注的相关性验证（0.68–0.80），提升了过程评估的可信度。
- **新数据任务的规则评估**：Batch Download 与 Treasure Hunt 基于可验证的最终环境状态而非自由文本判断（如文件校验和、地图最终状态），降低了评估的主观偏差。
- **并行指标设计有洞察力**：将"并行度"与"并行增益"分离，有效揭示了并行执行结构性收益的关键区别。
- **SwarmExp 的设计有实用价值且可迁移性考量充分**：经验分三类（技能/技巧/模型卡）粒度分明；在跨模型迁移上做了系统实验，并包含消融与跨任务泛化分析。
- **限制被明确讨论**：论文在 Limitations and Ethics 中坦承任务覆盖范围有限、统一框架与固定模型池可能限制一般化、LLM 评判存在偏差风险等，学术态度较客观。

## 8. 不足与局限

- **任务规模较小**：仅 8 个任务 × 50 样本，相对于 Agent Swarm 广阔的潜在场景而言覆盖仍显有限。MAP 等任务的多样性受原始数据集（如 MATH 的竞赛题、DeepReview 的论文）限制。
- **未披露推理细节与算力资源**：论文没有说明模型推理温度、随机种子、API 版本稳定性等运行参数，也未报告 GPU 需求与总计算开销，影响实验可复现性与算力成本评估。
- **统一的框架可能掩盖系统适配差异**：所有模型使用同一套轻量级 swarm scaffold（固定工具接口、固定输出格式）。有些模型未经过 Agent Swarm 场景的指令微调，可能系统性低估其在适配良好的系统中的真实能力。
- **固定子模型池引入耦合偏差**：编排模型中有些同时也是子智能体池中的候选模型（如 Claude-Haiku-4-5），这可能对公平对比造成混淆。此外，模型池中的模型选择与描述方式也影响编排者的选择能力。
- **LLM 评判仍有偏差风险**：虽然相关性验证达到较好值，但 LLM 作为过程质量评判者的系统性偏好（如对特定措辞、特定模型风格的偏移）无法完全排除，且二次抽样规模有限（50 条轨迹/任务）。
- **SwarmExp 实验覆盖有限**：
  - 仅以 4 个任务和单一主智能体（GPT-5.4）进行正式报告，缺乏在全部 8 个任务上的验证。
  - 跨任务迁移效果不稳定：WS 只能从 WS 自身的经验获益，跨域经验有时反而有害，说明经验的一般化尚受制于任务特异性。
  - MTU 上的提升极微弱（+0.25），提示 SwarmExp 对超长上下文、强分解需求场景仍乏力。
- **经验提炼的质量过滤器细节不足**：论文未描述如何对 Skill/Trick 候选进行质量筛选和去重，也未提供提炼成本与稳定性的定量分析，复现存在障碍。
- **结果可能存在时点与生命周期限制**：所有实验依赖 2026 年年中的模型版本/API，快速迭代的 LLM 可能较快使结论过时。
