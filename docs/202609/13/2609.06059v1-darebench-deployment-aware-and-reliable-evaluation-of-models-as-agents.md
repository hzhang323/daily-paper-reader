## 摘要
随着大语言模型从问答系统演变为通用智能体，评估必须超越静态答案正确性，转而评估多模态感知、多步执行、工具使用和产物交付。然而，现有基准往往与特定任务类型、执行环境或评分协议绑定，限制了其可比性、可解释性以及用于部署决策的可靠性。我们提出 DAREBench（Deployment-Aware and Reliable Evaluation of Models as Agents，面向部署且可靠的模型即智能体评估），一个旨在捕捉工作负载变化并支持可靠智能体评估的基准。DAREBench 构建在共享的 OpenClaw 执行环境之上，将选自 22 个源基准并经过适配的 233 个任务组织成由输入模态和执行形式定义的 2×3 工作负载矩阵，并在统一的基于契约的协议下进行评估，同时进行基于证据的评分审计。我们评估了 23 个商业 API 模型和 12 个本地部署的开放权重模型，覆盖 7,587 次模型-任务运行，报告准确率和 token 消耗，并给出 API 模型的参考成本。结果表明，没有单一模型在所有工作负载组中占据主导地位，文本和多模态任务表现出不同的准确率-成本权衡，本地开放权重模型在若干组中具有竞争力，但总体上仍落后于前沿商业模型。这些发现表明，智能体部署和模型选择应考虑工作负载特征、部署模式以及准确率-成本权衡，而不是依赖单一聚合分数。

## Abstract
As large language models evolve from question-answering systems into general-purpose agents, evaluation must move beyond static answer correctness to assess multimodal perception, multi-step execution, tool use, and artifact delivery. However, existing benchmarks are often tied to specific task types, execution environments, or scoring protocols, limiting their comparability, interpretability, and reliability for deployment decisions. We introduce DAREBench (Deployment-Aware and Reliable Evaluation of Models as Agents), a benchmark designed to capture workload variation and support reliable agent evaluation. Built on a shared OpenClaw execution environment, DAREBench organizes 233 tasks selected and adapted from 22 source benchmarks into a $2\times3$ workload matrix defined by input modality and execution form, and evaluates them under a unified contract-based protocol with evidence-based score auditing. We evaluate 23 commercial API models and 12 locally deployed open-weight models over 7,587 model--task runs, reporting accuracy and token consumption alongside reference costs for API models. Results show that no single model dominates all workload groups, text and multimodal tasks exhibit distinct accuracy--cost trade-offs, and local open-weight models are competitive in several groups but still trail frontier commercial models overall. These findings suggest that agent deployment and model selection should consider workload profiles, deployment mode, and accuracy--cost trade-offs rather than rely on a single aggregate score.

## 一、核心问题与研究动机

- **背景转变**：大语言模型正从静态问答系统演变为通用智能体的核心决策组件，智能体需要感知、推理、规划、调用工具并在动态工作空间中交付产物，而非仅生成答案字符串。因此评估范式必须从"静态输入-输出正确性"转向"在工具、上下文、时间与成本约束下的端到端执行"。
- **现有基准的三重局限**：
  - **不可解释**：智能体任务在输入模态、执行流程、工具依赖上差异巨大，单一聚合分数会掩盖模型在不同工作负载下的强弱。
  - **不可归因**：任务依赖不同的智能体框架、工具接口与执行协议时，观测到的差异混淆了"模型能力"与"运行时兼容性"。
  - **不可信**：开放式智能体任务涉及多步操作与产物交付，仅匹配最终文本无法验证任务是否真正完成；LLM 评判器可能在工具未执行、任务超时、必需产物缺失时错误给出正分。
- **核心主张**：智能体评估要服务于部署决策，必须同时解决"结果可解释、比较可归因、分数可信"三个问题，而非单纯扩大基准规模。

## 二、方法论

### 2.1 核心思想

- 构建 **DAREBench**（Deployment-Aware and Reliable Evaluation of Models as Agents），统一**工作负载组织、执行环境控制、结果验证**三要素。
- 四大组件：①工作负载构建；②共享智能体执行环境；③可靠评分；④面向部署的度量。

### 2.2 任务形式化定义

- 每个任务形式化为元组：**τ_i = (p_i, W⁰_i, T_i, C_i, G_i, t_max_i)**，分别为指令、初始工作空间、可用工具集、产物契约、任务专属评分器、执行时间预算。
- **产物契约**：C_i = {(a_{i,j}, φ_{i,j})}，其中 a 为要求的输出路径，φ 为有效性谓词（file bytes → {0,1}）。
- **契约满足度**：Sat(W*, C_i) = ∏_j 1[∃W*[a_{i,j}]] · φ_{i,j}(W*[a_{i,j}])，即所有路径存在且谓词通过才视为完整满足。

### 2.3 任务构建（三阶段筛选）

1. **可行性过滤**：剔除无法定义显式产物契约 C_i 或可靠评分器 G_i 的任务。
2. **难度过滤**：单步任务用 Qwen3.5-27B 跑三次，全对者删除；有源难度标注时只保留 medium/hard。
3. **代表性过滤**：按各源基准的类别结构人工挑选，保持覆盖广度、避免单一类别过度代表。
- 最终从 **22 个公开基准**得到 **233 个任务**。

### 2.4 工作负载矩阵（2×3）

- 模态维度 M = {text, multimodal}；执行形式维度 K = {single-step, multi-step, multi-step+tools}。
- 笛卡尔积 G = M × K 得到六组：Text-SS、Text-MS、Text-MT、MM-SS、MM-MS、MM-MT，组内任务数分别为 20/87/55/20/26/25。
- 通过确定性映射 φ: B → G 将每个源基准按其主导模态与所需执行形式归入单一组，任务继承组标签 g_i = φ(b(i))。

### 2.5 评分协议

- 每个任务在构建时被指定一种评分模式 η_i ∈ {auto, judge, hybrid}：
  - **自动评分**：规则化验证产物存在性与内容一致性；多步任务对可独立验证的中间状态与最终输出按操作重要性加权。
  - **LLM 评分**：固定评判模型接收任务提示、轨迹摘要、最终产物与人工 rubric，返回结构化分项分数后按权重聚合。
  - **混合评分**：w_auto + w_judge = 1，任务分数 s_{m,i} = w_auto·s_auto + w_judge·s_judge。
- 所有任务分数归一化到 [0,1]。

### 2.6 基于证据的审计（核心创新）

- 试点实验发现"**无支撑正分**"（unsupported positive judgments）：空输出得非零分、无实质操作的执行、缺失必需产物仍得分等。
- **流程**：对所有含 judge 的分数先施加确定性后置规则做高召回预筛选；命中触发条件的案例交由来自**不同模型家族**的 meta-judge 复核，输入包含完整提示、执行轨迹、最终产物、评分 rubric、原始分数与理由。
- **审计公式**：s_audit_{m,i} = (1 − h_{m,i}) · s_{m,i}，h_{m,i} ∈ {0,1} 表示原分被确认无支撑。未标记或经 meta-judge 维持的案例 h=0。
- 识别出的五类幻觉模式：**rubric leakage**（评判器把 rubric 内嵌的答案当作智能体输出）、**deadlock loop**（反复循环等价推理耗尽上下文）、**pseudo-tool-call credulity**（模型输出工具样式的文本而非可执行调用）、**output instability**（不完整/畸形输出）、**timeout-with-credit**（超时轨迹仍得分）。

### 2.7 度量与效率核算

- 准确率：Acc(m) = (1/|I_m|) Σ s_audit，并报告六组分组准确率 Acc_g(m)。
- Token 用量：按 in/out/cache-read/cache-write 四类 token 计数求和。
- 成本：Cost(m) = (1/|I_m|) Σ (1/10⁶) Σ_k α^m_k · u^m_{k,i}，α 取模型专属 OpenRouter 参考费率；无独立缓存费率的按输入价计。本地模型仅用托管推理价作第三方参考，帕累托分析基于 API 参考成本。

## 六、主要结论与发现

- **无单一模型通吃所有工作负载**：Claude-Opus-4.8 在 Text-SS（98.8）、Text-MT（65.3）、MM-MT（61.8）最强；GPT-5.5 在 Text-MS（83.6）、MM-SS（90.0）最强；Gemini-3.1-Pro 在 MM-MS（88.5）最强。模型选型应由目标工作负载特征驱动。
- **本地开源模型有竞争力但仍有明显差距**：最强本地模型 Qwen3.6-27B（Overall 59.8）接近部分早期商业模型，但距前沿商业模型仍有约 **15 个百分点**差距；Qwen3.6-35B-A3B（Overall 56.6）是可选的 MoE 替代；8B/9B 小模型在完整智能体循环中明显不稳定。
- **token 消耗与 USD 成本形成两条解耦的极值链**：GPT-5.4-mini token 最少，Gemini-3.5-Flash 最多（文本 456k、多模态 490k，约为前者的 6–8 倍）；但换算成美元后排序剧变——MiMo-V2.5 文本最便宜（$0.006），MiMo-V2-Omni 多模态最便宜（$0.003），Claude-Sonnet-4.6 文本最贵（$0.436），Claude-Opus-4.6 多模态最贵（$0.293）。MiMo-V2.5 token 用量高（276k）却成本极低（$0.005），Claude-Opus-4.6 token 更少（231k）但成本约为其 71 倍。
- **文本与多模态的准确率-成本前沿形态不同**：文本帕累托前沿为 MiMo-V2.5 → MiMo-V2.5-Pro → GPT-5.5，$0.02 以下已接近饱和（成本翻倍仅换 0.5 个百分点）；多模态前沿斜率更陡（MiMo-V2-Omni → MiMo-V2.5 → GPT-5.4 → Gemini-3.1-Pro → Claude-Opus-4.8），性能增益明显更显著。
