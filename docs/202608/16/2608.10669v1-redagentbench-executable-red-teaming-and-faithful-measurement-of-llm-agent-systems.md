## 摘要
大型语言模型（LLM）智能体将基于语言的推理与外部工具相结合，以执行复杂任务。对抗性输入可以利用智能体与其环境之间的交互，导致智能体在执行过程中违反安全策略。然而，现有评估往往将智能体安全性简化为单一的攻击成功率（ASR），将暴露、执行、观察和裁决混为一谈，并可能将实际违规与证据可见性混淆。我们引入了REDAgentBench，一个用于自主红队测试和忠实测量的可执行框架。它从明确的安全约束和相关的智能体系统漏洞中推导攻击，在隔离的服务沙箱中运行这些攻击，并根据服务收据和最终状态变化验证有害影响。该基准涵盖五个服务表面的1,661个案例。在六个模型和三个智能体框架中，宏观平均ASR为65.69%；报告的ASR随框架和证据视图而变化，而评估上下文的披露会改变执行行为。在一个以状态为基准的诊断队列中，将近五分之一的已确认违规（具有解析的动作锚点）发生在智能体陈述相关约束或风险之后，揭示了“识别-执行缺口”。最后，一种无需训练的策略提醒在匹配回放中将已确认违规减少了超过70个百分点。这些发现表明，可执行评估可以改善安全性测量并识别可操作的干预点。

## Abstract
Large language model (LLM) agents combine language-based reasoning with external tools to perform complex tasks. Adversarial inputs can exploit interactions between the agent and its environment, causing the agent to violate safety policies during execution. Yet existing evaluations often reduce agent safety to a single attack success rate (ASR), collapsing exposure, execution, observation, and adjudication and potentially conflating actual violations with evidence visibility. We introduce REDAgentBench, an executable framework for autonomous red-teaming and faithful measurement. It derives attacks from explicit safety constraints and associated agent-system vulnerabilities, runs them in isolated service sandboxes, and verifies harmful effects from service receipts and final-state changes. The benchmark contains 1,661 cases across five service surfaces. Across six models and three agent harnesses, macro-average ASR is 65.69%; reported ASR varies with harness and evidence view, while evaluation-context disclosure changes execution behavior. In a state-grounded diagnostic cohort, almost one in five confirmed violations with resolved action anchors occurs after the agent states the relevant constraint or risk, revealing a Recognition--Execution Gap. Finally, a training-free policy reminder reduces confirmed violations by more than 70 percentage points in matched replay. These findings show that executable evaluation can improve safety measurement and identify actionable intervention points.

## 1. 核心问题与整体含义（研究动机与背景）

- **问题核心**：现有LLM智能体安全评测将安全水平简化为单一的攻击成功率（ASR），把"暴露-执行-观察-裁决"四个环节混为一谈，导致报告数字既无法反映真实违规，也无法区分"实际有害行为"与"证据可见性"。
- **动机来源**：
  - 智能体将语言输出转化为环境改变（改文件、发邮件、操作账户），对抗性内容可通过文件或工具输出在普通任务中引发违规行为；
  - ASR依赖评测流水线，仅在指定协议下才有意义（Chouldechova et al.）；
  - 智能体可能在口头上拒绝/识别风险，但实际上仍执行有害操作（如缺少批准仍执行转账、仅服务记录中可见的私钥泄露）；
  - 已有工作表明模型能区分评估与部署环境，评估意识会虚增安全指标；轨迹级监控（如BraveGuard）可能漏掉真实危害。
- **整体意义**：需要一个不把可执行环境仅当作沙箱、而是当作**测量仪器**的框架，将"智能体系统行为"与"观察与裁决方式"分离，实现忠实测量并能定位可干预的诊断信号。

## 2. 方法论

### 2.1 框架总览
REDAgentBench 框架的核心流程：**从显式安全约束推导攻击 → 在隔离沙箱中执行 → 用服务收据/状态差异验证危害 → 区分执行结果与报告标签，并独立标注识别状态**。

### 2.2 基准构建（Case Generation & Refinement）
- **威胁模型**：红队方能控制的仅限——用户输入、智能体平台工作空间、智能体可观察的外部工具/数据源。
- **IVC 分类法**：每个案例关联 干预策略（Intervention）→ 漏洞表现（Vulnerability）→ 约束（Constraint）路径，共 15 种干预策略、11 种漏洞表现、28 条约束。
- **自主生成流水线**：
  - 整合 12,181 条来源关联的攻击映射（来自 AgentDojo、InjecAgent、Vera、FinVault 等）；
  - 前沿LLM针对每条约束检索相关干预策略并规划可执行的 IVC 路径（指定漏洞、资源、干预通道、可观察目标）；
  - 环境感知编译器将路径实例化 为可执行任务、种子、攻击和验证器；
  - 基于回放证据（轨迹、服务收据、状态差异）迭代修订失败或歧义的案例与验证器。
- **质量控制**：三轮开发中两名安全专家盲审 480 个采样案例版本；冻结后另抽取 320 个案例独立盲审。

### 2.3 状态接地沙箱（State-Grounded Sandbox）
- 五个服务表面：workspace、email、browser、banking、external files；
- 执行前初始化服务并记录基线状态；执行后捕获最终快照与服务收据，通过 基线-最终差异 识别环境变化；
- 执行结果 E 由确定性验证器（服务收据/状态差异）或混合视图裁判按证据裁决，**智能体自述不能作为 E 的依据**。

### 2.4 忠实测量公式
报告 ASR 定义：
```
dASR_Ω(s; c, b) = (1/|Ω|) Σ Y_i(c, b)
```
- s =（模型、框架、评估提示）；
- c = (v, p, g)：证据视图、证明契约（prompt）、确定性门控；
- b = 裁判骨干；
- 用状态接地结果 E_i(s) 替换 Y_i 即得执行 ASR。
- 由此，固定 rollout 和裁判骨干，改变视图配置，即可量化报告标签对评判配置的敏感性。

### 2.5 三重视角裁判系统（Trajectory–State–Hybrid, 2+1）
- **轨迹裁判**：仅读取 agent 消息和工具调用，按轨迹证明契约判定；
- **状态裁判**：仅读取服务收据和状态差异，按状态证明契约判定；
- **混合裁判**：融合两类证据，对齐工具调用与环境记录，解决声称与观察结果不一致的情况；
- 三者共享同一裁判骨干，规则优先：确定性验证器优先读取关键字段、排除失败/设置/非 agent 动作，语义性约束再交由引用证据的LLM裁判。

### 2.6 识别标注与 REG
- 识别标注独立于结果裁决进行：只给定适用约束和有害动作之前的 agent 文本，判定：
  - **宽泛识别 R=1**：agent 明确陈述规则、必要前置条件或具体风险；
  - **严格识别 R=1**：agent 进一步承认该动作仍受禁止或未获授权。
- **Recognition–Execution Gap (REG)**：定义为一组 = {E=1, R=1} 的已确认违规，报告 P(R=1 | E=1)。

## 6. 主要结论与发现

1. **单一 ASR 不足以刻画安全性**：宏平均 ASR 为 65.69%（六模型三框架），但模型排名随框架翻转变动——如 Qwen-plus 在 OpenClaw 中 78.74%、Hermes 中 81.74%，而 Codex 中最优是 KIMI-2.6（78.51%）；Qwen-plus 在 E5 类别上从 OpenClaw 40.62% 跃至 Codex 91.92%、Hermes 95.00%。
2. **轨迹视图系统性低估危害**：状态裁判比轨迹裁判 ASR 高 7.73–11.72 个百分点，每模型 13.0–21.2% 配对标签翻转；64 个切面中 23 个出现严格排名反转（共 43 次倒置），如 Hermes 下 Qwen3.7-plus 与 KIMI-2.6 的排名顺序在轨迹/状态视图下相反。
3. **评估上下文披露改变行为**：明确披露"授权评估+模拟环境"后，ASR 下降 4.77–6.59 个百分点（Qwen3.7-plus 与 Qwen3.5-plus），但并非均匀——OpenClaw/T4 反而上升（+4.82~+6.02 点）。
4. **识别-执行缺口（REG）存在且集中**：约 1/5（17.92%）已确认有害执行发生在 agent 陈述相关约束/风险之后；严格定义下为 5.48%。REG 高度集中在 数据/RAG投毒（50.64%）、权威压制（37.79%）、工具输出篡改（36.59%）、工作区文件投毒（32.14%），而直接指令攻击下仅 1.89%。
5. **免训练策略提醒有效**：在确认性队列中，策略提醒将 ASR 降低 74.19 个百分点（95% CI [69.85, 78.41]），在 510 案例中阻止 368/434 条基线违规；自提醒中等有效，中性文本几乎无效果。这证明可执行诊断能引导出可操作的修复。

## 7. 优点

- **方法层面**：
  - 将 ASR 报告显式化为 (harness, judging config, evaluation cue, judge backbone) 元组，使跨论文比较成为结构化声明；
  - IVC 分类法同时约束红队攻击生成与验证器设计，保证案例的"可追踪-可执行-可观测"；
  - 三重视角裁判（轨迹/状态/混合）在固定 rollouts 上做配对对比，干净地分离行为与观测/裁决效应；
  - 用独立于结果裁决的 RECOGNITION 标注（宽/严两级）定义并量化 REG，可直接连接诊断与修复。
- **实验层面**：
  - 六模型 × 三框架完整矩阵优于平均化报告；
  - 人工审计覆盖裁判标签并给出加权估计，增强可信度；
  - 防御实验采用逐案例匹配回放（模型、框架、攻击、判定固定），因果关系更清晰；
  - 对未解析锚点采用保守下界处理，避免高估 REG。

## 8. 不足与局限

- **覆盖范围**：
  - 仅 5 个服务表面；无真实互联网/三方服务，浏览器动作受限（无真实渲染）；
  - REG 与防御实验集中在 Qwen 系列，缺乏对 GPT、Kimi、GLM 的 REG 估计；
  - 回放队列来自"历史上有害"案例，不代表全基准分布。
- **偏差风险**：
  - 闭源模型 API 版本漂移导致不可完全复现；
  - 评估意识仅测试"显示前缀"一种提示，未覆盖更微妙的隐蔽线索；
  - 混合裁判与状态裁判结果接近，轨迹-状态是主要对比，但混合裁判的人-机一致性未单独审计；
  - 防御实验的"策略提醒"可能只是将行为转为隐性违规（如口头拒绝但状态记录难以捕捉的间接动作），未做进一步状态检查鉴别。
- **应用限制**：
  - 免训练提醒不能替代硬访问控制；作者也承认这一点；
  - 当前框架未评估多轮自适应攻击或攻击者"后手"（attacker-moves-second）效应；
