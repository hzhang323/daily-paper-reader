## 摘要
数据代理能够对组织工作空间进行自然语言分析，其中相关证据可能散布在数据库、结构化文件、长文档和多模态媒体中。现有基准大多将结构化查询、检索或开放式分析割裂开来，未能将异构证据发现、完整表格输出和确定性评估充分统一。我们引入DataSpace，这是一个基准测试，要求数据代理从任务局部的异构工作空间中生成可验证的表格结果。它包含410个跨语言任务和7439个工件，总计15.01 GB，涵盖CSV、JSON、SQLite、Markdown、PDF和视频。DataSpace还作为KDD Cup 2026复杂数据分析数据代理竞赛的官方评估基准。每个代理仅接收一个问题和工作空间，并返回完整请求的表格结果。我们使用DataSpace-Builder构建DataSpace，这是一个基于执行执行的框架，包括跨语言转换、约束感知的关系采样、模态路由和工件渲染，以及由11位领域专家进行的人工审查和任务修复。确定性评估器执行标题不变的列对齐、类型和精度感知的归一化以及顺序感知的行比较。在最近发布的六种前沿多模态模型和五种广泛使用的代理框架中，最佳准确率达到66.34%，而框架选择在固定主干网络的情况下产生了15.36个百分点的差距。多模态证据整合和连接在所有六个主干网络上持续降低准确率。这些结果表明DataSpace尚未饱和，并揭示了提高数据代理可靠性的关键挑战。

## Abstract
Data agents enable natural-language analytics over organizational workspaces, where relevant evidence may be scattered across databases, structured files, long documents, and multimedia. Existing benchmarks largely isolate structured querying, retrieval, or open-ended analysis, leaving heterogeneous evidence discovery, complete tabular outputs, and deterministic evaluation insufficiently unified. We introduce DataSpace, a benchmark in which data agents produce verifiable tabular results from task-local heterogeneous workspaces. It contains 410 cross-language tasks and 7,439 artifacts totaling 15.01 GB across CSV, JSON, SQLite, Markdown, PDF, and video. DataSpace also served as the official evaluation benchmark for the KDD Cup 2026 Data Agents for Complex Data Analysis competition. Each agent receives only a question and workspace and returns the complete requested tabular result. We construct DataSpace with DataSpace-Builder, an execution-grounded framework comprising cross-language transformation, constraint-aware relational sampling, modality routing and artifact rendering, and human review and task repair by 11 domain experts. A deterministic evaluator performs header-invariant column alignment, type- and precision-aware normalization, and order-aware row comparison. Across six recently released frontier multimodal models and five widely used agent harnesses, the best accuracy reaches 66.34%, while harness choice creates a 15.36-point spread with the backbone fixed. Multimodal evidence integration and joins consistently reduce accuracy across all six backbones. These results show that DataSpace remains unsaturated and identify key challenges for improving data-agent reliability.

# DataSpace：面向异构工作空间可验证分析的数据代理基准——论文总结

## 1. 核心问题与整体含义

- **研究背景**：数据代理（Data Agent）正成为连接自然语言与组织数据的接口。在真实分析场景中，回答用户问题所需证据通常分散在关系数据库、结构化文件、长文档、多媒体等多种异构工件中，且可能涉及多种语言。现有基准（如 Spider、BIRD、HotpotQA、MMLongBench-Doc、KramaBench、FDABench 等）往往只覆盖单一或部分方面，将结构化查询、信息检索和开放式分析割裂开，缺乏对以下三个关键属性的统一评测：
  - **L1. 工作空间范围**：任务局部工作空间应同时包含结构化文件、数据库、长文档和多媒体，且问题和数据均可跨语言。
  - **L2. 输出契约**：任务要求返回完整分析结果（完整表格），而非事实片段、执行管线或开放式报告。
  - **L3. 评估语义**：需要确定性评估，能接受等价表达，同时拒绝不完整或错误的答案。
- **核心问题**：如何构建一个能统一评测数据代理在异构工作空间中发现证据、跨表征对齐、执行多步计算并返回完整表格结果的基准，且评估是确定、可验证的。
- **整体意义**：该论文提出了 **DataSpace** 基准，填补了上述空白，并作为 KDD Cup 2026 数据代理复杂数据分析竞赛的官方评估基准，为衡量和推动数据代理的可靠性提供了标准化测试平台。

## 2. 方法论

- **基准任务定义**：每个任务输入为一个自然语言问题 \( q_i \) 和一个任务局部工作空间 \( W_i \)，其中 \( W_i = W_i^{str} \cup W_i^{doc} \cup W_i^{med} \)，分别涵盖结构化工件（CSV、JSON、SQLite）、文档工件（Markdown、PDF）和媒体工件（视频）。代理仅凭问题和工作空间，必须自主发现和组合可用数据，最终返回完整表格结果（CSV 文件）。任务正确性判定为预测表格与参考表格在给定语义配置下完全等价。
- **DataSpace-Builder 构建框架**：利用两个英文 Text-to-SQL 源（EHRSQL 临床、BULL 金融）的可执行 SQL 作为可验证的分析逻辑来源，通过四个阶段将源实例转化为跨语言、异构工作空间任务：
  1. **跨语言转换（CLT）**：
     - 将问题、数据库状态和可执行 SQL 进行联合迁移（joint migration），而非单独翻译，以保证实体、谓词和查询逻辑一致性。
     - 使用一致性感知重写：通过外键、共享名称、值重叠等建立列簇，统一翻译同一实体；标识符、代码、日期、数字保持不变。
     - 生成表级、列级、值级替换映射 \( M = \{M_{tab}, M_{col}, M_{val}\} \)，并据此确定性重写数据库和 SQL，同时翻译问题。
     - 验证：重写后 SQL 必须能在新数据库上执行，且结果与源结果经值映射后一致；再用 LLM 判断问题语义对齐。
  2. **约束感知关系采样**：
     - 为避免多个任务共享同一数据库导致的重复，构造任务局部数据库实例：保留完整表清单和模式，但按策略采样行。
     - 采样防护集 \( C_s \) 包含主键、外键、连接列、谓词和边界值、目标实体等，保证采样后连接路径和查询条件仍有效。
     - 通过“锚定行 + 关系闭包 + 软预算采样”得到采样数据库 \( D_s \)，执行 SQL 得到候选参考答案 \( Y_s \)，并验证结构性（表完整性、外键一致性）和执行性（SQL 可执行、结果非退化）。
  3. **模态路由与工件渲染**：
     - **基础路由**：根据表元数据（模式、类型、键、行数等），以固定种子和批量覆盖平衡，将每个表渲染为 CSV、JSON、SQLite、Markdown 或 PDF。
     - **事实驱动文档**：用 LLM 生成文档计划（行锚、属性组、分块），然后生成段落，要求每个源单元格被精确表达，并通过验证器检查字段值、精度、空值策略等；必要时转成 PDF。
     - **查询条件驱动的视频渲染**：从 SQL AST 和候选答案中提取类型化证据原子（过滤条件、结果单元），生成故事板、旁白并渲染为视频；同时修改问题，将被视频承载的条件或答案从显式问题中移除（谓词抽象或答案证据策略），使任务无法绕过视频。
  4. **人工审查与任务修复**：
     - 由 11 名领域专家组成评审组，每任务至少两位盲审独立求解，验证参考答案并独立编写评估配置（列类型、数值精度、排序敏感等）。
     - 出现分歧时进行证据讨论、最小化修复，再独立重审，循环直至共识；无法解决的移除。
- **确定性评估器**：
  - **任务配置** \( c_i = (o_i, \{\nu_{ij}\}) \)，记录列语义类型（文本、数值、日期、布尔等）、数值精度规则、是否允许百分号、行顺序是否敏感。
  - **规范化**：文本归一化（NFC、去空格），数值解析为十进制并按配置精度舍入，日期时间统一到 ISO/UTC，布尔归一，空值统一。
  - **列对齐**：预测表头不评分，列顺序可不同；评估器搜索参考列到预测列的一一映射，要求所有单元格都能在目标规则下解析。
  - **等价判定**：形状不同则不等；按行顺序比较（敏感时）或作为多重集合比较（不敏感时保留重复行）；任一有效列排列使规范化后行视图相等即为正确。
  - **聚合指标**：Task Accuracy，对所有任务求平均正确率。

  - 实验覆盖较全面：既比较了模型能力，又比较了代理框架对端到端结果的影响；同时提供了效率-精度权衡分析。
  - 评估协议统一、确定性、无模型裁判，减少了主观偏差。
  - 控制变量设计较公平：骨干对比固定同一代理；框架对比固定同一骨干，并保留各框架原生控制循环。
  - 局限性：每个骨干-框架组合只进行一次评估（未见多次重复和方差报告）；未对随机种子、模型温度等敏感性做分析；特征分组是描述性相关，不排除混淆因素。

## 6. 主要结论与发现

- **基准尚未饱和**：最佳骨干 Grok 4.5 仅达到 66.34% 准确率；有 76 个任务所有模型均无法解决（被 6 个模型全部解出的仅 56 个）。模型间的 oracle 联合可解率为 81.46%，说明存在模型特异性成功和共同困难。
- **框架选择显著影响结果**：固定 MiMo-V2.5 时，准确率从 Smolagents 的 30.98% 到 Grok Build 的 46.34%，相差 15.36 个百分点。
- **多模态证据整合与连接是最大瓶颈**：多模态任务在所有 6 个骨干上均低于单模态任务 1.8–14.0 个百分点；连接（join）使准确率下降 9.7–19.8 个百分点。
- **效率与精度可分离**：GPT-5.6 Sol 比 Grok 4.5 仅低 1.71 个百分点，但 token 使用减少 74.2%、动作减少 50.3%、延迟减少 39.2%；成本前沿不同，MiMo-V2.5 是极低成本的运行点。
- **答案物化是主要失败来源**：对 Grok 4.5 失败任务审计显示，52.2% 的失败源于物化阶段（多列/少列、格式错误等），22.8% 源于任务意图理解错误；大量失败发生在已有正确内部结果但未能输出正确表格的情况。
- **评估症状 ≠ 诊断原因**：同一输出错误可能由不同阶段导致，提示未来需要更细粒度的过程级评估。

## 7. 优点

- **任务设计贴近真实**：将数据代理定义为“工作空间求解器”，要求完整表格输出，统一了证据发现、跨表征对齐和多步计算，填补了现有基准的空白。
- **构建流程可执行、可验证**：DataSpace-Builder 从可执行 SQL 出发，通过一致性映射、关系采样、模态渲染和专家审查，生成每个任务的参考答案，保证任务有唯一正确解。
- **评估确定性且语义感知**：不受表头影响、支持列重排、数值精度和行序语义，能容忍等价表示同时拒绝不完整/错误输出，避免 LLM 裁判带来的偏见。
- **多语言、多模态、多规模**：410 任务覆盖金融、宏观、医疗，含 15 GB 数据、25k PDF 页、5.5 小时视频，跨语言任务占比 64.6%，具有丰富性和难度。
- **实验设计有控制变量**：分别固定代理比较骨干、固定骨干比较框架，揭示了模型能力和框架设计各自的影响；提供效率、成本、特征归因和失败分析，结论全面。
- **开源可用**：代码、数据集和部分参考答案公开，并实际用于 KDD Cup 2026 竞赛，具备可复现性和影响力。

## 8. 不足与局限

- **实验覆盖与可重复性**：每次实验似乎只运行一次，缺乏多次运行的方差或置信区间；无法判断结果稳定性。对模型推理配置（温度、reasoning effort）统一用默认值，可能未充分公平比较。
- **基准规模相对有限**：410 个任务在领域覆盖上仍集中在金融、宏观、医疗，语言以中英为主，视频仅作为附加模态（189 个任务，其中 97 个需要视频），缺少更多模态（如图表、音频）和更多语言组合。
- **构建依赖 LLM 与人工审查**：跨语言翻译、文档生成、视频证据等依赖 LLM，即使有人工审查和修复，仍可能存在生成偏差或意外泄漏；人工审查成本高且难以大规模扩展。
- **评估协议仍有可争议处**：数值“按配置精度”会掩盖真实浮点小差异；对文本大小写敏感，可能对某些等价表达过于严格；列对齐穷举搜索在列数较少时可行，但对宽表格（当前最宽 6 列）尚可，若未来扩展到更多列则可能面临计算开销。
- **特征归因限于描述性**：语言、模态、连接等分组分析未控制混杂因素，不能说明因果关系。
- **实际应用限制**：适合评估“工作空间求解”式数据代理，但未覆盖在线交互、数据库权限、数据更新、多用户协作等生产属性；也未评估模型在未见过的脏数据、对抗性误导证据下的鲁棒性。
