## 摘要
近年来，由多模态大语言模型（MLLMs）驱动的智能体系统发展迅速，但现有的具身智能体基准仍缺乏对多智能体协调的细粒度诊断。大多数基准要么专注于单智能体任务完成，要么以整体任务成功率来概括多智能体行为，这可能会掩盖诸如重复工作、违反顺序约束、资源争用和交接不同步等协调失败。在本文中，我们介绍了CoCoBench，一个用于评估可执行家务任务中多智能体具身协调的构念级基准。CoCoBench包含897个经过Oracle验证的实例，围绕四个反复出现的协调构念组织：任务分配、顺序排序、互斥和交接协调。除了任务成功率外，CoCoBench还提供构念级分数，用于衡量智能体是否有效协调。我们评估了11个领先的MLLMs在不同协调模式、观察输入和智能体数量下的表现。结果表明，协调能力具有高度的构念特异性：良好的整体表现并不意味着在不同协调类型上具备均衡的能力。这些发现为设计有针对性的模型架构和提升多智能体协调能力指明了新方向。

## Abstract
Agent systems powered by multimodal large language models (MLLMs) have advanced rapidly in recent years, yet existing embodied-agent benchmarks still lack fine-grained diagnostics for multi-agent coordination. Most benchmarks either focus on single-agent task completion or summarize multi-agent behavior with overall task success rates, which can obscure coordination failures such as duplicated work, violations of ordering constraints, resource contention, and desynchronized handoffs. In this paper, we introduce CoCoBench, a construct-level benchmark for evaluating multi-agent embodied coordination in executable household tasks. CoCoBench contains 897 oracle-validated instances organized around four recurring coordination constructs: task allocation, sequential ordering, mutual exclusion, and handoff coordination. In addition to task success rate, CoCoBench provides construct-level scores that measure whether agents coordinate effectively. We evaluate 11 leading MLLMs across different coordination modes, observation inputs, and numbers of agents. The results show that coordination ability is highly construct-specific: strong overall performance does not imply balanced competence across different coordination types. These findings point to new directions for designing targeted model architectures and improving multi-agent coordination ability.

  - 重复工作（任务分配不当）
  - 违反顺序约束（前置条件不满足）

- **核心贡献**：提出 CoCoBench，一个“构造级”（construct-level）的具身多智能体协调基准，将协调能力从任务完成中分离出来，通过可量化的协调分数对协作过程进行诊断。

## 2. 方法论

- **形式化建模**：将多智能体协调定义为共享环境中的高层联合决策问题，任务实例表示为 `x=(E, A, S, O, U, ∆, Φ, H, d)`。
- **协调耦合定义**：如果智能体 `a_i` 的动作会改变另一个智能体 `a_j` 执行某动作的可行性、目标贡献或执行代价，则该任务存在协调耦合。
- **评估轴**：每个轨迹同时获得 `Succ`（最终任务成功）和 `Cd`（构造级协调分数），两轴互补，避免“非法但成功”的路径被误判。
- **四大协调构念与评分公式**：
  - **D1 任务分配（Task Allocation）**：衡量并行分工的均衡性，使用 `CD1 = min(1, M*/M)`，其中 `M*` 为参考最长时间，`M` 为实际完成时间。
  - **D2 顺序排序（Sequential Ordering）**：衡量前置条件遵循度，`CD2 = p_legal * (1 - v/n)`，`p_legal` 为合法性门控（无非法技能/前置违规为1，否则0.5），`v/n` 为顺序违规占比。
  - **D3 互斥（Mutual Exclusion）**：衡量共享资源访问的冲突程度，`CD3 = (1 - c/a) * min(1, M*/L)`，`c/a` 为碰撞率，`L` 为实际步数。
  - **D4 交接协调（Handoff Coordination）**：衡量生产者-消费者节奏，`CD4 = 1 - min(1, (o+w)/h)`，`o` 为溢出次数，`w` 为空缓冲等待次数，`h` 为成功交接数。
- **基准构建**：基于 AI2-THOR 仿真环境，通过符号模板生成10种任务族，实例必须通过三类质量控制门控（布局、Oracle 可解性、度量近满分），确保实例可执行且诊断信息充分。
- **评估协议**：
  - 固定高层技能接口（导航、拾取、放置、打开/关闭、切片等）。
  - 支持集中式（全局规划）、分散式（各智能体独立决策）以及带通信的分散式协议。
  - 固定底层执行器，隔离高层决策差异；实时记录轨迹事件，评分可完全由轨迹复现。

## 6. 主要结论与发现

- **协调能力是构造特异的**：GPT-5.6-sol 整体最优，但 Qwen3-VL-8B 在 D1 上超过它；Claude Opus 4.8 在 D2 上领先；GPT-5.6-sol 在 D3、D4 上领先。强整体性能 ≠ 各协调类型均衡。
- **集中式状态聚合仍然关键**：集中式策略（SR 48.0%，CS 0.69）优于分散式+通信（39.6%，0.65）和纯分散式（36.7%，0.63）；通信只能部分弥补全局视觉缺失。
- **符号协调是主要瓶颈**：在高层技能接口下，去掉视觉（盲设定）性能不降反升（盲 SR 42.3% vs 图像 40.6%），说明瓶颈在于符号级团队规划，而非底层视觉识别。
- **团队规模增大加剧协调负担**：整体 SR 从2智能体的48.8%降至4智能体的43.1%，CS 从0.68降至0.63；强模型保持稳定，弱开源模型下降更明显（如 InternVL3.5-8B 从16.9%降至7.7%）。
- **成功与合法协调可能背离**：如 Claude Haiku 4.5 的成功率（63.1%）高于合法计划率（47.2%），说明部分成功来自“非法捷径”；而 Claude Opus 4.8 的合法率（96.3%）远大于成功率（78.5%），说明失败多为“合法但不完整”。
- **失败模式差异明显**：专有模型几乎无协议失败，而开源模型平均17.5%协议失败、预算耗尽比例高，反映能力与协议遵循度的差距。

## 7. 优点

- **构造级细粒度诊断**：将抽象协调问题分解为四种可量化构造，填补了“单一成功率”掩盖问题的空白。
- **双指标分离**：任务成功与协调质量分开报告，能够识别“非法成功”和“合法未成”两类情况。
- **评分可复现**：评分基于模拟器日志中的事件（如碰撞、等待、溢出），非人工裁决，客观且可复现。
- **质量控制严格**：三类门控（布局可行性、Oracle 可解性、度量区分性）保证实例的构造有效性和诊断力度。
- **多维度评估框架**：同时覆盖集中/分散、通信/无通信、图像/盲、团队规模，便于系统定位模型缺陷。
- **相关性验证充分**：构造分数间低相关证明四维构造并非冗余，增强了基准的结构信度。
- **失败原因归因**：通过依赖违规、占用冲突、非法调用等细分，帮助判断模型是“规划差”还是“执行差”。

## 8. 不足与局限

- **环境单一**：仅基于 AI2-THOR 仿真，未在真实机器人或更多仿真平台（如 Habitat、Minecraft）验证，真实世界泛化性未知。
- **高层抽象限制**：技能接口很粗糙，固定执行器忽略低层运动与感知误差，因此基准评估的是“团队规划能力”而非端到端协作能力，可能低估多智能体低层协调的复杂度。
- **盲设定结论有边界**：盲观察性能不降只能说明在该高层接口下视觉冗余；在真实具身场景中，视觉对空间定位和对象识别仍不可或缺。
- **评价函数依赖参考计划**：D1 和 D3 使用 Oracle makespan（`M*`），参考计划仅对高层技能抽象最优，且未保证全局低层最短路；若参考计划非最优，分数可能产生偏差。
- **实例分布不均**：2/3/4智能体实例数不平衡（415/288/194），团队规模效应可能受样本量影响。
- **计算开销比较受限**：API 延迟与本地推理时间混在一起，跨专有/开源模型的效率对比缺乏严格公平性。
- **未讨论模型训练与微调**：基准只评估推理决策，未分析模型在协调任务上的训练数据泄露或微调适应性。
- **构念维度有限**：四个构造并未穷举所有协调模式（如协商、角色切换、异步进展下的动态重规划），未来可扩展更多协调失败类型。
