## 摘要
大型语言模型（LLMs）依赖工具调用作为基本的代理能力，使其能够调用外部系统并完成文本生成之外的任务。然而，干净的端到端（E2E）成功无法识别工具使用故障的起源，也无法识别故障如何在调用中传播。我们引入了ToolRobustBench，一个面向工具调用代理的分阶段诊断基准，其中工具调用代理是一个LLM系统，它选择工具、提供结构化参数并解释其返回的反馈。ToolRobustBench将四个扰动族与工具使用流程对齐：工具接口、用户意图、工具输出/观察和运行时环境扰动。它将故障归因于工具选择、模式接地、参数绑定、工具输出/运行时反馈处理以及E2E任务成功。在涵盖7个模型、16个采样本地工具、4个扰动族和14个子类型的15,456个单族实例上的实验显示，干净性能高但不均匀，且鲁棒性大幅下降，其中工具输出/观察扰动是主要瓶颈。混合族实验揭示了非加性故障模式，这些模式无法由孤立的单族结果解释。因此，ToolRobustBench提供了一个确定性的、级联感知的基准，用于诊断超出干净工具调用准确性的鲁棒性；

## Abstract
Large language models (LLMs) rely on tool calling as a fundamental agent capability, enabling them to invoke external systems and complete tasks beyond text generation. However, clean end-to-end (E2E) success cannot identify where a tool-use failure originates or how it propagates through a call. We introduce ToolRobustBench, a stage-wise diagnostic benchmark for tool-calling agents, where a tool-calling agent is an LLM system that selects a tool, supplies structured arguments, and interprets its returned feedback. ToolRobustBench aligns four perturbation families with the tool-use pipeline: tool-interface, user-intent, tool-output/observation, and runtime-environment perturbations. It attributes failures to tool selection, schema grounding, argument binding, tool-output/runtime-feedback handling, and E2E task success. Experiments on 15,456 single-family instances across 7 models, 16 sampled local tools, 4 perturbation families, and 14 subtypes show high but non-uniform clean performance and substantial robustness degradation, with tool-output/observation perturbation the dominant bottleneck. Mixed-family experiments reveal non-additive failure patterns that are not explained by isolated single-family results. Thus, ToolRobustBench provides a deterministic and cascade-aware benchmark for diagnosing robustness beyond clean tool-calling accuracy;

## 一、核心问题与整体含义（研究动机与背景）

- **核心问题**：工具调用是 LLM 智能体与外部系统交互的关键能力，但仅靠干净的端到端（E2E）任务成功率**无法识别故障的起源位置与传播路径**。例如，“参数错误”可能直接源于参数绑定失败，也可能源于上游工具选择阶段被模糊接口误导后的级联连带；而“运行时故障”可能并非执行环境问题，而是上游参数污染所致。
- **研究动机**：现有基准（如 ToolBench、BFCL、ToolSandbox、AgentNoiseBench 等）主要关注工具调用的最终准确率、大规模 API 执行或轨迹质量，但缺乏在**受控条件下定位首个失败阶段**的机制，导致仅记录最终失败标签会混淆症状与根源，可能把上游错误错误归因到错误能力上。
- **整体含义**：ToolRobustBench 的目标是超越“干净工具调用准确率”的评估，**将扰动注入位置与工具调用流水线阶段对齐**，并通过级联感知的归因机制区分“症状”与“根源”，实现确定性的、可复现的鲁棒性诊断。

## 二、方法论

### 2.1 核心思想

将一次工具调用视为一条流水线：意图推断 → 工具选择 → 参数绑定 → 执行/反馈解释 → 最终决策。通过在**不同管道入口**注入受控扰动，再通过**回溯式归因**定位首个失败阶段，从而把下游症状与上游原因分离。

### 2.2 五个诊断能力轴（S1–S5）

| 轴 | 能力 | 典型失败 |
|---|---|---|
| S1 | 工具选择 | 未调用、选错工具 |
| S2 | 模式接地 | 选错工具、模式格式违规 |
| S3 | 参数绑定 | 缺少参数、参数值错误 |
| S4 | 工具输出/运行时反馈处理 | 参数错误、格式违规、运行时故障 |
| S5 | 端到端任务成功 | 所有失败标签 |

### 2.3 四族阶段对齐扰动

- **A 工具接口扰动**：A1 名称表面移位、A2 描述抽象化、A3 兄弟工具混淆；
- **B 用户意图扰动**：B1 间接表达、B2 欠明确、B3 干扰上下文、B4 内部冲突；
- **C 工具输出/观察扰动**：C1 返回结构噪声、C2 证据丢失、C3 证据篡改、C4 证据竞争；
- **D 运行时环境扰动**：D1 可用性故障、D2 运行变异性、D3 反馈质量。

每个子类型有确定性的模板操作（如重命名键、丢弃字段、插入过期值、提供冲突候选证据等），并配有静态严重度评分，通过预检测门确保 light < medium < heavy。

### 2.4 级联感知错误归因

- **六个诊断字段**：观测错误标签、主错误标签、最早失败阶段、错误源阶段、级联指示器、边界违例指示器。
- **确定性回溯算法**：先按固定优先级顺序得出观测错误标签，再比较该标签是否为该扰动族允许的下游溢出错；如果是，则向前回溯至最早兼容的上游阶段并记录为主错误源。
- **不使用 LLM 裁判**，保证归因确定性；通过反事实修复验证归因的因果有效性。

### 2.5 指标

- Clean、Robust_f、Overall、Drop_f 等成功率指标；
- 级联率 CR 与边界违例率 BVR；
- 混合族指标 Δ = 混合成功率 − 较弱单族成功率；
- 严重度为一个**受控的输入侧压力轴**，不要求模型精度严格单调。

## 六、主要结论与发现

1. **干净工具调用准确率高但不均匀，且不能预测鲁棒性**：平均干净成功率达 0.979（3 个模型达 1.000），但整体扰动鲁棒性仅 0.664–0.766。个别工具（如 filter_items 仅 0.881）存在较大任务级差异。
2. **C 族（工具输出/观察扰动）是所有模型的主要瓶颈**：家族平均仅 0.455，没有任何模型超过 0.60；C2 证据丢失最难（0.142）。
3. **缺失/竞争性返回证据远难于表面接口变化**：A 族 0.918、B 族 0.773、D 族 0.688、C 族 0.455。B3（干扰）与 D2（运行变异性）分别是 B、D 族的最难子类型。
4. **级联归因有效**：D 族级联率最高（0.638），A 族 0.352；C 族仅 0.003（失败通常直接源于证据恢复）。边界违例率整体很低（≤0.109）。
5. **反事实修复验证归因的因果性**：修复主错误后 72.4%（71/98）的任务可恢复；Tier-1 单错案例 100% 恢复，Tier-2 级联案例 82.1% 恢复。
6. **诊断标签可指导干预**：B 族 S3 层的 CoT 提示无效（21/30→21/30），而 A 族 S1 层别名澄清有效（21/30→30/30），证明“修对阶段”比“修错阶段”更关键。
7. **混合族扰动呈现非加性负面交互**：中严重度混合族成功率 0.448，显著低于较弱单族 0.621 和两族均值 0.754；A3+C4 和 B4+C4 产生最强的负面交互。
8. **C2 失败非数据人为不可恢复**：人类 YES+PARTIAL 可恢复率 68.3%，而最强模型仅 27.8% 成功，暴露模型证据恢复能力与人类之间的显著鸿沟。

## 七、优点

- **阶段对齐的扰动设计**：四族扰动恰好注入工具调用流水线的四个不同入口，首次实现“扰动位置”与“失败阶段”的可控对应。
- **级联感知归因机制**：通过确定性回溯把下游症状与上游根源分离，报告主错误而非仅观测错误，避免错误归因。
- **完全确定性、可复现**：本地确定性工具 + 固定种子采样 + 确定性模板与标签，避免 live API 波动，评估可精确复现。
- **多重有效性验证**：人工审计、LLM 交叉验证、C2 可恢复性审计、反事实修复研究、定向干预实验形成完整的证据链，说明诊断标签不仅是描述性工具，而是具有因果效力的信号。
- **混合族实验的方法论贡献**：发现混合扰动的非加性失效模式，说明单纯单族测试不足以预测部署场景下的组合鲁棒性。
- **指标设计严谨**：区分“级联”与“边界违例”，提供更细粒度的归因画像；严重度为构造期受控轴而非经验排序。

## 八、不足与局限

- **单步任务设定**：不覆盖长程规划、持久状态、跨工具依赖，无法评估多轮交互与状态修复能力。
- **混合族覆盖有限**：仅报告 5 个代表性子类型对，未穷举全部配对；部分 C–D 混合因缺失明确定义的观察目标而无法归因，被有意排除。
- **本地确定性工具的生态代表性有限**：真实生产 API 包含认证、限流、状态副作用、厂商特定错误语义等，绝对成功率、级联率与 D 族结论可能不直接迁移。
- **模型访问协议差异**：不同模型经由不同 provider 或 OpenAI 兼容后端访问，存在协议兼容性这一残余变异源；虽经归一化处理，仍不能完全消除。
- **人工验证样本的非无偏性**：审计样本为覆盖子类型而刻意纳入较多重型与失败案例，不宜视为全基准难度分布的无偏估计；且允许“不清楚”保守判断，减少了部分指标的有效样本量。
- **严重度单调性约束较弱**：静态严重度保证构造强度单调，但模型精度在个别子类型中不严格单调（如显式的重度运行时失败反比模糊的部分碎片更易分类）。
