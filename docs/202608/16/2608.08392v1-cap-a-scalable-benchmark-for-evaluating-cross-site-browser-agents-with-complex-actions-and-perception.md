## 摘要
大型语言模型正越来越多地被部署为通过浏览器与网页交互的自主代理。虽然近期进展主要由评估端到端任务成功率的基准所推动，但这些评估在很大程度上忽略了一个现实网页浏览中的两个基本难点来源：对丰富用户界面的复杂操作，以及动态渲染内容的视觉感知，尤其是在跨多个网站的工作流中。我们引入了CAP，一个可扩展基准，用于评估浏览器代理在跨站点、类人网页任务上的表现，这些任务需要非平凡的UI交互和视觉理解。具体而言，我们采用一种分解与重组流程：首先将每个网站抽象为一个结构化的站点卡片，该卡片捕获面向用户的功能、复杂执行操作和感知需求，然后将这些组件重组为现实的跨站点工作流。因此，每个任务都基于每个网站上的多个具体操作，从而支持细粒度的诊断。在此框架之上，我们在严格质量控制下构建了跨越108个真实网站和24个领域的420个任务。在我们可验证的代理即评判员评估框架下进行的实验显示，当前最先进的浏览器代理成功率较低，并揭示出感知密集型交互仍是一个主要瓶颈，暴露出当前代理与真实世界网页浏览需求之间的巨大差距。

## Abstract
Large language models are increasingly deployed as autonomous agents that interact with the web through browsers. While recent progress has been driven by benchmarks that evaluate end-to-end task success, these evaluations largely overlook two fundamental sources of difficulty in real web browsing: complex actions over rich user interfaces and visual perception of dynamically rendered content, especially in workflows that span multiple websites. We introduce CAP, a scalable benchmark for evaluating browser agents on cross-site, human-like web tasks that require non-trivial UI interactions and visual understanding. Specifically, we adopt a decomposition-and-recomposition pipeline that first abstracts each website into a structured site card capturing user-facing functions, complex execution operations, and perceptual requirements, and then recomposes these components into realistic cross-site workflows. Each task is therefore grounded in multiple specific operations on each website, enabling fine-grained diagnosis. Built on this framework, we construct 420 tasks across 108 real-world websites and 24 domains under careful quality control. Experiments on state-of-the-art browser agents using our verifiable agent-as-a-judge evaluation framework show low success rates and reveal that perception-heavy interactions remain a major bottleneck, exposing substantial gaps between current agents and real-world web browsing demands.

  - 且这些问题在**跨多个网站（Cross-site）** 的真实工作流中尤为突出。
- **现有评估的不足**：
  - 单站点基准（如 Mind2Web、WebVoyager）只关注简单操作，不覆盖跨站工作流。
  - 跨站点基准（如 AssistantBench、GAIA）只评估最终答案，**无法系统度量底层交互的实际难度**，难以诊断智能体失败的根因。
- **整体含义**：论文主张，要反映真实网页浏览需求，基准必须同时覆盖三个维度——跨站点工作流（Cross-site）、复杂执行（Actions）、困难感知（Perception），并提供**细粒度的失败诊断能力**，而不仅仅是端到端成功率。

## 2. 论文提出的方法论

### 2.1 核心思想：分解-重组（Decomposition-and-Recomposition）流程

将网站拆解为结构化表示，再组合成现实的跨站点任务，从而实现**可扩展的任务生成**与**可落地的细粒度诊断**。

### 2.2 四个构建阶段（关键技术细节）

1. **站点卡片注释（Site Card Annotation）**
   - 以网站为任务构建单元，定义 24 个功能聚类（如电商、旅行预订、学术搜索、房地产、代码托管等），从 SimilarWeb 高流量网站中选 139 个候选，过滤掉阻止自动访问或强制登录的站点，最终保留 **108 个网站**。
   - 每个网站 w 被注释为站点卡片：$s_w = \langle F, A, P \rangle$：
     - **F**：用户面向的功能集合（如房产搜索、按揭计算）；
     - **A**：执行项（非平凡交互，如地图拖拽、缩放），定义 $a = \langle u_{\text{comp}}, \tau_{\text{act}}, f_{\text{assoc}} \rangle$（UI 组件、动作类型、关联功能）；
     - **P**：感知项（需视觉理解的要求，如趋势识别、图像内容理解），定义 $p = \langle u_{\text{comp}}, \tau_{\text{perc}}, f_{\text{assoc}} \rangle$。
   - 动作类型与感知类型的分类体系**基于 Ant Design 组件库**（保留 Navigation、Data Entry、Data Display、Feedback，补充 Data Visualization、Media、Editor），共识别出 **64 种动作类型、56 种感知类型**。
   - 使用 Browser-Use 开源代理自动探索网站生成站点卡片，人工抽样审计准确率为 92.3%（其中功能项 97.1%、感知项 94.1%、执行项 88.7%）。

2. **聚类采样（Cluster Sampling）**
   - 计算**功能亲和度矩阵 M**：由 LLM 评估聚类两两组合形成连贯工作流的可能性（如学术搜索↔代码托管亲和度高；房地产↔代码托管亲和度低）。
   - **锚点选择**：选择历史使用频率最低的聚类作为锚点（$C_{\text{anchor}} = \arg\min_{C_i \in \mathcal{C}} h(C_i)$），防止常见领域过度代表。
   - **亲和引导扩展**：由 LLM 基于 M 和历史共同出现次数，选择 3–6 个与锚点配合良好但较少组合的聚类。

3. **任务提议（Task Proposal）**
   - 生成提议 $t_{\text{prop}} = \langle u_{\text{intent}}, o_{\text{prop}}, \phi_{\text{prop}} \rangle$，包含用户意图、计划输出、以及以有向无环图（DAG）表示的信息流 $\phi_{\text{prop}}$。
   - 支持的信息流模式：顺序（sequential）、并行（parallel）、扇出（fan-out）、扇入（fan-in）、链式（chain）。
   - **关键约束**：跨站点信息必须是执行过程中获得的，而非任务描述中预设（动态依赖原则）；通过 Skip Test 检验每个网站的必要性。
   - 人工审查 600 个提议，85.3% 通过（Cohen's κ = 0.81）。

4. **任务实例化（Task Instantiation）**
   - 生成任务实例 $t_{\text{inst}} = \langle d_{\text{desc}}, \phi_{\text{inst}}, \mathcal{E}, o_{\text{inst}}, m_{\text{meta}} \rangle$，包含自然语言描述、具体信息流、覆盖点（$\mathcal{E} = \mathcal{E}_{\text{act}} \cup \mathcal{E}_{\text{perc}}$）、期望输出、元数据。
   - **目标导向引导（Goal-Oriented Elicitation）**：描述以用户目标表述（如“找 $2000 以下的公寓”），而非 UI 操作（如“拖动价格滑块”），使复杂交互自然涌现。
   - 最终人工把关：合理性、复杂度、可执行性、可评估性、主题安全性，筛选出 **420 个任务**（192 公开 / 228 私有）。

### 2.3 可验证的“代理即评判员”评估框架（Verifiable Agent-as-a-Judge）

- **阶段 1：评估脚本生成**——LLM 基于任务描述 D 和覆盖点 E 生成 Python 评估脚本；受 **API 白名单**（限制为可安全验证的基元）和**参考模板**约束；包含自调试和自我反思循环。
- **阶段 2：分层标准树构建（Rubric Tree G = (V, E)）**——叶节点分为：动作节点（V_act）、感知节点（V_perc）、其他节点（V_other）；节点标记为 **critical**（失败则父节点归零）或 **non-critical**（允许部分得分）。
- **阶段 3：打分的 Gate-then-Average 聚合策略**——内部节点得分公式：
$$s(v) = \begin{cases} 0 & \text{若 } \exists u \in K(v): s(u) < 1\\ \bar{s}_N & \text{若 } \forall u \in K(v): s(u) = 1 \text{ 且 } N(v) \neq \emptyset\\ 1 & \text{否则} \end{cases}$$
  - 任一关键子节点失败 → 父节点归零（gating）；全部关键子节点通过 → 非关键子节点得分取平均（averaging）。
- **报告四项指标**：部分完成度（Partial Completion）、成功率（Success Rate）、动作得分（Action Score）、感知得分（Perception Score）。

## 6. 论文的主要结论与发现

- **发现 1：现有最先进浏览器智能体表现差强人意**——最优智能体（Manus）成功率仅 **8.0%**，人类基线也仅 10%；但 Comet 在部分完成度上领先（48.0%），说明中间推理正确但最终整合能力不足。
- **发现 2：感知（Perception）是比执行（Execution）更严重的瓶颈**——所有系统在 Complex-P 上的得分低于 Complex-A（如 Comet 67.0% vs 58.0%；其他系统多为 23–34%），人类基线则两者均衡（35.0% vs 34.0%）。
- **发现 3：延长推理与任务进度相关，但算力本身不足够**——Comet 和人类耗时较多获得更高部分完成度；但 Browser-Use + GPT-5 花费 15.3 分钟仍只有 15.0% 部分完成度，说明高效行动比单纯多花时间更重要。
- **发现 4：细粒度视觉读取和 UI 状态推断是失败最集中的环节**——执行操作中 node manipulation（0.087）和 date range selection（0.110）得分最低；感知操作中 value reading 得分近零（0.000），expansion state awareness（0.092）严重受损。
- **发现 5：任务难度不由复杂操作数量决定，而由类型决定**——单一图表值读取步骤即可破坏一个简单工作流；领域专用站点（如 cdc.gov 得分 0.033、google.com/flights 得分 0.048）对智能体特别难。

## 7. 优点

- **三维度统一覆盖**：首次在同一基准中联合覆盖跨站点工作流、复杂执行操作和困难视觉感知三个维度，弥补了现有基准的空白。
- **可扩展的任务构建流水线**：通过分解-重组策略，新网站只需注释站点卡片即可自动集成到任务中，无需手工任务工程，支持持续扩展。
- **细粒度的失败诊断**：每个任务显式标注执行点和感知点，评估可以基于显式检查点（而非仅最终答案），准确定位执行或感知的失败环节。
- **可验证的自动评估框架**：从任务结构自动生成分层标准树，配合 URL 校验与确定性检查，兼顾了评估的精确性与可扩展性；经人工验证（κ = 0.84）和跨 judge backbone 验证，结果可靠。
- **严格的质量控制**：多阶段人工审查（提议筛选、实例化质量控制、任务现场执行验证），并报告站点卡片错误分析，保证基准质量。
- **分类体系完整且接地气**：以 Ant Design 组件库为基础制定动作与感知类型分类法，覆盖面广且与实际 Web 应用契合。

## 8. 不足与局限

- **评测系统覆盖有限**：仅评估 8 个智能体系统加 1 个人类基线，未穷尽所有系统/模型变体；论文自述绝对数值属于 2025 年末的快照，非最终排名。
- **任务与领域覆盖有边界**：排除了需要真实交易、账户绑定私密数据、或强真实世界副作用的任务（如实际购买、发送邮件），不覆盖这些场景。
- **自动构建管道的残留噪声**：站点卡片可能遗漏罕见功能、任务可能存在措辞瑕疵；人工审计当前扩缩到 420 个任务可行，但扩展到数万个任务时不可线性扩展。

- **Live-web 非平稳性**：网站布局、内容、功能随时间变化，绝对得分会漂移；虽通过相对时间窗口、范围过滤等多重缓解，但**无法彻底消除这一影响**——基准分数的“保质期”有限，跨时段的分数对比需谨慎解读，且网站改版可能系统性改变某类任务的难度，导致纵向追踪时的混淆变量。

## 9. 论文建议的未来方向

- **基准扩展**：站点卡片流水线具备可扩展性，未来可纳入更多语言、更多垂直领域（如医疗、法律、金融）以及非英语网站，进一步提升覆盖面。
- **任务规模提升**：当前 420 个任务的质量控制依赖大量人工审查，未来可探索更强的自动校验机制（如交叉验证、多模型共识），以支撑数万级任务的大规模扩展。
- **评估框架泛化**：分层标准树与 Gate-then-Average 评分策略可推广到其他复杂交互场景（如桌面应用、移动端 App、代码 IDE），不仅限于浏览器。
- **面向智能体训练的闭环**：论文明确指出，失败最集中的检查点（如值读取、节点操作、日期范围选择）可直接用于指导智能体的训练数据构造或推理时反馈，推动从“评测诊断”到“能力改进”的正向循环。

## 10. 总体评价

- **方法论价值**：CAP 提出的“分解-重组”生成范式，将 108 个网站的碎片信息（功能、动作、感知）组合为跨站点工作流，既保证了任务的真实性，又使失败诊断成为可能，是浏览器智能体评测从“黑盒端到端”走向“白盒检查点”的重要一步。
- **实证价值**：8 个智能体加人类基线的系统评估，揭示了当前前沿模型在真实网页上的显著短板——特别是感知环节的“细粒度值读取”几乎全线崩溃，这一结论对后续模型与数据研发具有直接参考意义。
- **局限认知**：评测覆盖范围（系统数量、任务规模、非英语场景）有限，且 live-web 环境本身不可复现，CAP 更适合作为**相对诊断工具**而非绝对能力排行榜；但其设计哲学和诊断粒度，使其成为当前浏览器智能体评测基准中有鲜明差异化和实用价值的贡献。
