## 摘要
智能体 AI 系统日益依赖云托管的大语言模型进行规划、工具使用和迭代执行，这引发了人们对 API 成本与数据暴露的担忧。个人 AI 设备的进步使智能体能够在本地执行，但设备上有限的资源可能影响任务成功率和性能。现有基准测试不足以系统性地刻画这些在设备、工作负载和部署架构之间的权衡。我们提出了 AgBench，一个基准测试套件和开放工件，用于在个人设备上对智能体 AI 进行可复现评估。借助 AgBench，我们评估了跨智能体工作负载的本地、混合和云执行，考察任务成功率、延迟、云 API 成本和数据暴露。我们的结果基于超过 1.6207 亿个数据点，表明个人 AI 设备可以在本地完成许多智能体任务，但仅本地执行通常比仅云执行具有更低的任务成功率和更长的完成时间，尤其是在并发增加时。仅本地执行消除了云模型 API 成本以及向云智能体暴露敏感信息的问题。混合执行可以提高任务成功率，但其云成本和数据暴露取决于智能体如何划分工作与共享信息。没有任何单一架构在任务成功率、有效吞吐量、云成本和数据暴露方面表现最佳；部署选择应反映预期工作负载和设备能力。AgBench 可在 https://anonymous.4open.science/r/AgBench-2777 获取。

## Abstract
Agentic AI systems increasingly rely on cloud-hosted large language models for planning, tool use, and iterative execution, raising concerns about API cost and data exposure. Advances in personal AI devices enable agents to execute locally, but limited resources on device may affect task success and performance. Existing benchmarks are inadequate for systematically characterizing these trade-offs across devices, workloads, and deployment architectures. We present AgBench, a benchmark suite and open artifacts for reproducible evaluation of agentic AI on personal devices. Using AgBench, we evaluate local, hybrid, and cloud execution across agentic workloads, examining task success, latency, cloud API cost, and data exposure. Our results, drawn from over 162.07 million data points, show that personal AI devices can complete many agent tasks locally, but local-only execution generally has lower task success and longer completion times than cloud-only execution, especially as concurrency increases. Local-only execution eliminates cloud model API costs and sensitive-information exposure to cloud agents. Hybrid execution can improve task success, but its cloud cost and data exposure depend on how agents divide work and share information. No single architecture performs best across task success, goodput, cloud cost, and data exposure; deployment choices should reflect the intended workload and device capabilities. AgBench is available at https://anonymous.4open.science/r/AgBench-2777.

- **两大痛点**：
  - 用户输入与执行上下文需上传云端，带来**隐私/数据暴露**风险；
  - 长流程中反复调用模型导致**高昂 API 成本**。
- **新机遇与代价**：具备专用 AI 加速器与大统一内存的个人 AI 设备（RTX 5090 PC、NVIDIA DGX Spark、AMD Ryzen AI Max+ 395 等）使本地执行成为可能，可消除云 API 成本与数据外泄；但资源受限限制了可用模型规模，可能降低任务成功率、拉长延迟。
- **核心研究问题**：*个人 AI 设备是否已为智能体 AI 做好准备？* 拆解为四个 RQ：
  - Q1：从云迁到端侧对任务成功率的影响？
  - Q2：本地执行是否拖慢智能体工作流？
  - Q3：本地执行能否降低云 API 成本？
  - Q4：本地执行能减少多少云端数据暴露？
- **现有基准的缺口**：
  - *能力型*基准（GAIA、TUA-Bench、Terminal-Bench、MyPCBench）只测任务成败；
  - *系统型*基准（XPerf、OSWorld-Human、AgentSysBench）只测性能与资源开销；
  - 两者均未系统刻画「云 → 个人设备」迁移所引发的**成功率、性能、成本、隐私四维权衡**。

## 二、方法论：AgBench 基准套件

### 1. 核心思想
在同一基准框架内**同时**评估任务能力与执行系统行为，覆盖「设备 × 部署架构 × 并发度」的受控组合，从而量化四维权衡。

### 2. 四步工作流
1. **任务构建**：60 个任务、8 大类，每任务含人类可读指令、隔离执行环境、任务专属验证器（智能体不可见）。
2. **配置设定**：每条配置 = 设备 + 部署架构 + 并发级别；设备硬件用于本地推理与工具执行，架构决定推理位置与协作方式，并发决定同时运行的任务上限。
3. **执行**：智能体反复调用工具、检视结果直至完成或终止；任务在隔离 Docker 容器中运行，但共享 CPU/GPU/内存/存储 I/O 与本地模型服务，以暴露资源竞争。
4. **测量**：捕获任务结果、模型与工具交互、智能体间通信、云端用量与传输数据、系统资源占用。

### 4. 评估设备（2 台）
- **高端工作站**：Intel Core Ultra 9 285K（24 核）、NVIDIA GeForce RTX 5090（32 GB 独显）、128 GB 内存 → 离散 GPU + 独立显存。
- **紧凑型 AI 系统**：AMD Ryzen AI Max+ 395（16 核/32 线程）、Radeon 8060S 集显、128 GB 统一内存（其中 96 GB 划给 GPU，系统可见约 30.5 GB）→ 集成 GPU + 统一内存。

### 5. 四种部署架构（任务环境与工具执行始终留在本地设备）
- **LO（Local-Only）**：本地智能体负责规划与工具调用，推理全本地。
- **CO（Cloud-Only）**：云智能体规划，云 API 推理，工具在本地执行。
- **HCL（Hybrid Cloud-Led）**：**委派式**——云智能体主导，按需将动作委派给本地执行体，本地返回结果。
- **HLL（Hybrid Local-Led）**：**咨询式**——本地智能体主导，必要时向云端咨询推理，云端返回建议后本地继续。

### 6. 推理与智能体配置
- **本地**：Qwen3.8-27B，UD-Q6_K_L 6-bit 量化，llama.cpp（commit 0b5be7e4）；RTX 5090 用 CUDA 12.8.1，Max+ 395 用 Vulkan；启用 Flash Attention、8-bit KV cache、最多 2 个 draft token 的 MTP 投机解码；每设备允许最多 8 个并发模型调用；上下文 65,536 token，单次输出上限 8,192。
- **云端**：DeepSeek V4 Flash，high reasoning effort；上下文 1,000,000 token，单次输出上限 384,000。
- **智能体循环**：Pi Coding Agent v0.84.1；系统提示词全程固定。
- **定价**（用于估算 API 成本，USD/百万 token）：缓存输入 0.0028、未缓存输入 0.14、输出 0.28。

### 7. 度量体系
- **主指标**：
  - 任务成功率（通过任务专属验证器比例）；
  - 完成时间（成功完成任务的墙钟时间）；
  - Goodput（单位基准时间内成功完成任务数）；
  - API 成本（按用量与定价估算，区分成功/失败执行）；
  - 数据暴露率（见下）。
- **诊断指标**：模型与工具执行耗时、智能体间交互、时间戳；输入/输出 token、prefill/decode 时间与吞吐；CPU/GPU 利用率、内存、存储 I/O。
