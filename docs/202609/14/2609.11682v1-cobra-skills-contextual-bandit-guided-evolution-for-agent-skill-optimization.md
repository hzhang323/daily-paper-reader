## 摘要
大语言模型（LLM）智能体可以从先前任务经验中提炼出的可复用技能中受益，然而现有的技能优化方法往往依赖代价高昂的基于执行的评估以及大量任务数据。我们提出 COBRA-Skills，一个高效框架，将技能优化形式化为在动态演化的候选空间上进行的有预算约束的序贯优化。COBRA-Skills 将上下文赌博机引导的优先级排序与基于证据的技能演化相结合，选择性地将评估分配给有潜力或信息量大的候选，同时根据执行反馈持续改进技能种群。在六个异构智能体基准和三个目标模型上，COBRA-Skills 在对比方法中始终取得最强的平均性能，同时相对于 SkillOpt 将优化成本降低 55–58%，且每个基准仅使用 50 个唯一的优化示例。进一步分析表明，COBRA-Skills 对智能体运行框架（agent harness）的变化保持稳健，并且在目标模型自身用于技能生成与改进时仍能有效发挥作用。

## Abstract
Large language model (LLM) agents can benefit from reusable skills distilled from prior task experience, yet existing skill optimization methods often rely on costly execution-based evaluation and substantial task data. We introduce \textbf{COBRA-Skills}, an efficient framework that formulates skill optimization as budgeted sequential optimization over a dynamically evolving candidate space. COBRA-Skills couples contextual-bandit-guided prioritization with evidence-grounded skill evolution, selectively allocating evaluations to promising or informative candidates while continually refining the skill population from execution feedback. Across six heterogeneous agent benchmarks and three target models, COBRA-Skills consistently achieves the strongest average performance among compared methods, while reducing optimization cost by 55--58\% relative to SkillOpt and using only 50 unique optimization examples per benchmark. Further analyses show that COBRA-Skills remains robust to changes in the agent harness and performs effectively when the target model itself is used for skill generation and refinement.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体面对的任务往往共享重复出现的目标、流程、工具与失败模式，因此"技能"（skill）——即可复用的程序性知识（任务指南、推理策略、工具调用流程）——成为一种轻量化的经验载体，可在求解新实例时注入智能体上下文。
- **痛点一：技能获取困难**。人工撰写技能需要大量专家投入；直接用 LLM 参数化知识生成技能，容易产出"看似合理但缺乏依据"的指导，无法稳定提升下游性能。因此近期工作转向用真实执行轨迹与反馈来"落地"（grounding）技能构建。
- **痛点二：优化效率瓶颈**。已有基于"生成—评估—精炼"循环的方法存在双重开销：
  - **候选评估昂贵**：必须真实执行候选技能才能观察其效用，大量预算被浪费在低质量候选上；
  - **技能精炼昂贵**：反复调用 LLM 分析轨迹、诊断失败、合成修改，token 成本高。
- **核心问题**：在有限计算与任务经验（少量任务样本）约束下，如何**选择性地分配候选评估预算**，并**高效复用执行证据**来精炼技能，而不是穷举评估与反复重写。
- **整体含义**：论文将技能优化重新形式化为**动态演化候选空间上的预算化序贯优化问题**，并指出该问题天然契合上下文赌博机（contextual bandit）框架——候选技能是"臂"，其语义嵌入是上下文特征，目标智能体性能是奖励，且候选集合本身随演化而变化。

## 2. 方法论

### 2.1 问题形式化

- 设 $\mathcal{D}_{opt}\subset\mathcal{D}$ 为小规模优化集，$\mathcal{T}_0$ 为无技能初始轨迹。目标是在有限轮数 $T$ 内，从探索过的技能集合 $S_T$ 中找出能泛化到未见实例的技能：

$$s^\star=\arg\max_{s\in S_T}\ \mathbb{E}_{(x,y)\sim\mathcal{D}}\big[\mathrm{Metric}\big(\mathcal{A}(x;s),y\big)\big]$$

- 其中 $\mathcal{A}(x;s)$ 是装配技能 $s$ 后目标智能体的输出。预算以固定优化轮数 $T$ 实例化。

### 2.2 总体框架：闭环设计

- 维护一个**固定大小的候选技能种群** $\mathcal{P}_t$；
- **上下文赌博机**负责"选谁去评估"和"保留谁"（评估分配 + 种群保留）；
- **基于证据的演化**负责"造出什么新候选"（生成 + 精炼）；
- 二者构成闭环：赌博机在当代种群内高效分配评估，演化持续精炼并扩展候选搜索空间。
- 关键设计：**候选评分只来自目标智能体的真实执行反馈**，教学模型 $\mathcal{M}_{teach}$ 只做基于证据的生成与精炼，不参与打分。

### 2.3 赌博机引导的技能搜索

- **语义表示**：每个候选技能用固定嵌入模型编码为 $z_s=\phi(s)$（实验用 Qwen3-Embedding-4B，2560 维，L2 归一化）。
- **神经奖励预测**：轻量两层 MLP $f_\theta$（2560→64→1，ReLU），在累积历史 $\mathcal{H}_{t-1}$ 上用带 L2 正则的均方误差重训：

$$\mathcal{L}(\theta)=\frac{1}{|\mathcal{H}_t|}\sum_{(s_i,z_i,r_i)\in\mathcal{H}_t}\big(f_\theta(z_i)-r_i\big)^2+\beta\|\theta\|_2^2$$

- **LinearUCB 探索奖励**：

$$b_t(z_s)=\nu\sqrt{z_s^\top A_{t-1}^{-1}z_s},\qquad A_{t-1}=\lambda I+\sum_{i=1}^{t-1}z_{s_i}z_{s_i}^\top$$

  语义空间中探索不足的候选获得更大不确定性奖励；被反复评估的技能及其邻域不确定性下降。

- **优先级分数**：$U_t(s)=f_{\theta_{t-1}}(z_s)+b_t(z_s)$。
- 每轮评估 $s_t=\arg\max_{s\in\mathcal{P}_t}U_t(s)$，即把预算投向"有潜力"或"信息量不足"的技能；同一分数也用于种群更新时剪枝。

### 2.4 基于证据的技能演化

- **触发时机**：并非每轮都演化，而是按**对数调度**周期性触发（$t-t_{last}\ge d$ 且 $\log(t/t_{last})\ge\eta$），显著降低 LLM 调用频率。
- **剪枝与补充**：用更新后的 $f_\theta$ 与 $A_t$ 重算优先级，剪掉分数最低的 $m$ 个技能，空缺由新生成候选填补；新技能不继承任何历史奖励，必须重新进入赌博机评估循环。
- **三种演化算子**：
  - **Regeneration（再生）**：仅从原始无技能轨迹 $\mathcal{T}_0$ 独立生成新技能，不依赖父技能，用于引入新搜索方向、维持种群多样性、避免过早收敛；
  - **Rollout Mutation（轨迹变异）**：对当前轮被评估的技能做**局部保守精炼**，以该技能产生的成功/失败轨迹为具体证据；
  - **Crossover（交叉）**：将历史中已评估技能分为高/低表现两组，采样一个强技能作骨架，另一个强技能提供正向证据，弱技能作负向证据，实现"性能接地"的重组，而非直接拼接父技能。
- 算子刻意保守：只做局部、有证据支撑的修改，以保留已从有限经验中学到的有效策略。

### 2.5 算法流程（Alg. 1 文字化）

1. 初始化：优化集 $\mathcal{D}_{opt}$、无技能轨迹 $\mathcal{T}_0$、初始种群 $\mathcal{P}_1$、轮数 $T$、演化参数 $d,\eta$；$\mathcal{H}_0\leftarrow\emptyset$，$A_0\leftarrow\lambda I$，$f_{\theta_0}\equiv 0.5$。
2. 对每轮 $t=1..T$：为 $\mathcal{P}_t$ 中每个技能计算 $U_t(s)$ → 选最高分技能 $s_t$ → 在 $\mathcal{D}_{opt}$ 上由目标智能体评估得 $(r_t,\mathcal{T}_t)$ → 更新历史 $\mathcal{H}_t$ 与设计矩阵 $A_t$ → 重训 NN。
3. 若满足演化调度条件：调用 EVOLVE（剪枝 + 再生/变异/交叉）得到 $\mathcal{P}_{t+1}$；否则种群不变。
4. 返回历史中平均奖励最高的技能。

- **跨模型技能迁移**：3×3 的"优化模型→评估模型"矩阵显示，技能在能力相近的模型之间迁移较为稳定，跨能力层级迁移存在衰减，提示技能中仍含有一定的模型特异性成分。
- **超参稳健性**：探索系数 ν 在 0.03–0.3 区间内性能变化平缓，0.1 附近较优，说明方法对探索强度不敏感，调参负担较低。
- **优化动态**：检查点曲线显示 COBRA-Skills 在早期即以更低成本达到与基线相当或更高的水平，且随轮次继续缓升；每轮优化分数曲线表明种群经剪枝—再生后会出现短暂波动再回升，符合"探索—利用"交替的预期。

## 7. 局限性与需谨慎解读之处

- **算力口径不可迁移**：全文以 API token 计费衡量效率，未给出 GPU/CPU 型号、数量与墙钟时间。对自托管或本地推理场景，"成本降低 55%–58%"的结论不能直接外推；真正决定效率的是 LLM 调用次数与 token 量，这一点论文有间接体现，但缺乏统一的计算口径。
- **教师模型依赖未完全解耦**：主实验使用 GPT-5.5 作为教学模型，成本表中的教师 token 虽显著下降，但绝对成本仍受强模型定价影响；自教学实验缓解但未消除这一疑虑。
- **基线预算不对等**：COBRA-Skills 每基准仅用 50 个唯一优化示例，基线使用 53–170 个，论文以"成本–性能权衡"解释该选择。这使得"更省数据"的结论成立，但也意味着无法排除"基线在其官方更大预算下会更强"的可能，缺少上界对照。
- **统计稳健性有限**：SocialMaze 等基准上的标准误较大（±3.0 至 ±6.8），且部分基准（SearchQA、ALFWorld）上方法间差距接近持平，平均分优势主要由 LiveMath、SpreadsheetBench、SocialMaze 少数基准驱动，单基准结论不宜过度解读。
- **奖励信号设计**：候选评分完全来自目标智能体在 50 例优化集上的执行反馈，奖励噪声、任务难度分布与评估器偏差都会直接传导到赌博机的选择上；论文未系统分析奖励噪声对选择质量的影响。
- **种群与候选规模偏小**：K=10、T=30、每轮剪枝 3 个，属于轻量配置。更大规模下的行为（是否仍能保持低成本、是否出现早熟收敛）未被探索。
- **技能表示假设**：以单一嵌入模型的语义向量作为上下文特征，隐含"语义相近的技能性能相近"的假设；对于风格差异大但语义相近的技能，UCB 奖励可能失真。论文未对该假设做诊断性实验。
- **可复现性信息不完整**：除超参与数据划分外，技能文本模板、演化提示词、奖励归一化方式等关键细节对复现的影响较大，若未完整公开，外部复现难度会上升。

## 8. 总体评价与启示

- **问题刻画到位**：论文把"技能优化"从"反复生成—评估—精炼"的启发式循环，重述为**动态候选空间上的预算化序贯决策问题**，这一视角转换是其主要概念贡献——它把"评估预算分配"和"候选生成"这两件此前混在一起的事明确拆开。
- **方法耦合合理**：赌博机解决"在给定种群内如何花钱"，演化解决"种群本身如何变化"，二者通过同一优先级分数（预测均值 + 不确定性）打通，形成简洁闭环；三种演化算子（再生/变异/交叉）各自承担多样性、局部精炼、性能接地三种功能，分工清晰。
- **证据接地的原则值得强调**：候选评分只来自目标智能体的真实执行反馈，教学模型不参与打分。这一约束避免了"用 LLM 评判 LLM 生成内容"的自我强化循环，是方法可信度的重要来源。
- **效率提升的机制可解释**：教师 token 下降 67%–80% 主要来自对数调度触发演化，而非每轮重写；成本下降来自"少评估低质候选"与"少调用 LLM"两条路径，与设计动机一致，而非纯工程优化。
- **实践启示**：在真实 agent 产品中，若已有一个可执行的评估回路（能对技能打分），则该框架可以直接叠加使用，且对小样本优化集（数十例）即可起效，适合预算受限的迭代场景。
- **可延展方向**：将奖励建模扩展到多目标（准确率/延迟/成本）、把技能表示为可组合的结构化模块而非纯文本、在更大种群与更长轮数下验证、以及在自托管模型上以 FLOPs 口径重新核算效率，都是自然且价值较高的后续工作。
