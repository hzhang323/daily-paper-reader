## 摘要
实际的时间序列预测通常不是一次性模型调用：从业人员必须明确任务、连接数据与模型、融入领域专业知识、评估预测合理性并传达不确定性。专门的预测模型能提供强大的数值预测，但往往依赖固定流程；而通用大语言模型（LLM）智能体则常缺乏面向预测的检查、约束与停止规则。我们提出CastClaw——一种通过面向预测的流程工程构建的人机协同自主预测系统。CastClaw在单一运行时中连接数据、专门模型、分析工具、用户输入以及版本化执行记录。用户以自然语言指定目标、时间跨度、约束与假设。从给定或模型生成的初始预测出发，CastClaw检查时间模式与用户约束；当证据缺失时，它检索上下文、运行一项分析或调用另一模型，或询问用户。随后在明确停止条件下保留、修订或上报结果。输出包含最终预测及记录输入、证据、动作与修订的执行报告。在包含五个数据集的电价场景中，CastClaw在16个基线中取得最低点估计MSE和MAE。Nord Pool案例展示了可审计的工作流。CastClaw还在中国北方2026年1月至6月的省级电力负荷数据上进行了离线验证。

## Abstract
Real-world time-series forecasting is rarely a one-shot model invocation: practitioners must formulate tasks, connect data and models, incorporate domain expertise, assess prediction plausibility, and communicate uncertainty. Specialized forecasting models provide strong numerical predictions but usually operate in fixed pipelines, while general-purpose large language model (LLM) agents often lack forecasting-specific checks, constraints, and stopping rules. We present CastClaw, a human-in-the-loop autonomous forecasting system built through forecasting-oriented harness engineering. CastClaw connects data, specialized models, analytical tools, user input, and a versioned execution record in one runtime. Users specify the target, horizon, constraints, and hypotheses in natural language. Starting from a supplied or model-generated forecast, CastClaw checks temporal patterns and user constraints; when evidence is missing, it retrieves context, runs an analysis or another model, or asks the user. It then keeps, revises, or escalates the result under explicit stopping conditions. The output contains the final forecast and an execution report recording inputs, evidence, actions, and revisions. In this five-dataset electricity-price setting, CastClaw reports the lowest point-estimate MSE and MAE among 16 baselines. A Nord Pool case demonstrates the inspectable workflow. CastClaw was also validated offline on provincial electricity-load data from North China covering January--June 2026.

## 2. 方法论：CastClaw 系统

### 2.1 核心思想

CastClaw 不是一个新的预测模型（backbone），而是一个**面向预测的“流程工程”（harness engineering）系统**。它将数据、专用模型、分析工具、用户输入与版本化执行记录连接在同一运行时中，让系统在“检查—补证—修订—验证”的迭代循环中收敛到最终预测，同时将人类置于决策回路中而非事后反馈环节。

### 2.2 系统架构与关键流程

系统流程分为五个阶段：**意图理解 → 数据画像 → 预测 → 最终答案与评判 → 经验积累**，由执行环境、工具库和状态管理三大服务支撑。

具体运行机制如下：

1. **任务创建与更新（Task Definition）**
   - 用户以自然语言提供目标、预测时域、粒度、历史长度、约束及期望输出；
   - 系统对缺失的必要信息主动提问，而非静默采用隐式默认值；
   - 区分“硬性要求”（hard requirements）与“待检验假设”（hypotheses），并对用户更正加上时间戳；过期的请求会将其相关预测标记为“失效”（stale），但保留仍可用的证据。

2. **经验重用（Experience Reuse）**
   - 预测前可按目标、粒度、时域和时间状态检索历史运行记录与规则；
   - 每条记录标明来源与适用范围，仅作为待检验的“建议”而非现成证据；
   - 与当前数据或硬约束冲突的历史条目将被拒绝。

3. **预测检查与修订（Check & Revise）**
   - CastClaw 加载用户预测或调用注册模型生成初始候选；
   - 从以下几个方面对候选进行系统检查：近期模式匹配、领域约束一致性、上下文变化、模型之间的分歧、用户假设；
   - 当证据不充分时，可采取的操作包括：检索上下文、考察相似历史区间、运行新的分析或模型、尝试候选修订、或直接询问用户；
   - 所有修订必须通过任务规定的**验证指标**与**硬约束**门控，否则候选被拒绝并记录在版本化执行记录中；
   - 存在明确的停止条件：预测已获充分支持、下一步行为预期价值很小、预算耗尽、或必须由专家做出判断。

4. **可执行记录与报告（Execution Report）**
   - 输出 = 最终预测值 + 适用警告 + 执行报告；
   - 执行报告记录请求信息、数据和模型版本、工具输出、用户输入、各测试过的候选预测版本及其验证结果、以及停止决策；
   - 每条证据都标注其来源类型：用户输入、模型输出、检索上下文、或派生分析；
   - 用户输入和硬约束不会被系统静默覆盖。

5. **人类交互机制**
   - 用户可在运行前或运行中干预：修正目标/时域、增加硬约束或限时假设、请求额外检查、或终止运行；
   - 人工修正会使受影响的候选标记为失效，而新假设只作为待检验条件，不直接强制修改预测；
   - 任何预测变更仍需通过验证和一致性检查。

## 6. 主要结论与发现

- **核心结果**：在 5 个电价数据集上，CastClaw 在所有 10 个“数据集-指标”（MSE/MAE）单元格中均取得 16 个基线中的最优值。
- 相对每个数据集上最优基线，MSE 绝对降低幅度：BE 5.5%、DE 30.1%、FR 11.4%、NP 17.7%、PJM 9.7%；MAE 降低：13.9%、20.9%、23.5%、23.5%、11.3%。5 个数据集不加权平均降幅为 **MSE 14.9%、MAE 18.6%**。
- MSE（侧重大幅偏差）与 MAE（反映典型误差）的同步改善说明收益并非由单一误差形式驱动，具有一定的稳健性。
- Nord Pool 案例展示了一个关键设计特性：系统检索到缺失上下文后构造了候选修正，但该候选在验证集上表现**更差**，于是系统按要求**保留用户原始预测**并将决策过程完整记入执行报告——证明了“人有否决权且模型修订需受验证门控”的设计确实运转。
- 作者明确表态：结果支持 CastClaw 是一个**已实现的系统**，而非一个新的预测骨干模型；消融实验与用户研究留作未来工作。

## 7. 优点

- **系统设计理念清晰**：将预测从“模型调用”重塑为“受控流程”，把握了工业预测实际使用的痛点。
- **真正的“人在回路”而非事后反馈**：人类输入贯穿任务定义、证据补充、约束设定和停止决策，且作为执行记录的一部分被结构化保存，可审计性强。
- **验证门控机制**：任何候选修订都必须通过验证指标和硬约束才能替换当前预测，失败候选也保留在记录中，避免盲目“为改而改”。
- **选择性工具调用**：仅在检查发现证据缺口时才做检索/调用其他模型/询问用户，而非不停调用无差别工具，设计上更贴近真实决策成本约束。
- **显式停止条件**：给出可解释的停止依据（证据充分、预期价值低、预算耗尽、需专家判断），使迭代过程有边界。
- **工程可交付**：提供 npm 一键安装（npm install -g castclaw）和交互式演示接口，便于学术交流和实际试用。
- **实验对照设置较扎实**：16 个基线覆盖统计、深度、基础模型、LLM、智能体多个层次。

## 8. 不足与局限

- **统计证据不足**：只报点估计，无显著性测试、置信区间和多次重复运行结果，无法排除随机性；论文自己也承认这一点。
