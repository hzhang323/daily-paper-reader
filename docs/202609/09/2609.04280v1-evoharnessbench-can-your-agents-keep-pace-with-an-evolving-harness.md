## 摘要
现代基于LLM的智能体通过一个由工具、可复用技能和专家智能体组成的工具集（harness）来运作，该工具集塑造了它们可观察和可执行的内容。在实践中，随着新能力的加入，这一工具集不断演化。我们引入了EVOHARNESSBENCH，这是一个基准测试，用于在受控的工具集演化下评估智能体，涵盖三个维度（工具、技能和智能体）。与现有的智能体持续学习基准不同——后者通常将非平稳性（即随时间变化的内容）置于任务流中，而保持工具集固定——EVOHARNESSBENCH将非平稳性置于外部提供的工具集本身。它包含17个由基于验证器的基准确定性构建的多阶段工具集流，包含802个任务、520个工具、42个技能和62个智能体。我们评估了两个互补的设置，对应工具集演化的核心挑战：部署评估，它隔离了随着工具集扩展，先前可访问能力的保持情况；以及自演化适应评估，它测试当引入新能力时，累积的经验是否仍然有用。我们的结果揭示了三个持续存在的差距。首先，仅工具集扩展就可能降低先前已解决任务的性能，产生由工具集引发的遗忘。其次，自演化适应的收益在工具集演化的不同阶段、能力维度和环境中不一致。第三，保持和适应可能朝着不同方向拉动：保留早期能力不一定能改善对新引入能力的适应，反之亦然。这些结果将工具集演化确立为构建能够跟上演化工具集同时保持先前有效行为的智能体所面临的一个独特挑战。

## Abstract
Modern LLM-based agents operate through a harness of tools, reusable skills, and specialist agents that shapes what they observe and what they can do. In practice, this harness continually evolves as new capabilities are added. We introduce EVOHARNESSBENCH, a benchmark for evaluating agents under controlled harness evolution across three axes (tools, skills, and agents). Unlike existing continual-learning benchmarks for agents, which typically place non-stationarity (i.e., what changes over time) in the task stream while keeping the harness fixed, EVOHARNESSBENCH places non-stationarity in the externally supplied harness itself. It contains 17 multi-stage harness streams constructed deterministically from verifier-based benchmarks, comprising 802 tasks, 520 tools, 42 skills, and 62 agents. We evaluate two complementary settings corresponding to the central challenges of harness evolution: deployment evaluation, which isolates retention of previously accessible competence as the harness expands, and self-evolving adaptation evaluation, which tests whether accumulated experience remains useful as new capabilities are introduced. Our results reveal three persistent gaps. First, harness expansion alone can degrade performance on previously solved tasks, producing harness-induced forgetting. Second, gains from self-evolving adaptation remain inconsistent across stages of harness evolution, capability axes, and environments. Third, retention and adaptation can pull in different directions: preserving earlier competence does not necessarily improve adaptation to newly introduced capabilities, and vice versa. These results establish harness evolution as a distinct challenge for building agents that can keep pace with an evolving harness while preserving previously effective behavior.

## 1. 论文核心问题与整体含义（研究动机与背景）

- **背景**：基于 LLM 的智能体系统远不止“模型 + 提示词”，它被嵌入在一个 **harness（工具集/执行框架）** 中——包括可以调用的**工具（tools）**、可以复用的**技能（skills）**、可以协作的**其他智能体（agents）**。这个 harness 同时决定了智能体“能看到什么”和“能做什么”。
- **现实问题**：在实际部署中，harness 本质上是**非平稳（non-stationary）**的——新工具、新技能、新智能体会不断加入。例如 Salesforce Agentforce 生态的持续增长、OpenAI 公共技能仓库的持续更新与删减，都说明 harness 演化是已部署系统的常态属性，而非偶然的边界情形。
- **现有基准的盲区**：已有智能体基准大致分为三类，但均未直接评估 harness 演化带来的性能变化：
  1. **静态 harness 基准**（如 API-Bank、τ-bench、MultiAgentBench）：工具集固定，无演化；
  2. **自演化智能体基准**（如 SkillLearnBench、SkillFlow）：能力增长由智能体自身驱动（内演化），而非外部施加；
  3. **持续学习基准**（如 AgentCL、ContinualBench）：非平稳性放在**任务流**中，harness 保持固定。最接近的是 CMRBench，但它只把演化放在外部模型池，只评估路由决策，不做端到端执行。
- **提出的核心挑战**：harness 演化带来两个既相互独立又相互交织的难题：
  1. **保留（Retention）**：harness 扩展后，此前能解决的任务是否仍能解决？所需能力仍在，但嵌入在更大的候选池中，先前成功的调用路径可能被“淹没”，造成 **harness 诱导的遗忘（harness-induced forgetting）**——模型参数并未改变，纯粹因外部能力池扩大而导致旧任务性能下降。
  2. **基于累积经验的适应（Adaptation under accumulated experience）**：若系统具备自演化适应能力，其在早期较窄 harness 下积累的记忆、技能、提示词等持久化产物，在新能力引入后可能变得过时，甚至误导执行方向。
- **论文的核心主张**：harness 演化是一个区别于任务漂移的、独立的智能体评测维度，需要专门的方法论来度量与优化。

## 2. 提出的方法论：EVOHARNESSBENCH

### 2.1 核心思想

- 将非平稳性从“任务流”转移到“外部施加的 harness”上：**任务内容保持不变**，沿工具、技能、智能体三个轴，受控地让可用能力池逐阶段扩展。
- 设计**外层 harness 演化（outer harness evolution）** 与可选的**内层自演化适应（inner self-evolving adaptation）** 两个层次，从而分别隔离两类挑战。

### 2.2 形式化定义与构造管线

- **Harness 流（Harness Stream）**：一个嵌套序列 H₁ ⊆ H₂ ⊆ ⋯ ⊆ H_T，每个 H_t 是第 t 阶段暴露给智能体的能力集合；阶段之间扩展，阶段内固定。
- **任务分配**：每个任务为三元组 (xᵢ, yᵢ, Cᵢ)，即用户任务、可验证结果（verifier-checkable outcome）和隐藏的真实能力标注。任务被分配到最早可解决该任务的阶段，满足两个构造保证：
  - **可行性（Feasibility）**：Cᵢ ⊆ H_{tᵢ}（所需能力在分配阶段均可用）；
  - **新能力压力（New-capability pressure）**：Cᵢ ∩ (H_{tᵢ} ∖ H_{tᵢ−1}) ≠ ∅（任务要求至少一个该阶段新引入的能力）。
- **四步确定性构造管线**：
  1. **能力标注**：工具轴直接继承源基准的 oracle 工具标注；技能轴通过规则从系统提示中挖掘隐藏参考技能（非 LLM 生成）；智能体轴通过所有权映射 η 将工具分组成实体级专家智能体；
  2. **频率排序发布**：按能力在任务中的使用频率排序，高频“核心”能力先发布，低频“长尾”能力后发布；
  3. **累积 harness**：H_t := {c ∈ U : r(c) ≤ t}，能力一旦引入就不删除、不修改；
  4. **任务分配**：tᵢ := max_{c∈Cᵢ} r(c)，即任务分配给其最晚所需能力被释放的阶段。
- **该管线是确定性的**，不需要 LLM 生成任务，也不需要人工验证，可应用于任何具有可验证任务与能力标注的基准。

### 2.3 三类能力轴的构造差异

| 轴 | 能力标注来源 | 评测特点 |
|---|---|---|
| **工具** | 直接使用 oracle 工具标注 | 智能体收到完整累积工具目录（非裁剪列表）；后期阶段同时包含有用新工具和越来越多的干扰工具 |
| **技能** | 规则挖掘隐藏参考技能，再通过验证器状态关键词匹配关联任务 | 技能不注入提示词；智能体必须从增长的能力池中检索并调用相关技能 |
| **智能体** | 将工具按所有权映射分组为实体级专家智能体 | 主导智能体无直接工具访问权，需从累积智能体池中选取、委派并协调合适的专家，跨实体任务需要多智能体委派 |

### 2.4 两种互补评测模式

1. **部署评估（Deployment evaluation）**：阶段间无持久状态；每阶段用全新系统实例在累积测试集上评测。此模式隔离 harness 扩展本身的影响——**性能下降纯粹是 harness 诱导的**。
2. **自演化适应评估（Self-evolving adaptation evaluation）**：系统维护跨阶段演化的持久状态 z_t（如记忆、技能、提示词、路由策略）；每阶段可用适应集更新 z_t 后再评测。此模式检验累积经验在新能力引入后是否有用、是否过时。

### 2.5 评测指标

- **性能矩阵 P ∈ R^{T×T}**：下三角矩阵，P_{t,τ}（τ ≤ t）表示任务队列 τ 在 harness 阶段 t 下的准确率。
- **后向迁移（BWT）**：比较各队列最终阶段与引入时性能的差异，负值表示遗忘。
- **前向迁移（FWT）**：度量第 i 阶段自演化是否提升了该阶段新任务的性能，负值表示适应过程反而有害。
- **累积得分（ACC）**：最终阶段的微平均准确率。
- **运行成本**：token 使用量、工具调用次数、延迟等。

  - 记忆内容消融（原始轨迹 vs. 结构化推理、成功/失败轨迹筛选、是否加工具 schema）；
  - 转移指标（FWT/BWT）分轴报告；
  - 额外的技能学习方法对比（7 种方法）与智能体委派质量分析。
- **充分性判断**：整体而言实验设计**较为充分且客观**——构造管线确定、评测分离（适应集与测试集不相交）、使用验证器而非 LLM 评判、多个种子重复并报告标准差。相较同类基准，消融维度丰富，有机制层面的分析（委派漂移、技能调用率、技能库重叠度等）。
- **客观性**：Claude Code 因底层模型不同被排除在主对比之外单独报告，GPT-5.5 仅用于特定分析，主对比在受控 GPT-5 体系内进行——这种做法增强了公平性。ALE 与 EOG 的跨环境对比也有效支撑了“环境依赖性”结论。

## 4. 主要结论与发现

### 4.1 工具演化轴

- **部署层面**：较宽的工具目录意外地**提升了准确率**（对比任务专属条件），但 token 使用量大幅增加——更大的目录不只是干扰源，智能体能从中受益，但代价是更多的搜索与执行。
- **自演化适应增益不一致**：EOG 上 MemToolAgent（38.6% Pass）显著超过部署基线（30.2%），但 ALE 上多数方法接近或低于基线。
- **转移现象**：部署 BWT 为负（工具扩展导致遗忘）；适应可改善保留（GEPA、Meta-Harness 实现正 BWT），但在 ALE 上 FWT 降至 −28.5%/−11.1%——适应过程可能对新任务产生负面干扰。
- **记忆表征很重要**：结构化记忆（MemToolAgent、ReasoningBank）优于原始轨迹回放；对 ReasoningBank 加显式工具 schema 反而降低性能（36.9%→30.3%）；成功与失败轨迹单独使用效果相近。

### 4.2 技能演化轴

- **部署层面**：技能池扩大的直接干扰很小——因为技能需先被检索和启用，而非像工具那样持续可用。
- **适应层面**：GEPA 在 EOG 上增益最明显（18.9%→24.1%），多数方法效果有限且跨环境不一致；基于记忆的方法在技能轴上表现不佳甚至强烈负迁移（MemToolAgent 跌至 4.4%）。
- **技能启用是核心瓶颈**：默认 GPT-5 系统几乎不调用任何提供技能（0%）；GPT-5.5 在任务专属条件下启用 82%；任务专属 GEPA 可将 GPT-5 的启用率提升至 31%——技能是否被使用主要取决于模型与适应策略。
- **技能学习**：基于执行经验与迭代反馈的方法最优（Batch Teacher Feedback 22.1%）；朴素生成（One-shot 11.5%）比不学任何技能（16.9% Pass）还差。分阶段累积学习（22.1%）比一次性获得全部经验（23.6%）更难。

### 4.3 智能体演化轴

- **部署层面**：智能体池扩展的效果强烈依赖环境——EOG 上提升（6.5%→8.8%），ALE 上下降（5.3%→4.2%）。
- **适应层面**：EOG 上获益最大（Meta-Harness 从 8.8% 提升至 18.5%），ALE 上多数方法仍徘徊在基线附近。
- **遗忘最严重**：ALE 部署 Codex 的 BWT 达 **−34.7%**，是三个轴中观测到的最强 harness 诱导遗忘。
- **机制归因**：
  - 适应主要提高**委派完整性（recall）** 而非选择性（precision 已在 ~90%）；条件于到达所有必需智能体后，仍有 78–86% 的试验失败——协调与执行是更深层的瓶颈。
  - 被遗忘任务的委派漂移明显大于保留任务（13%→25%）；遗忘更多来自**先前成功的委派覆盖断裂**，而非新智能体的干扰接管。
  - 适应上下文方面，对 Meta-Harness 而言，从开始就暴露最终完整智能体池（无演化轨迹）效果最好（20.3%）——变化的智能体序列本身（而非池大小）是学习持久协调行为的主要难点。

### 4.4 跨轴汇总

| | 工具 | 技能 | 智能体 |
|---|---|---|---|
| 部署扩展效果 | 准确率↑，成本↑ | 影响很小 | 高度依赖环境 |
| 最大 harness 诱导遗忘 | −5.3% | −4.0% | **−34.7%** |
| 最佳适应增益 | +27.8%（MemToolAgent） | +27.5%（GEPA） | +110.2%（Meta-Harness） |
| 最佳适应上下文 | 任务专属 | 任务专属 | 初始即给完整最终池 |
| 观测瓶颈 | 提取有用的工具经验 | 启用正确的技能 | 平衡委派覆盖与选择性 |

- **课程式结论**：
  1. **部署层面**：仅 harness 变化本身就制造保留问题——模型参数与持久状态均未更新，旧任务性能仍会下降，且机制因轴而异；
  2. **适应层面**：有效的适应既取决于 harness 轴，也取决于适应发生的上下文；内部适应不能独立于外部 harness 演化来优化；
  3. **迁移层面**：适应增益不蕴含保留增益，反之亦然——两者应沿 harness 轨迹分别评测，聚合指标会掩盖行为差异。

## 5. 论文优点

1. **问题定位新颖且实用**：首次将“外部施加的 harness 演化”确立为独立评测维度，紧密对应真实部署场景，填补了任务流漂移与智能体自演化之间的空白。
2. **构造管线严谨可控**：从现有基准出发、完全确定性的管线（无需 LLM 生成或人工标注），可复现、可扩展；嵌套累积的流构造确保“可行性 + 新能力压力”两个核心属性。
3. **评测协议设计精巧**：部署评估与自演化适应评估分离，FWT/BWT/ACC/成本多维指标配合下三角性能矩阵，能同时定位“何时变差、影响新旧任务中的哪些、为什么”。
4. **覆盖全面**：三轴 × 两环境 × 多种 SAS/MAS × 三种适应家族 × 丰富的记忆/上下文消融，规模在同类基准中居前（802 任务、1510 样例、17 条流）。
5. **机制分析深入**：不满足于聚合性能比较，进一步剖析了委派漂移、技能启用率、技能库覆盖重叠、委派质量与端到端成功的关系等细粒度机制。
6. **跨轴对比有洞察力**：发现不同能力轴的遗忘机制截然不同（工具=行动空间扩大、技能=检索启用、智能体=委派覆盖），并总结出“保留与适应并不总是同向”的重要洞见。
7. **评测公平性考量**：任务专属参考条件提供了可靠基线；Claude Code 因模型混杂单独报告；重复实验报告标准差；评估使用 verifier 而非 LLM 评判。

## 6. 不足与局限

1. **演化只覆盖“扩展”，未涉及修正、删除与替换**：EVOHARNESSBENCH 的所有 harness 流都是单调嵌套的（H₁ ⊆ H₂ ⊆ ⋯ ⊆ H_T），能力一旦引入便永不撤下。然而真实部署中工具版本升级、接口 deprecated、被安全漏洞强制下架、以及被更优工具替代等现象同样常见。这类“非单调演化”可能引发与“扩展”截然不同的失败模式（例如依赖已删除工具的调用崩溃），论文对其完全没有覆盖，使得基准对现实中“工具集收缩与变更”场景的描述能力受限。

2. **适应方法被限定在“模型权重不变”的推理层**：论文将全部自演化方法限制为记忆、提示词或代码层面的更新，明言不涉及模型训练。这个约束保证了内部效度，却回避了一个重要问题：如果允许在 harness 演化后用新数据对模型做持续微调或参数高效更新，保留与适应的权衡是否会呈现完全不同的规律？当前结论因此只对“无训练”的部署架构成立，对支持在线学习的系统普适性有限。

3. **三轴上的演化粒度与难度不均衡**：工具轴只增加目录大小；技能轴额外引入“检索—启用”环节；智能体轴则增加委派与协调。这三个轴的认知负荷并不对等，但论文以几乎相同的评测协议直接比较结果。智能体轴最优适应增益高达 +110.2%、而部署遗忘也高达 −34.7%，或许部分来自轴间任务构成的固有差异，而非本质上的轴特性，跨轴结论的解释力度有所折扣。

4. **隐蔽参考技能的“规则挖掘”做法可能对方法论边界造成限制**：技能轴没有像工具轴那样使用真实技能标注，而是先借助 verifier 状态关键词匹配反向挖掘隐藏技能，再通过关键词回应配到任务。这种“关键词近似”可能引入噪声标签：技能 C 在中间步骤确实被调用过，但它未必是完成该任务的必要能力。更干净的评估应当用带 oracle 技能标注的源基准来构造。

5. **短视的构造保证可能高估前向难度**：论文在构造任务分配时隐含假设——智能体只在“刚引入最大所需能力”的阶段遭遇该任务，没有考虑“较晚阶段中，智能体此前积累的技能/经验能更高效地完成旧任务”这一前向收益，其 FWT 指标因此在定义上便偏向于揭示负迁移。测试集阶段内固定、阶段间全部累积的无重复评测，虽然可复现性好，但更接近“竞赛式评测”而非“交互式生命周期评估”，与真实部署中任务与 harness 同时漂移的纠缠状态仍有距离。

6. **环境难度天花板有限**：尽管 EOG 与 ALE 覆盖面不错，两者的任务仍然集中在“受限于 verifier 可判定输出的业务软件操作”上。对于需要开放式探索、创造性设计、或需要真实用户反馈才能验证的智能体任务，当前基准完全无法描述——harness 演化带来的干扰和记忆过时问题在这些环境中可能更严重，甚至机制完全不同。

7. **将“频率排序”作为构建流的唯一发布顺序，缺少反事实验证**：论文按通用使用频率发布能力（高频先发布、低频后发布），但未与随机排序、反向排序（低频先发布）等替代顺序做消融比较。因此无从判断观测到的“harness 诱导遗忘”在多大程度上是候选池规模扩大造成的，在多大程度上与“旧能力是新能力的子集还是超集”这一结构性顺序有关。这使得“最严重遗忘出现在智能体轴”这一结论的稳健性缺少对照支撑。

8. **缺乏对自演化方法运行成本与收益的系统权衡分析**：论文分别报告了消耗/收益指标，但未将 token/延迟成本与 Pass 提升量化到同一个决策框架下（例如“效率前沿”）。考虑到一个增加 25.7 小时适应成本但准确率提升 8% 的系统，与一个仅增加 1 小时成本但提升 6% 的系统相比，实用性可能是相反的，读者无法从现有表格推断出这类取舍。

9. **实验统计功效与报告细节有待加强**：尽管文中多处报告“X 与 Y 之间差异显著”，但未提供显著性检验的方法说明（是否采用配对检验？样本量是多少？）；多数主表结果来自每条件若干种子，论文未披露每种子覆盖的具体任务实例数，也未对“GPT-5、Codex、Claude Code 三种底层模型能力差异”如何与 harness 交互做更系统、更完整的三方比较（Claude Code 被彻底排除在主分析外）。这使得结论生态效度打了折扣。

10. **缺少一条“动手做”的洞察闭环**：论文最终停留在“发现问题”层面——指出 harness 演化会造成遗忘、适应策略在多轴上的失败模式各不相同。但并未给出任何一般化的实践指引（例如：应当为哪些工具提供结构化记忆？多智能体系统中，是否可以将委派覆盖的维护抽成专门的模式？技能要不要自动注入？）。对一个定位在评测的论文来说这不一定是缺陷，但评测之外若能给出针对性的 mitigations 验证，会让论文价值大幅提升。

## 7. 总体评价

EVOHARNESSBENCH 是近两年多智能体与智能体工具使用评测领域中最值得关注的一项实证工作。它捕捉了一个真实部署中普遍存在、却长期被基准忽略的维度——外部 harness 的持续演化——并用相当严谨的受控构造将其分离为可测试的科学问题。它在规模设计、机制分析深度与跨轴系统性上都表现出色，实验结果提供了大量可供后续研究者复用的反直觉现象（“扩展目录反而提升准确率”“委派覆盖断裂是记忆漂移的主因”“技能启用率才是核心瓶颈”等）。

其最突出的贡献并非某一条具体发现，而是证明了 **“保留”“适应”“前向迁移”三者无法通过任何单一聚合值来刻画，必须沿着 harness 轨迹以矩阵式协议分别追踪**——这为未来智能体生命周期监控与评测提供了方法论底座。

当然，单调扩展假设、无训练约束与验证器能力的上限也定义了该基准的适用边界。整体而言：**这是一篇提出问题先行、方法精致、执行扎实、结论具有强工程启发价值的高质量基准论文**，值得对这个方向感兴趣的每一位研究者仔细研读。
