## 摘要
大语言模型（LLM）智能体在复杂网页导航任务上表现出强大性能，但在用户意图欠明确、偏好异质的现实场景中仍显脆弱。在实践中，用户很少提供显式画像，这要求智能体从隐式信号中推断潜在偏好。尽管这一问题对部署至关重要，但现有基准在很大程度上尚未充分探索这一设定。为填补这一空白，我们提出 AdaptArena，一个通过隐式偏好推断来评估 Web 智能体测试时个性化的基准。AdaptArena 包含 480 个任务，涵盖单一偏好和双重偏好场景。每个评估任务都必须通过检索并利用最相关的、隐式编码了目标偏好的历史用户轨迹来解决。此外，我们提出 AdaptiveAgent，一个基于检索的框架，用于对隐式偏好推断进行标准化评估。实验揭示了显著的性能差距：能够访问真实偏好的 oracle 智能体达到了 82.92% 的成功率，而使用我们框架的受评估 LLM 智能体最高仅达到 15.62%。此外，我们发现正确推断用户偏好是任务成功的必要条件，但并非充分条件，因为即使智能体与目标偏好一致，下游网页交互中的执行失败仍然是一个显著瓶颈。这些发现凸显了隐式偏好推断和稳健的动作 grounding 是部署可靠、面向用户的 Web 智能体的关键挑战。我们发布了代码：https://github.com/McGill-NLP/web-agents-test-time-adaptations

## Abstract
Large language model (LLM) agents have demonstrated strong performance on complex web navigation tasks, yet they remain brittle in real-world settings where user intentions are underspecified and preferences are heterogeneous. In practice, users rarely provide explicit profiles, requiring agents to infer latent preferences from implicit signals. Despite its importance for deployment, this problem setting is largely underexplored in existing benchmarks. To address this gap, we introduce AdaptArena, a benchmark for evaluating test-time personalization of web agents via implicit preference inference. AdaptArena consists of 480 tasks, featuring both single-preference and double-preference scenarios. Each evaluation task must be solved by retrieving and leveraging the most relevant historical user trajectory that implicitly encodes the target preference. In addition, we introduce AdaptiveAgent, a retrieval-based framework for standardized evaluation of implicit preference inference. Experiments reveal a substantial performance gap: while oracle agents with access to ground-truth preferences achieve an 82.92% success rate, the evaluated LLM agents using our framework reach at most 15.62%. Furthermore, we find that correctly inferring user preferences is necessary but not sufficient for task success, as execution failures in downstream web interactions remain a significant bottleneck even when agents align with the target preference. These findings highlight implicit preference inference and robust action grounding as key challenges for deploying reliable, user-facing web agents. We release our code: https://github.com/McGill-NLP/web-agents-test-time-adaptations

## 1. 核心问题与整体含义（研究动机与背景）

- **现实痛点**：LLM 智能体在复杂网页导航任务上表现强劲，但在真实部署场景中仍很脆弱——用户意图往往欠明确、偏好高度异质，且**极少提供显式用户画像**，智能体必须从隐式行为信号中推断潜在偏好。
- **现有研究缺口**：
  - 自改进/探索类工作提升了智能体对新网站的鲁棒性，但忽略了**用户行为多样性**这一关键维度。
  - 已有个性化评测基准存在不现实之处：PersonalWAB 依赖显式文本画像，CUPID 依赖直接口头反馈，Persona2Web 主要关注静态历史下的查询消歧，均未真正评估"测试时从历史交互轨迹中检索并运用隐式偏好"的能力。
- **研究定位**：论文提出 **AdaptArena**，评估 Web 智能体的**测试时个性化（test-time personalization）**，即在固定模型参数、不做梯度更新的前提下，让智能体在推理时依据用户历史轨迹调整行为，以适应隐式偏好。

## 2. 方法论

### 2.1 核心思想

- 采用**两阶段评估范式**，将"偏好获取"与"测试时评估"解耦：
  - **阶段一（轨迹收集）**：在显式偏好条件下收集用户交互轨迹，构建编码偏好的用户历史。
  - **阶段二（部署）**：在新任务中移除所有显式偏好信息，智能体只能从用户历史中推断相关偏好并据此行动。
- 提出 **AdaptiveAgent** 框架，将偏好推断与任务执行显式分离，仅以历史交互轨迹作为监督来源，不假设可获取任何金标或预重建画像。

### 2.2 关键技术细节

- **基准构成（AdaptArena）**：
  - 共 **480 个任务**，单一偏好与双重偏好各占一半。
  - 覆盖三个 WebArena 环境：电商商店、Reddit 讨论论坛、OpenStreetMap。
  - 通过 **BrowserGym** 平台交互，提供可访问性树、截图与提示接口。
  - 定义 **10 个用户 persona**，每个 persona 由同一套 **12 个偏好类别**刻画，并跨三个环境落地。
  - 轨迹收集阶段使用 **Qwen-3-VL-32B-Thinking** 作为"用户行为生成器"，共构建 **120 个任务/轨迹**（每 persona 12 个）。
  - 每条轨迹的标注由 **Persona Trait（显式偏好）** 与 **General Instruction（偏好无关任务目标）** 组成。

- **AdaptiveAgent 检索与推断流程（文字化算法）**：
  1. 将任务指令编码到与截图共享的嵌入空间（**CLIP ViT-B/32** 文本编码器）。
  2. 在用户历史轨迹截图的 **FAISS 内积索引**中做相似度检索，找到最相似的截图及其所属轨迹，记录步索引 k。
  3. 将已选轨迹从候选池移除，**重复一次**，共检索 **2 条轨迹**，以保证多样性。
  4. 对每条轨迹重建 **前缀**（从初始步 s0 到选定步 sk），将所有前缀截图拼接为统一图像序列。
  5. 将截图序列（base64 编码）输入 **多模态偏好提取器（GPT-5-nano）**，要求其仅依据可观察交互模式，以第一人称输出简洁偏好描述（如"I prefer..."）。
  6. 将推断偏好以辅助上下文块（`<image_summary>`）注入下游 Web 智能体提示，与任务指令、观测历史、动作空间规范共同构成输入。
  7. 所有嵌入与 FAISS 索引缓存至磁盘，避免重复计算。

- **评估指标**：
  - **任务成功率（Task Success Rate）**：功能性自动评估器返回二元标签，采用**参考答案**（字符串匹配）或**参考程序**（指定参考 URL、JavaScript 定位器与期望内容，做精确/部分匹配）。
  - **偏好对齐分数（Preference Alignment Score）**：由 **Gemini-3-Flash** 作为 LLM 评判者，依据完整交互轨迹与目标偏好描述，判断轨迹是否与偏好一致；并用 Cohen's κ 验证与人类标注的一致性。

## 3. 实验设计

- **数据集/场景**：三个 WebArena 环境（Shopping、Reddit、Map），共 480 个部署任务；轨迹收集阶段 120 条用户轨迹。
- **Benchmark**：AdaptArena 本身即为新提出的基准。
- **对比的智能体设计与基线**：
  - **No Profile**：不提供用户历史，仅凭任务描述与环境观测。
  - **Reconstructed Profile**：联合检查某用户全部轨迹，用 GPT-5 总结其想法与动作以重建画像；该过程实际部分接触金标偏好，属"半特权"基线（平均覆盖率 51.67%）。
  - **AdaptiveAgent（本文方法）**：无任何金标偏好信号，仅靠推理时轨迹检索。
  - **User-Centric（上界）**：提供完整金标用户画像，需自行判断哪个偏好与任务相关。
  - **Oracle（上界）**：直接给出任务所需的单一金标偏好，隔离"应用偏好"的能力。
- **评测的六个 backbone 模型**：Gemini-3-Pro、Gemini-3-Flash、GPT-5.4、GPT-5-mini、Qwen-3.5-27B、Qwen-3-VL-32B-Thinking。
- **消融实验**：
  - **跨用户轨迹分配（cross-user trajectory assignment）**：将用户 Uj 的轨迹条件化到用户 Ui 的任务上，并刻意交换偏好最矛盾的用户轨迹。
  - **单偏好 vs 双重偏好**对比分析。
  - **检索质量分析**：按偏好类别计算 recall@1 / recall@2。
  - **人类–LLM 一致性研究**：2 名标注者对 90 个 episode（3 个模型各 30 个）独立标注。
  - **执行级失败分类**：Action Failure、Termination Failure、Navigation Loop、Other。

## 4. 资源与算力

- 论文明确说明所有实验（部署阶段与 AdaptiveAgent 框架）均在 **NVIDIA A100（80GB）GPU** 上执行，强调大显存对大规模多模态输入处理是必要的。
- 单个 AdaptiveAgent 配置在全部基准任务上运行一次约需 **10–12 小时**。
- **未明确说明**：GPU 的具体数量、是否使用分布式训练、以及总 GPU 小时数。论文未涉及模型训练（方法本身不做参数更新），因此算力主要消耗在推理与评测。

## 5. 实验数量与充分性

- **实验规模**：480 任务 × 6 个 backbone × 5 种偏好可用性设置，外加多项专项分析，整体规模较充分。
- **覆盖维度**：
  - 偏好可用性梯度（无画像 → 重建画像 → 检索推断 → 完整画像 → 单一金标偏好）。
  - 偏好组合复杂度（单偏好 vs 双偏好）。
  - 跨域拆分（Shopping / Map / Reddit）。
  - 偏好类别细粒度（12 类，含检索召回与对齐分数的交叉分析）。
  - 检索质量与下游阶段的解耦分析。
  - 跨用户轨迹错配消融。
  - LLM 评判者的人类一致性验证（κ=0.80/0.87，人类间 κ=0.93）。
- **客观性与公平性**：
  - 使用统一 BrowserGym 超参数与温度设置（temperature=1.0），所有 backbone 在同一框架下评测。
  - 消融实验设计巧妙：保留轨迹分布与任务格式，仅破坏"用户—轨迹"对应关系，从而排除任务重叠或数据集伪影带来的收益。
  - LLM 评判者通过人类标注验证，可靠性有据。
  - **潜在偏差**：Reconstructed Profile 基线部分接触金标偏好，论文已主动标注其为"半特权"基线，解释较透明；轨迹收集模型 Qwen-3-VL-32B-Thinking 与受评 backbone 同族，存在风格偏置风险，但该 backbone 反而取得最低成功率，论文据此论证偏置影响有限。

## 6. 主要结论与发现

- **巨大性能差距**：Oracle 智能体最高 **82.92%** 成功率，而 AdaptiveAgent 下受评 LLM 智能体最高仅 **15.62%**；隐式偏好推断是关键瓶颈。
- **AdaptiveAgent 表现接近半特权基线**：尽管无金标信号，其表现与 Reconstructed Profile 相当（如 GPT-5.4：12.71% vs 14.17%；Gemini-3-Pro：15.62% vs 17.71%），且始终优于 No Profile（7.29%–9.17%）。
- **单偏好→双偏好一致退化**：所有模型在双偏好任务上大幅下降，差距达 **10.83–15.42 个百分点**（如 GPT-5.4 从 20.42% 降至 5.00%），说明组合式个性化是系统性瓶颈。
- **偏好对齐 ≠ 任务成功**：对齐分数（22.50%–29.79%）普遍高于成功率（10.42%–15.62%）；即使对齐正确，条件成功率也仅 32%–52%。正确推断偏好**必要但不充分**，执行失败是独立瓶颈。
- **检索并非主要瓶颈**：recall@2 达 **71.88%**（单偏好 77.50%，双偏好 66.25%），但下游对齐与执行损失严重，大部分信号在检索后阶段被丢弃。
- **偏好类别难度分化明显**：Location、Phone、Diet、Brand、Reddit Forum 检索 recall@2 达 100%；而 Product Sorting（35.0%）与 Wishlist vs. Cart（5.0%）检索极差，反映视觉检索难以区分"渲染状态相似、仅操作不同"的偏好。
- **执行失败模式因模型而异**：Gemini-3-Pro 与 Qwen-3.5-27B 以 Termination Failure 为主（44.29% / 46.27%），GPT-5-mini、GPT-5.4、Qwen-3-VL-32B 以 Action Failure 为主（46.75% / 37.68% / 40.51%）。
- **跨用户错配显著降效**：将轨迹分配给不匹配用户后，成功率回落至接近 No Profile 水平，证明收益依赖正确对齐的用户特定信号。

## 7. 优点

- **问题设定贴近真实**：摒弃显式画像与口头反馈，聚焦从行为历史推断隐式偏好，切中实际部署痛点。
- **两阶段解耦范式**：将偏好获取与测试时评估分离，兼顾真实性与可复现性，避免长周期交互协议带来的成本与不可控性。
- **框架简洁可复现**：AdaptiveAgent 不依赖参数更新，检索流程确定性强（CLIP+FAISS 对全部 backbone 一致），便于标准化比较。
- **指标设计立体**：同时测量任务成功率与偏好对齐分数，能定位"未检索到偏好"与"检索到但用不好"两类不同失败来源。
- **消融设计严谨**：跨用户轨迹错配实验有效排除了任务重叠与数据集伪影的解释。
- **评测可信度验证**：LLM 评判者经人类标注验证（κ 高），人类独立研究也验证了轨迹中偏好信号的可恢复性（85.83% vs 基线 51.67%）。
- **分析细致**：按偏好类别、单/双偏好、域、失败类型多角度拆解，结论有据。

## 8. 不足与局限

- **环境覆盖有限**：仅三个受控 WebArena 环境，无法代表动态变化界面、更长期交互或偏好信号更丰富的真实网站。
- **轨迹为人工构造**：历史轨迹在显式 persona 条件下生成，而非自然产生的长期用户行为，可能无法反映真实偏好的模糊性、不一致性与稀疏性。
- **偏好模型过于静态**：假设偏好稳定可推断，未评估偏好随时间演化或强依赖上下文/情境约束的设定。
- **框架设计特定**：AdaptiveAgent 采用特定截图检索方案（CLIP 嵌入、检索 2 条轨迹前缀），结论对其他检索设计（如文本历史、更细粒度动作级检索）的泛化性未知。
- **潜在风格偏置**：轨迹收集模型 Qwen-3-VL-32B-Thinking 与受评 backbone 同族，虽其成功率最低、论文据此弱化偏置担忧，但彻底排除仍需多模型或真实用户采集轨迹。
- **算力信息不完整**：未披露 GPU 数量与总耗时，复现成本评估受限。
- **偏好类别不均衡难度**：部分类别（如 Wishlist vs. Cart）检索 recall 仅 5%，可能使部分任务实质上难以完成，影响基准的区分度分布。
- **应用限制**：论文结论限于固定模型、无梯度更新的测试时个性化，未讨论结合微调或持续学习的混合方案。
