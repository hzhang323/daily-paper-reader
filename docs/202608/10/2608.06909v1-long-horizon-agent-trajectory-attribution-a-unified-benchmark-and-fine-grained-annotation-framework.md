## 摘要
大语言模型（LLM）智能体日益通过涉及用户指令、工具使用、外部观察和记忆的长程轨迹进行操作。现有基准主要评估行为结果，但对细粒度归因分析的支持有限。我们引入轨迹归因，并为此任务开发了一个基准和标注框架。该基准在统一组件模式（schema）下组织异构轨迹，并提供主要归因组件的标注，以及适用的攻击链和执行链。利用来自AgentDojo以及Agent3Sigma的Stage和Canary设置中的轨迹实例化该基准，产生了超过1,300条标注轨迹，涵盖任务对齐行为、不安全行为和安全拒绝。该基准定义了两个评估任务：主要归因定位（primary attribution localization）和归因链恢复（attribution-chain recovery），并提供了基于增量轨迹贡献和组件级留一扰动的参考基线。它捕获了多样化的归因设置，包括局部和远程归因以及结构化归因链。参考基线结果在这些设置中表现出显著的性能差异，提供了对基准归因挑战的初步刻画。除了这一初始实例化之外，我们发布了一个可复用的标注技能（annotation skill），使新智能体模型生成的轨迹能够在同一框架下进行标准化、标注和评估。项目资源和未来版本可在https://github.com/chenjing-2024/agent-trajectory-attribution获取。

## Abstract
Large language model (LLM) agents increasingly operate through long-horizon trajectories involving user instructions, tool use, external observations, and memory. Existing benchmarks primarily evaluate behavioral outcomes but provide limited support for fine-grained attribution analysis. We introduce trajectory attribution and develop a benchmark and annotation framework for this task. The benchmark organizes heterogeneous trajectories under a unified component schema and provides annotations of the primary attribution component, together with attack and execution chains where applicable. Instantiating the benchmark with trajectories from AgentDojo and the Stage and Canary settings of Agent3Sigma yields more than 1,300 annotated trajectories covering task-aligned actions, unsafe actions, and safety refusals. The benchmark defines two evaluation tasks, primary attribution localization and attribution-chain recovery, and provides reference baselines based on incremental trajectory contribution and component-level leave-one-out perturbation. It captures diverse attribution settings, including local and long-range attribution as well as structured attribution chains. Reference baseline results exhibit substantial performance differences across these settings, providing an initial characterization of the benchmark's attribution challenges. Beyond this initial instantiation, we release a reusable annotation skill that enables trajectories generated by new agent models to be standardized, annotated, and evaluated under the same framework. Project resources and future releases are available at https://github.com/chenjing-2024/agent-trajectory-attribution.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：LLM智能体正从单轮助手演进为具备长视野规划、多步推理、工具调用和记忆能力的自主系统。智能体的行为不再由单次模型响应决定，而是由整个轨迹中用户指令、观察、中间决策、工具交互和记忆等因素累积影响。因此，解释智能体行为必须把轨迹作为一个整体来推理，而不能只看最终响应。
- **核心问题**：现有基准（如AgentDojo、Agent3Sigma）主要评估行为结果（任务是否完成、是否安全、是否被攻击），但缺乏对“行为为何发生”的细粒度归因支持。论文将这一缺失问题定义为**轨迹归因（trajectory attribution）**——即根据观察到的目标行为，识别并排序前序轨迹中对该行为有贡献的组件。
- **整体含义**：轨迹归因旨在将归因从“失败定位”扩展到“任务对齐行为、不安全行为、安全拒绝”三类行为的统一解释框架，为智能体失败诊断、安全审计和可解释性研究提供标准化评估基础。

## 2. 方法论：核心思想、关键技术细节与公式流程

- **核心思想**：构建一个可复用的组件级归因标注与评估框架，而非一个静态固定数据集。通过统一组件模式将异构轨迹标准化，对每条轨迹标注一个主要归因组件以及可选的多步归因链，并定义标准化的评估任务与指标。
- **统一组件模式（Unified Component Schema）**：
  - 每条轨迹表示为有序组件序列：τ = (c₁, c₂, ..., c_T)
  - 每个组件包含两个字段：**Role**（来源角色：system/user/assistant/tool）和 **Content**（文本化内容，如指令、推理、工具调用、观察等）
  - 工具调用与其观察合并为一个复合组件，视为一次完整的环境交互
  - 目标行为组件 c_t 之前的全部组件构成候选集 C_t = {c₁, ..., c_{t−1}}
- **参考归因结构（Reference Attribution Structure）**：
  - **主要归因组件** P = {c*}：每条轨迹恰好一个，表示目标行为的根因，可能来自用户指令、系统指令、持久记忆、工具交互、助手响应等
  - **有序归因链** H = (c_{i₁}, c_{i₂}, ..., c_{i_m})：表示必要的传播信息、上下文或中间动作链，按原始轨迹中的发生顺序排列，不包含主归因组件和目标组件
  - 完整标注为 A = ⟨P*, H*⟩；无附加链时 H* = ∅
- **三类目标行为**：
  - **任务对齐动作**（task-aligned action）：推进或完成预期用户任务
  - **不安全动作**（unsafe action）：有害或被攻击诱导的行为
  - **安全拒绝**（safety refusal）：拒绝不安全或禁止请求的响应
- **两种因果链（仅针对不安全动作子集）**：
  - **攻击链（attack chain）**：追踪对抗性影响如何通过交互传播
  - **执行链（execution chain）**：捕获不安全行为最终得以实施的下游组件序列
- **两个评估任务**：
  - **主归因定位（Primary Attribution Localization）**：判断方法是否能将标注的主要归因组件排到首位或高位，使用 Hit@1 和 MRR
  - **归因链恢复（Attribution-chain Recovery）**：评估方法能否恢复链中的额外归因组件，使用 Recall@K 和 MAP
- **两种参考基线方法**：
  - **增量归因（Incremental Attribution）**：s_inc_i = log p(y | c≤i) − log p(y | c≤i−1)，衡量引入组件 c_i 后目标行为概率的增量变化
  - **留一归因（Leave-One-Out, LOO）**：s_loo_i = (1/|y|)Σ log p(y_t | y_{<t}, τ) − (1/|y|)Σ log p(y_t | y_{<t}, τ(−i))，衡量移除组件 c_i 后目标行为平均token级对数似然的降幅
- **标注验证流程**：两阶段验证——**结构验证**（确定性检查：主归因是否在目标之前、链是否按时间顺序、组件是否有效）和**语义验证**（LLM评审器按预定义语义标准评估标注准确性），失败则通过额外LLM标注轮次修复后重新验证。
- **可复用标注技能**：释放标注技能，使新智能体模型生成的轨迹可以在同一框架下标准化、标注和评估，实现模型自适应的基准扩展。

## 6. 主要结论与发现

- **归因难度存在显著差异**：任务对齐动作最易归因，不安全动作和安全拒绝难度更高；不同基准来源在同类目标中也有明显差异，说明轨迹结构显著影响归因难度（增量归因下任务对齐Hit@1=0.621，不安全动作Hit@1=0.341，安全拒绝Hit@1=0.154）。
- **长距离归因系统性更难**：d=1 的局部案例一致优于 d≥2 的远程案例，表明中间推理步骤、工具调用和观察会产生竞争性解释，增加区分主因的难度。LOO基线在局部任务对齐案例中达到完美成绩（Hit@1=1.000），但远程案例显著下降。
- **链级归因比主因定位更难**：与单组件主归因相比，恢复完整攻击链/执行链的Recall@3和MAP更差，反映出多组件分布式因果关系中任何一个组件缺失都影响整体表现。
- **长程因果依赖是核心挑战**：轨迹长度最长可达97个组件，归因距离p90可达23以上，归因方法不能仅依赖局部上下文。
- **标注框架具有可扩展性**：统一模式、行为感知标注协议和验证流程可迁移到新智能体模型和框架，实现跨基准的一致归因评估。

## 7. 优点

- **填补空白**：首次将轨迹归因确立为独立的评测问题，超越了单纯的失败定位，覆盖了三类互补行为（任务对齐、不安全、安全拒绝），形成了统一评估框架。
- **统一组件模式设计巧妙**：通过 Role+Content 两层表示抽象了框架之间的格式差异，使标注协议和评估方法可以跨AgentDojo与Agent3Sigma等异构基准一致应用。
- **区分主因与链组件**：不是将归因简单视为无序多因集合，而是区分根因（primary cause）和传播/执行链组件（attack/execution chain），降低了标注歧义，也使根因定位目标更清晰。
- **链级标注扩展归因深度**：同时支持攻击链（上游对抗传播）和执行链（下游实现路径），更真实地刻画了从诱因到不安全行为之间的完整因果路径。
- **两阶段标注验证**：由确定性结构检查与LLM语义评审结合，提供可扩展的质量保障机制。
- **可复用性/模型自适应**：发布可复用标注技能，而非固定数据集，任何新智能体轨迹都能在同一框架下标准化和标注，解决Agent生态快速演进带来的基准时效问题。
- **数据规模可观：** 1,351条标注轨迹，覆盖十余个任务环境，分布较均衡。

## 8. 不足与局限

- **覆盖范围有限**：目前仅基于三个基准家族（AgentDojo、Agent3Sigma Stage/Canary），未覆盖多智能体协作、具身智能等新兴场景，可能不足以代表全部智能体类型。
- **标注可靠性风险**：依赖LLM辅助标注，尽管经过两阶段验证，但部分轨迹仍可能存在多种合理归因解释；论文未报告人工评审的一致性指标（如Cohen's Kappa或人工抽查比例），存在标注偏差风险。
- **粒度限制**：当前为组件级归因，未扩展到句子级或token级，对同一组件内部哪个具体部分起主导作用无法区分。
- **基线过于简单**：仅两个基于似然的参考基线（增量+留一），没有更先进的归因方法（如因果干预、graph-based方法、反事实方法）作为更强baseline，基准对先进方法的区分度尚待验证。
- **无端到端可复现性实验**：没有展示标注技能在新模型上的实际使用案例和评估结果，框架的“模型自适应”主张的证据尚不充分。
- **算力资源未披露**：缺乏资源消耗报告，影响实验可复现性和对其他研究者的参考价值。
