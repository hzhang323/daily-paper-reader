## 摘要
LLM智能体越来越多地应用于从真实世界系统收集的时间序列观测中的异常检测和根因分析；然而，它们在受控条件下在这些任务上的性能尚未得到系统评估。我们引入了TraceBench，一个基于模拟的框架，用于生成受控的根因归因任务。在每个生成的任务中，智能体接收通过模拟物理动态系统产生的时间序列观测，必须确定系统参数在模拟过程中是否被更改，如果是，则确定是哪一个参数。利用TraceBench，我们从三个可解释的机械系统生成任务，并在受控实验条件下系统评估四个LLM智能体，从而对这些智能体如何分析动态系统的时间序列观测提供新的见解。我们的结果表明，智能体在很大程度上受益于领域上下文，并且主要通过数值控制台输出而非可视化来探索数据。我们还发现，当要求智能体生成一个将每个时间序列样本映射到预测根因标签的Python脚本时，它们的表现通常比直接提交预测时更差。我们在我们的网站tracebench.github.io上发布了我们的数据集、智能体轨迹、实验结果和排行榜。

## Abstract
LLM agents are increasingly applied to anomaly detection and root-cause analysis in time-series observations collected from real-world systems; however, their performance on these tasks has not been systematically evaluated under controlled conditions. We introduce TraceBench, a simulation-based framework for generating controlled root-cause attribution tasks. In each generated task, an agent receives time-series observations produced by simulating a physical dynamical system and must determine whether a system parameter was altered during the simulation and, if so, which one. Using TraceBench, we generate tasks from three interpretable mechanical systems and systematically evaluate four LLM agents across controlled experimental conditions, yielding new insights into how these agents analyze time-series observations from dynamical systems. Our results show that agents benefit substantially from domain context and explore data primarily through numerical console output rather than visualizations. We also find that agents generally perform worse when required to produce a Python script that maps each time-series sample to a predicted root-cause label than when they submit predictions directly. We release our datasets, agent trajectories, experimental results, and a leaderboard on our website, tracebench.github.io.

## 二、论文提出的方法论

- **TraceBench 总体框架**：基于物理仿真器生成时间序列观测，在每个任务中，智能体收到一批由同一动态系统模拟生成的多变量时间序列样本，需要判断每个样本中是否发生了系统参数干预，以及是哪一个参数被改变（若发生了干预）。
- **任务定义**：每个 TraceBench 任务是一个**批处理闭集分类问题**——每个多变量时间序列样本（维度为 $T \times C$，$T$ 为时间步数，$C$ 为观测通道数）被归入"无干预"或某一参数干预类别。
- **四个可控轴**：
  1. **领域上下文**（domain context）：是否提供系统描述、通道含义和候选类别语义；
  2. **观测噪声**（observation noise）：由标量 $\kappa$ 控制观测噪声强度，实验中取 $\kappa_{low} = \kappa_{ref}$ 和 $\kappa_{high} = 4\kappa_{ref}$；
  3. **标注样本**（labeled examples）：是否提供每类若干带有真实标签的支持样本；
  4. **提交模式**（submission mode）：直接答案模式（$\mathcal{S}_{direct}$）要求智能体直接返回每样本预测；程序化模式（$\mathcal{S}_{prog}$）要求编写可复用的 Python 脚本 `predict(df)` 并将输入 DataFrame 映射为标签列表。
- **干预生成方式**：干预建模为**单次瞬时阶跃变化**。参数向量 $\boldsymbol{\theta}^{(i,+)}$ 表示仅将第 $i$ 个分量替换为干预后值 $\theta'_i$，时间相关的参数调度 $\boldsymbol{\theta}^{(i)}(t)$ 在 $t < t_{int}$ 时为基线参数、$t \geq t_{int}$ 时为干预后参数。
- **可解性过滤**：为排除根因本身模糊的训练样本，采用启发式过滤：
  - **无干预探针**（no-intervention probe）：相同初态与基线参数、无干预的轨迹；
  - **静态变化探针**（static-change probe）：从始至终使用干预后参数的轨迹。
  - 当干预轨迹与任一探针的**效应噪声比**（各通道均方根差除以期望噪声标准差）未超过全局阈值 $\rho = 2$ 时，拒绝该样本。此外还配合了各模拟器特定的手工拒绝规则，以处理参数间观测混淆（如 BallDrop 中静态接触后质量与重力的共线）。

## 三、实验设计

- **三个物理仿真系统**：
  1. **BallDrop**：受重力和二次空气阻力支配的垂直弹跳球，观测通道为位置、速度、地面接触冲量；候选标签为恢复系数、质量、阻力系数、重力加速度、无干预（5 类）。
  2. **BounceBall**：倾斜轨道上两刚性壁之间的阻尼质量块运动，观测通道为位置、速度、右壁接触力；候选标签为倾角、质量、左右恢复系数、粘性阻尼、无干预（6 类）。
  3. **MassSlide**：倾斜平面上受周期外力和库仑摩擦作用的质量块，观测通道为速度、摩擦力、法向力；候选标签为启动摩擦力、库仑摩擦力、重力常数、平面倾角、无干预（5 类）。(注：此处陈述依据附录A的类别设置)

- **主实验设计**：4 种条件（低/高噪声 × 直接/程序化提交）× 3 个模拟器 × 5 个随机种子 = **每智能体 60 个评估片段**（episode），每片段含 10 个测试样本，即每条件 150 个测试样本。所有条件均提供详细领域描述和每类 3 个标注支持样本。
- **对比的智能体**：gpt-5.5（配 Codex）、gemini-3.1-pro（配 Gemini CLI）、claude-opus-4.6（配 Claude Code）、minimax-m2.7（配 OpenCode），推理强度均设为 high。
- **消融实验**（仅在 $\kappa_{high}$ 下，仅对 gpt-5.5 和 gemini-3.1-pro）：① 移除所有领域上下文（含列名、类名）；② 移除标注样本（保留领域上下文）。
- **基线方法**：经典非智能体基线包括 Euclidean 1-NN、DTW 1-NN、MiniRocket + Ridg e 分类器，以及它们的"特权"变体（即用干净的无干预配对轨迹对观测做差）。
- **运行环境**：独立容器化环境，禁用网络，提供预装 Python 库，基础设施故障自动重启。
- **指标**：预测性能用 top-1 准确率；此外从智能体日志中提取 token 用量、成本、耗时、工具调用数、Python 调用数、生成/检视图表数、控制台输出数值量及其 token 占比等行为指标。

## 六、论文的主要结论与发现

1. **gpt-5.5 全面领先**：在全部 6 个准确率指标列中排名第一（低噪声直接模式 0.933；低噪声程序化 episode 0.853；低噪声程序化 held-out 0.671；高噪声直接 0.833；高噪声程序化 episode 0.733；高噪声程序化 held-out 0.547）。minimax-m2.7 显著落后（聚合平均低约 46 个百分点），该差距模式与 Terminal-Bench 2.0 的表现差异一致，而与 SWE-Bench Pro 相对接近的结果形成对比，说明 TraceBench 更依赖**持续性、多轮、工具辅助分析**能力而非单一代码生成能力。
2. **噪声对性能的系统性影响**：三个闭源模型的 episode 准确率均随噪声增大而下降（平均降幅 11.0–19.3 个百分点）。
3. **程序化提交模式普遍更难**：所有闭源模型在 $\mathcal{S}_{prog}$ 下 episode 准确率低于 $\mathcal{S}_{direct}$；且 held-out 准确率进一步低于 episode 准确率，说明智能体生成的脚本**未能完全捕捉干预的稳定性物理特征**，泛化能力有限。
4. **探索行为以数值控制台输出为主，可视化极少被真正查看**：三个闭源模型平均每 episode 在控制台输出超过 4600 个数值；gpt-5.5 的输入上下文中 77–80% 的 token 来自控制台输出；gemini-3.1-pro 虽生成 1.7–5.1 个图表但从不检视。这与常规探索性数据分析中"先可视化"的做法明显不同。
5. **领域上下文是关键**：移除领域描述后，准确率下降 20.0–32.0 个百分点。移除领域上下文反而在多数情况下增加了 token 消耗，说明智能体以更多的探索来弥补缺失的信息。
6. **标注样本未必有益**：移除每类 3 个标注样本后，准确率反而小幅上升（gpt-5.5 +5.3 至 +11.3 个百分点；gemini-3.1-pro +8.7 至 +10.7 个百分点），同时 token 成本大幅降低。这一反直觉发现在领域描述已足够好时提示我们**重新审视少样本示例的价值**。

## 七、优点

- **受控性突出**：四个任务轴可独立调节，条件间共享相同测试样本，使差异可归因于单一变量。
- **物理仿真保证 ground-truth 已知**：干预由构造定义，标签无歧义，可清洗地评估推理正确性。
- **可解性过滤提高任务质量**：剔除了因干预时机、参数可替代性或观测混淆而导致根因不可识别的样本，使评估集中于"可解决的"归因任务。
- **双模式评估**：直接答案与可复用脚本的对比，既评估瞬时推理能力，又评估将策略编译为可泛化程序的能力；held-out 测试进一步检测过拟合。
- **行为级分析**：除了准确率，还量化了 token、成本、工具调用、控制台输出占比等行为指标，揭示了智能体实际工作方式，提升了结论的信息量。
- **可复现性**：完整公开代码、数据集、全部智能体轨迹、实验配置和排行榜。

## 八、不足与局限

- **封闭标签集与简化假设**：任务形式是"五选一/六选一"的闭集分类，不反映真实根因分析中开放式假设生成与结论沟通的复杂性。模拟器仅覆盖低维机械系统、规则采样、完全观测、最多单参数单次瞬时干预，未包含部分观测、时变参数漂移、多参数同变等现实复杂性。
- **噪声模型的仿真性**：噪声被建模为高斯噪声+平滑漂移+事件局部噪声的组合，而非真实传感器噪声；结论对真实工业遥测的可迁移性有限。
- **统计功效受限**：每条件仅 5 个重复，

续写“统计功效受限”条目及后续内容：

- **统计功效受限**：每条件仅 5 个重复，统计功效不足，难以检测较小效应量；且每个 episode 仅含 10 个测试样本，批内方差较大，部分观察到的差异可能受随机波动影响。作者在限制中也承认了这一不足。
- **脚手架与模型混杂**：不同智能体使用不同的命令行界面工具（Codex、Gemini CLI、Claude Code、OpenCode），模型间的性能差异可能部分来自脚手架工具能力的差异，而非底层 LLM 推理能力本身的差异。
- **缺乏人类基线**：未报告人类专家在相同任务上的表现，因此无法判断智能体的绝对水平；仅对比经典机器学习基线，不足以说明智能体是否达到实用价值的门槛。
- **消融实验覆盖不足**：领域上下文和标注样本的消融实验仅对两个模型进行，且仅在高噪声条件下，无法全面评估这些因素对其他模型的影响，也无法检验低噪声下这些因素的交互效应。

## 九、总体评价与总结

- TraceBench 是一个设计精良、高度受控的 LLM 智能体时间序列根因归因基准。其在任务可解性过滤、双提交模式、行为指标采集、可复现性等方面做出了值得借鉴的贡献。
- 核心发现表明：当前最强的闭源 LLM 智能体在低噪声、直接回答模式下可达到 90% 以上的准确率，但在高噪声与程序化泛化情境中性能显著下降；领域上下文是性能的关键支撑，而少样本标注示例的价值反而需要重新评估。
- 该基准为未来研究提供了清晰的着力点：一是提升智能体对物理机制理解与多步工具使用的整合能力，二是将评估范式拓展至更复杂的开放式根因分析场景（如多参数同变、部分观测、时变漂移等）。
