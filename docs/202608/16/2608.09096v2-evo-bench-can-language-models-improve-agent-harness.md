## 摘要
大语言模型（LLMs）推动了自主智能体的快速发展，但标准评估仍局限于静态任务求解。一个新兴的前沿是框架进化——智能体自主优化其自身工作框架的能力。然而，系统地基准测试这一能力仍具挑战性，因为现有评估无法将框架改进与基础模型强度隔离、无法防止任务特定过拟合，或无法捕捉长时程迭代研究。为应对这些挑战，我们引入了Evo-Bench，这是首个旨在评估模型在搜索、办公和通用智能体领域内在框架进化能力的基准。为严格隔离这一能力，Evo-Bench采用了一种新颖的框架引导构建框架：它利用辅助任务进化来识别对框架改进真正敏感的任务，随后通过敏感性感知的分层划分确保跨套件的稳健泛化。对九个前沿和开放权重模型的广泛评估显示，顶级模型实现了高达16.6分的绝对提升，接近最先进的人工设计基线。关键在于，虽然自主进化在通用任务中优于人工框架并在搜索任务中表现出色，但在需要高度特定处理流程的办公任务中却表现不佳。此外，我们的分析揭示了早期饱和等关键时间异常，同时表明合成的框架可作为高度可迁移的推理结构，持续提升多种策略模型。

## Abstract
Large Language Models (LLMs) have driven rapid progress in autonomous agents, yet standard evaluations remain confined to static task solving. An emerging frontier is harness evolution---the agent's capacity to autonomously optimize its own operating harness. However, systematically benchmarking this capability remains challenging, as existing evaluations fail to isolate harness improvements from base model strength, prevent task-specific overfitting, or capture long-horizon iterative research. To address these challenges, we introduce Evo-Bench, the first benchmark designed to evaluate models' intrinsic harness-evolving capabilities across Search, Office, and General agent domains. To rigorously isolate this capability, Evo-Bench employs a novel harness-guided construction framework: it leverages auxiliary-task evolution to identify tasks genuinely sensitive to framework improvements, followed by sensitivity-aware stratified splitting to ensure robust cross-suite generalization. Extensive evaluations across nine frontier and open-weight models reveal that top models achieve massive absolute gains reaching 16.6 points, closely approaching state-of-the-art human-engineered baselines. Crucially, while autonomous evolution outpeforms artificial harness in General tasks and excels in Search tasks, it struggles in Office tasks that demand highly specific processing workflows. Furthermore, our analysis exposes critical temporal anomalies like early saturation, while demonstrating that the synthesized harnesses act as highly transferable reasoning structures, consistently boosting diverse policy models.

- **关键挑战**（现有评估的三大缺陷）：
  1. **Harness 敏感性缺失**：任务性能必须对 harness 改进敏感，而非被基础模型能力主导；

  3. **长时程演化缺失**：模型须支持多轮迭代式改进——诊断失败、形成假设、持续更新代码。

### 2. 论文提出的方法论

#### 2.1 核心思想

构建一个 **Evo-Bench** 基准：在固定策略模型（policy model）前提下，让演化者模型（evolver）在受控的长时程研究环境中，对共享的 CodeAct 种子 harness 进行多轮迭代优化，并在不可见的测试集上评估最终冻结版本的表现。通过"框架引导的基准构建框架"来严格隔离 harness 演化能力。

#### 2.2 任务形式化（Task Formulation）

- 固定策略模型 π 和演化者 E 共同工作；
- 演化迭代 t 时，策略智能体为 A^task_t = (π, H_t)，其中 H_t 为可编辑的 policy harness；
- 演化者 A^evo = (E, H_evo) 通过固定的 evolve harness 运作；
- 演化者观察累积验证证据 Eval_t，编辑当前 harness H_t，并在可见验证集上请求正式评估；
- 资源预算 b = (b_iter, b_time, b_steps) 约束迭代次数、墙钟时间与演化者步数；
- 终止后，最终修订版 H_T 被冻结，在不相交的 hold-out 评估集上评测。

#### 2.3 两阶段框架引导构建方法（Two-Stage Harness-Guided Construction）

**阶段一：辅助 harness 生成**

- 收集 320 个辅助任务（128 搜索 + 128 办公 + 64 通用），与五个来源基准数据集在语料和实例层面不相交；
- 使用 DeepSeek-V4-Flash 进行多次独立 rollout，筛选低分、长轨迹的任务（表示有更大的 harness 改进空间）；
- 用 4 个前沿模型（GLM-5.2、Claude-Opus-4.8、Claude-Sonnet-5、GPT-5.6-Sol）独立进行辅助任务上的 harness 演化实验；
- 收集 73 个经正式评估的 harness 变体，通过确定性多样性感知选择流程选出 12 个代表性 harness（H_aux）。

**阶段二：Harness 引导的任务选择**

- 在 12 个辅助 harness 下评估 2,329 个候选任务；
- 计算两个关键指标：
  - **Harness 敏感性（Sens(x)）**：任务分数与 harness 总体质量的 Pearson 相关系数（leave-one-task-out 的总体质量估计）：
    Sens(x) = corr({m_h(x)}_{h∈H_aux}, {Q_h^(-x)}_{h∈H_aux})
  - **任务难度（1 − Perf(x)）**：Perf(x) 为任务在 H_aux 上的平均分数；
- 过滤 Sens(x) ≤ 0 的任务，按难度分层并在每层内优先选择敏感性最高的任务；
- 在每层内随机划分验证集与评估集，确保难度分布一致。

#### 2.4 评估指标

- **Overall Score**：最终冻结 harness 在不可见评估集上的聚合分数；
- **Anytime Validation Score**：演化过程中 best-so-far 验证性能在预算上的平均，捕捉演化进度。

#### 2.5 Harness 设计

- **Evolve harness**：固定 agent 循环，含系统提示、执行工具、上下文管理器、轨迹分析与实验追踪技能；
- **Policy harness（种子 H₀）**：最小 CodeAct 循环，仅含 shell 执行与最终答案完成工具。

### 7. 优点

- **首创性**：Evo-Bench 是首个专门评估 LLM 内在 harness 演化能力的基准，填补了智能体自我改进评测的关键空白；

- **严谨的基准构建流程**：两阶段框架引导构建方法（辅助任务演化 + harness 敏感性与难度双指标筛选 + 分层分割）具有方法论上的创新性和科学性；
- **多维度评估体系**：同时提供最终泛化性能（Overall）和演化过程质量（AnytimeVal）两个互补视角；
- **广泛模型覆盖**：9 个模型涵盖前沿闭源与开放权重模型，结果具有代表性；

- **可迁移性验证**：通过更换策略模型的消融实验证明了演化 harness 的通用性而非过拟合。


### 8. 不足与局限

- **单一运行缺乏方差估计**：每个模型只运行一次，无法评估演化过程的随机性对结果的稳定性和显著性的影响；
- **人工基线可能不具最优性**：Artificial harness 是特定组件的拼接，并非在相同任务上系统调优的最优解；部分领域（如搜索）人工组合也未必代表人类上限；
- **办公任务的代表性问题**：仅选取 GDPval 与 APEX-Agents 两个基准，是否足以代表办公任务的多样性存疑；
- **策略模型固定单一**：虽做了策略模型交换的消融，但仅覆盖了 2 个演化者 × 3 个策略模型的组合，主实验仍使用单一策略模型，无法排除策略模型与 harness 演化之间的交互效应；
