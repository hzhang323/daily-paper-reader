## 摘要
大语言模型（LLMs）正越来越多地被要求对图等结构化数据进行推理，但它们能否在语言中可靠地执行多步图算法仍不明确。现有评估往往使用小图上的简单任务、对代码生成而非对图本身的推理进行评分，或固定单一输入格式。我们提出 Graph Theory Bench（GT Bench），这是一个涵盖 44 种任务-结构设置下 24 个经典图问题的基准，包含超过 100,000 个示例，覆盖四种表示：自然语言、结构化语言、邻接表和邻接矩阵。在 GT Bench 上评估八个 LLM 表明，准确率与输入表示密切相关；最佳表示会随图密度、规模、拓扑以及模型而变化；并且这种敏感性在最强推理模型中依然存在，只是有所减弱。基于这些观察，我们提出 Graph Theory Agent（GTA），它将经过偏好训练的表示选择器与围绕冻结执行器 LLM 的规划-分解脚手架相结合。GTA 将 Phi-4 在基准的简单划分上从 53.5% 提升至 69.1%，在困难划分上从 33.0% 提升至 41.5%，优于八个提示与智能体基线，并且无需重新训练即可迁移到 GraCoRe 和 NLGraph。基准生成与评估代码：https://github.com/xzx34/GTA。项目主页：https://xzx34.github.io/gta/。

## Abstract
Large Language Models (LLMs) are increasingly asked to reason over structured data such as graphs, yet how reliably they can carry out multi-step graph algorithms in language remains unclear. Existing evaluations tend to use simple tasks on small graphs, to score code generation rather than reasoning over the graph itself, or to fix a single input format. We introduce Graph Theory Bench (GT Bench), a benchmark covering 24 classical graph problems in 44 task-structure settings, with over 100,000 examples across four representations: natural language, structured language, adjacency list, and adjacency matrix. Evaluating eight LLMs on GT Bench shows that accuracy is strongly tied to the input representation, that the best representation shifts with graph density, size, and topology as well as with the model, and that this sensitivity persists, attenuated, in the strongest reasoning models. Building on these observations, we propose the Graph Theory Agent (GTA), which pairs a preference-trained representation selector with plan-and-decompose scaffolding around a frozen executor LLM. GTA lifts Phi-4 from 53.5% to 69.1% on the benchmark's easy split and from 33.0% to 41.5% on its hard split, outperforming eight prompting and agent baselines, and transfers without retraining to GraCoRe and NLGraph. Code for benchmark generation and evaluation: https://github.com/xzx34/GTA. The project homepage is available at https://xzx34.github.io/gta/.

## 1. 核心问题与整体含义

- **研究动机**：LLM 正被广泛用于处理图结构数据（社交网络、会话搜索交互图、分子结构等），但"模型能否在纯语言条件下可靠执行多步图算法"这一问题尚不清楚。
- **现有评测的三大缺陷**：
  - 任务过于简单、图规模过小；
  - 评分对象是生成的代码而非对图本身的推理；
  - 固定单一输入格式，无法考察表示方式的影响。
- **整体含义**：论文同时贡献了一个受控基准（GT Bench）与一个自适应智能体（GTA），将"输入表示"从工程细节提升为一等优化目标，试图在**不修改执行器模型**的前提下提升语言级图算法推理能力。

## 2. 方法论

### 2.1 核心思想
- 先诊断（GT Bench 揭示表示敏感性与多步推理瓶颈），再对症下药：**自适应选择表示 + 系统化分解求解**。
- 采用**冻结执行器（frozen executor）范式**：基座 LLM 不训练、不微调，只优化轻量辅助模块（Selector、Decomposer），使增益可归因于"呈现方式与推理结构"而非模型容量。

### 2.2 流水线（文字化流程）
```
P = (G, T)
  → Selector：为图 G 与任务 T 选最优表示 R*，得 P' = (G_R*, T)
  → Generator：产出高层算法策略 A（概念性蓝图，不写代码、不求解）
  → Decomposer：将 A 细化为子步骤序列 {s1, ..., sk}（k ≤ 3）
  → Executor：按子步骤逐步推理，输出最终答案
```

### 2.3 关键技术细节
- **输入表示选择器（两种实现）**
  - *启发式选择器*：基于 GT Bench 统计（附录表 19）的规则查表，零参数、开销低；
  - *学习式选择器*：以 (G, T) 为输入、以四种表示下的端到端成败为偏好对，用 DPO 微调，可适配特定执行器与模糊结构区间。
- **算法生成器**：现成 LLM 提示生成高层计划，**不做任务微调**；实验测得计划自一致性 94.7±1.2%（Jaccard），与参考算法对齐度 91.5±1.8%（GPT-4o 评判）。
- **算法分解器**：两阶段训练——先在 GPT-4o 蒸馏的专家分解上做 SFT，再用"执行正确/错误"构成的胜负偏好对做 DPO，直接以任务成功为优化目标。
- **训练顺序**：先训 Decomposer（此时用启发式选择器），固定后再训 Learned Selector，形成端到端偏好对齐。
- **约束发现**：k > 3 时开销上升且准确率下降，故限制子步骤不超过 3 步。

## 3. 实验设计

### 3.1 基准与数据集
- **GT Bench（自建）**：24 类经典图问题、44 种任务-结构设置、105,600 条编码示例；四种等价表示（自然语言 NL、结构化语言 SL、邻接矩阵 AM、邻接表 AL）；分 Easy（GT-E）与 Hard（GT-H）子集。
- **图属性**：稀疏（E=O(V)）、稠密（E=O(V²)）、树（E=V−1）；节点规模 6–60，按"提示词适配预算"逐族校准，稠密族范围更紧。
- **任务覆盖**：多项式问题（最短路、MCMF）、NP-hard 优化（最大团、最大独立集）、NP-complete 判定（哈密顿路径/回路）等；真值由规范算法自动生成，无需人工标注。
- **迁移测试**：GraCoRe（Graph Understanding 子集）与 NLGraph（完整集），各随机转成四种表示之一，每个数据集 1,000 条实例。

### 3.2 对比方法
- **提示类**：Vanilla、CoT、LLM-Debate、Self-Refine；
- **图专用**：GraphTeam（仅推理配置）、GraphWiz-DPO（附录补充）；
- **自动智能体框架**：ADAS、AFlow、MaAS；
- 所有基线统一使用 **Phi-4** 作为执行器以保证公平。

### 3.3 评测规模
- 8 个模型（GPT-4o-mini、GPT-4o、o3-mini、Llama-3.1-8B、Llama-3.3-70B、Phi-4、QwQ-32B、DeepSeek-R1）各 10,000 条实例 × 4 种表示，温度 0.01。

## 6. 主要结论与发现

- **表示敏感性是一阶因素**：同一任务上格式选择可带来近 30 个百分点的差异（稀疏连通性 60.5%–89.1%）；模型层面最大-最小差距从 Llama-3.1-8B 的 2.0 分到 QwQ-32B 的 9.2 分，在 o3-mini（2.8）与 DeepSeek-R1（1.9）上减弱但未消失。
- **规律性**：NL 适合稀疏图；SL 适合树结构；AM 适合稠密图；AL 适合路径搜索与邻居迭代类任务。
- **"全给"反而更差**：四表示拼接使 GPT-4o 从 47.6% 降至 40.3%，原因是提示膨胀 3–4 倍且引入结构噪声。
- **难度分层改变模型排名**：GPT-4o 在 Easy 上超过 Llama-3.3-70B，但在 Hard 上落后；QwQ-32B 从 85.62% 跌至 38.46%。
- **图推理是独立能力轴**：QwQ-32B 在指令遵循/长查询 Elo 上偏低，却在 GT-H 上排第 3，说明图算法推理更接近 Coding/MATH 式的精确多步执行。
- **GTA 效果**：Phi-4 上 GT-E 53.5%→69.1%、GT-H 33.0%→41.5%，优于全部 8 个基线；GraCoRe 80.5%、NLGraph 89.4%，均为最高。
- **组件贡献**：去掉 Selector 损失最大（GT-E 69.1→58.2）；Learned Selector 比启发式高 4.6 分；去掉规划分解损失 7.0 分；Decomposer 单独贡献（−4.8）大于 Generator（−2.3），二者近似可加。
- **迁移性**：Phi-4 上训练的组件可直接迁移到 GPT-4o-mini/GPT-4o/DeepSeek-R1，后者在未饱和的 GT-H 上增益最大（+8.1 分）。
- **成本与鲁棒性**：GTA 成本 1.11 美元/600 实例，低于除 MaAS 与 Vanilla 外的所有方法；输入溢出 0%、输出截断 1.2%、答案抽取失败 0.8%，不足以解释性能差距。

## 7. 优点

- **基准设计受控且规模大**：同一实例提供四种等价表示，可直接分离"表示效应"与"任务难度"，这是多数现有图基准不具备的。
- **真值可验证**：全部由经典算法自动生成，规避人工标注噪声与 LLM 评判偏差，且生成管线参数化、可复现、可扩规模。
- **方法定位清晰**：冻结执行器 + 轻量辅助模块，把"更好的推理策略"与"更强的模型能力"解耦，结论归因明确。
- **训练信号直接对齐任务成功**：用执行结果构造 DPO 偏好对，比纯模仿式 SFT 更贴合端到端目标。
- **分析维度完整**：除准确率外，还给出成本、规模退化曲线、失败/截断率、跨基准与跨执行器迁移，工程可用性强。
- **诚实的诊断性报告**：主动指出单次推理的统计局限、LLM 评判的偏差风险、图规模受上下文预算限制等。

## 8. 不足与局限

- **任务域局限**：全部为合成、领域无关的经典图问题，未覆盖带领域属性的图（社交、分子等），也未涉及需要外部知识的任务。
- **图规模受限**：节点仅 6–60，受上下文窗口与 O(V²) 稠密边数约束；大规模真实图的结论不可直接外推（虽做了扩规模研究，结论仍限于所测范围）。
- **表示集合有限**：仅四种文本化表示，未涉及视觉/多模态、彩色编码、连续软提示或图神经网络接口，且不考察代码执行与工具调用路径。
- **统计强度不均**：表示敏感性扫描为单次运行，未给出逐配置方差；只有第 6 节的定向分析做了 3 次重复。
- **启发式选择器的可迁移性弱**：本质是 GT Bench 统计查表，超出覆盖范围需重新推导；Learned Selector 换新任务族时仍需少量偏好对微调。
- **分解粒度受限**：Decomposer 子步骤上限为 3，是为 Phi-4 调优的经验结果，对更强或更弱执行器未必最优。
- **诊断指标存在偏差风险**：Generator 的计划对齐度依赖 GPT-4o 评判，论文自己也引用了 LLM-as-judge 偏差相关文献。
